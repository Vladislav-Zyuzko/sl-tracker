# SL Tracker — сквозные UX-потоки

Версия 1.0. Владелец: `sl-designer`.
Спеки экранов — [`screens/`](./screens/), токены — [`system.md`](./system.md),
компоненты — [`components.md`](./components.md).

Этот документ описывает **переходы между экранами**: то, что не видно, если читать
спеки по одной. Каждый поток проверяется по одному критерию: **на каждом шаге понятно,
что делать дальше, и ни один шаг не ведёт в тупик.**

---

## Поток 1. Первый вход нового человека

Самый уязвимый путь продукта: человек ещё ничего не знает и легко решит,
что трекер сломан.

```
Открыл ссылку на трекер
        |
        v
 [Экран входа]  ── «Войти через Яндекс» ──> Яндекс ID
        |                                        |
        |<─────── отказал в доступе ─────────────+
        |         баннер «Вход отменён»          |
        |                                        v
        |                                 колбэк на бэкенд
        |                                        |
        |         +──────────────────────────────+──────────────────────────+
        |         v                              v                          v
        |   email в списке доступа      действует приглашение        ни того, ни другого
        |         |                              |                          |
        |         v                              v                          v
        |   [Мои проекты]              [Приём приглашения]        [Доступ к трекеру закрыт]
        |      (адрес `/`)                                        (`?ticket=`, без cookie)
        |         |                              |                          |
        |         |                    «Присоединиться»              «Выйти» / «Войти
        |         |                              |                    другим аккаунтом»
        |         |                              v                          |
        |         |                        [Проект]                        v
        |         |                                                  [Экран входа]
        v         v
   пустой список проектов ──> «Создать проект» ──> [Проект] ──> подсказка «создайте очередь»
```

### Три развилки, каждая со своим тупиком — и выходом из него

| Развилка | Тупик, если не продумать | Что делаем |
|---|---|---|
| Человека нет в списке доступа | «Ошибка 403» и пустой экран | экран «Доступ к трекеру закрыт» с понятной причиной и двумя выходами; адрес, под которым вошли, экран получает обменом тикета, а не из адресной строки ([access-denied.md](./screens/access-denied.md)) |
| Человек внутри, но не в одном проекте | пустой список без объяснения | пустое состояние: «Создайте свой проект или попросите ссылку-приглашение — в чужой проект попадают только по ней» ([projects.md](./screens/projects.md)) |
| Создал проект — а дальше пусто | проект без очередей, задачи создать негде | на экране проекта пустое состояние очередей объясняет, что ключ очереди станет началом ключей задач ([project.md](./screens/project.md)) |

### Возврат к цели

Человек, открывший `/issues/DEV-42` без сессии, после входа попадает **на эту задачу**,
а не на главный (US-01). То же для `/invite/<token>` (US-21). Адрес назначения
сохраняется до ухода на Яндекс и подхватывается после возврата.

Это правило действует на **всех** маршрутах приложения, а не только на задаче:
любая ссылка, отправленная в чате, должна доводить до цели за один вход.

## Поток 2. Приглашение коллеги

Здесь живёт главный риск утечки доступа ([D-04](../product/decisions.md#d-04)).

```
Администратор                                     Приглашённый
     |                                                 |
[Проект] → вкладка «Приглашения»                       |
     |                                                 |
«Создать приглашение»                                  |
     |                                                 |
роль (участник / читатель) + срок (1 / 7 / 30 дней)   |
     |                                                 |
«Создать» → ссылка показана в модалке                  |
     |                                                 |
«Скопировать ссылку» → тост-warning:                   |
 «По ней в проект войдёт любой, у кого она окажется»   |
     |                                                 |
     +──────── отправил в мессенджере ────────────────>|
                                                       v
                                            открыл /invite/<token>
                                                       |
                            +──────────────────────────+──────────────────────+
                            v                          v                      v
                     нет сессии                 токен действует        токен протух
                            |                          |                      |
                     [Экран входа]                     v                      v
                            |              [Приём приглашения]     есть в списке доступа?
                     Яндекс ID                         |                нет |    | да
                            |                  «Присоединиться»           v    v
                     вернулись СЮДА же                 |        [Доступ    [Приглашение
                            |                          v         закрыт]    не действует]
                            +──────────────────────────+
                                                       v
                                                  [Проект]
                                                       |
                            уведомление всем администраторам проекта (US-23)
```

### Почему протухшее приглашение ведёт в разные места

Если человека **нет** в списке доступа, протухшая ссылка не даёт ему даже узнать,
что проект существует: он видит «Доступ к трекеру закрыт» (US-21). Если он **есть**
в списке (уже работает в трекере), ему честно показывают «Приглашение больше
не действует» — скрывать нечего.

### Разведение двух ссылок в потоке

| | Адрес проекта | Ссылка-приглашение |
|---|---|---|
| Откуда берётся | шапка проекта, одно нажатие | вкладка «Приглашения», четыре шага |
| Кто может взять | любой участник, включая читателя | только администратор |
| Что делает у получателя | «Проект не найден», если он не участник | делает участником |
| Тост при копировании | нейтральный «Адрес скопирован» | `warning` с предупреждением |

Полная таблица семи различающих признаков — в [project.md](./screens/project.md).

## Поток 3. Создание задачи

Два входа, один результат.

```
Вход А: из очереди            Вход Б: из шапки приложения
[Список задач очереди]        [любой экран] → «Создать задачу»
       |                              |
«Создать задачу»              диалог выбора очереди
       |                              |
       |                      (очередь подставлена, если известна из контекста)
       +──────────────┬───────────────+
                      v
         +-----------------------------+
         | Название *                  |  ← единственное обязательное поле
         | Описание (Markdown)         |
         | Очередь: DEV                |
         +-----------------------------+
                      |
                 «Создать»
                      |
                      v
              [Задача DEV-43]
              статус «Открыт», приоритет 50,
              автор = создатель, исполнитель не назначен,
              в истории запись «Задача создана»
```

**Обязательное поле одно** (US-40). Всё остальное заполняется потом, на экране задачи.
Форма, требующая заполнить восемь полей, чтобы записать мысль, — способ добиться того,
что задачи будут заводить в мессенджере.

Значения по умолчанию (US-40): статус — первый статус очереди, приоритет — **50**
(«Обычный»), сложность — не оценена, автор — создатель, исполнитель — никто.

После создания пользователь **попадает на страницу задачи** и видит её ключ (US-40):
ключ — это то, что он сейчас отправит коллеге.

## Поток 4. Работа с задачей

Основной ежедневный цикл. Все действия — оптимистичные, все откатываются одинаково.

```
[Сайдбар: мои активные задачи]  или  [Список задач очереди]  или  [Уведомление]
                    |                         |                        |
                    +─────────────────────────+────────────────────────+
                                              v
                                        [Задача DEV-42]
                                              |
        +──────────────┬─────────────┬────────+────────┬──────────────┐
        v              v             v                 v              v
   сменить статус  назначить    написать          прикрепить      посмотреть
        |          исполнителя  комментарий          файл          историю
        v              v             v                 v              v
   оптимистично:  оптимистично  появляется       прогресс на      вкладка
   чип меняется   аватар        сразу, 60 %      плитке           «История»
   мгновенно      меняется      непрозрачности
        |              |             |                 |
        +──────────────+──────┬──────+─────────────────+
                              v
                    ошибка сохранения?
                              |
              +───────────────+───────────────+
              v                               v
            нет                              да
              |                               |
     значение осталось            откат к прежнему значению за 200 мс
     запись в истории             + подсветка dangerSurface на 400 мс
     уведомления подписчикам      + тост «Не удалось изменить статус DEV-42»
                                    с кнопкой «Повторить»
                                  + текст комментария НЕ теряется
```

### Что порождает уведомления, а что нет

Важно для понимания потока: не всякое изменение кого-то беспокоит.

| Действие | Уведомление |
|---|---|
| Назначил исполнителем (не себя) | исполнителю (US-100) |
| Указал автором (не себя) | новому автору (US-100) |
| Сменил статус | всем подписчикам, кроме себя (US-101) |
| Написал комментарий | всем подписчикам, кроме себя (US-102) |
| Упомянул через `@` | упомянутому, одно вместо двух (US-104) |
| Изменил приоритет, сложность, название, описание, вложения, ссылки | **никому** (US-101) — это видно в истории |

Подписка неявная ([D-17](../product/decisions.md#d-17)): создатель, автор, исполнитель,
все комментировавшие, все упомянутые. Поля «Наблюдатели» нет.

### Цикл закрытия задачи

```
Задача в работе ──> статус «Закрыт» (категория done)
                              |
                              v
              исчезает из сайдбара активных задач исполнителя (D-19)
                              |
                              v
        если это открытая сейчас задача — остаётся на экране с пометкой,
        а не выдёргивается из-под пользователя (app-shell.md)
```

Возврат в любой другой статус возвращает задачу в сайдбар (US-61).

## Поток 5. Что происходит, когда доступ отзывают

Три разных отзыва с тремя разными последствиями. Их регулярно путают.

```
1. Исключение из проекта (US-16)
   администратор → [Проект] → участники → «Исключить»
        |
        v
   человек теряет проект: проект пропал из списка, задачи «не найдено»,
   исполнитель в его задачах очищен, комментарии и авторство остались
        |
        v
   ВХОД В ТРЕКЕР СОХРАНЯЕТСЯ: он видит список проектов без этого проекта

2. Удаление из списка доступа (ADR-0006, п. 4)
   владелец инстанса → [Доступ к трекеру] → «Удалить доступ»
        |
        v
   вход закрыт + активные сессии погашены немедленно
   (сколько именно — в ответе `revokedSessions`, и это показывается владельцу
    в тосте: он должен знать, что кого-то выбросило прямо сейчас)
        |
        v
   человек, работавший в этот момент: следующее действие → модалка
   «Сессия истекла» → [Экран входа] → Яндекс ID → [Доступ к трекеру закрыт]
        |
        v
   УЧАСТИЕ В ПРОЕКТАХ СОХРАНЯЕТСЯ в данных: вернут доступ — вернётся и в проекты

3. Выход самого пользователя (US-03)
   меню профиля → «Выйти» → [Экран входа]
   сессия в Яндексе не трогается
```

Ключевая мысль, которую поток обязан доносить интерфейсом:
**«убрать из проекта» и «закрыть вход в трекер» — разные действия в разных местах,
с разными последствиями.** Поэтому они и разведены по экранам: первое — на экране
проекта, второе — на административном экране, куда обычный участник не попадает.

## Поток 6. Возвращение после отсутствия

Утренний сценарий, ради которого существует сайдбар и центр уведомлений.

```
Открыл трекер (сессия жива, US-02)
        |
        v
[Мои проекты] — но взгляд сразу на сайдбар и колокольчик
        |
        +──> сайдбар: «МОИ АКТИВНЫЕ ЗАДАЧИ 14» — что я делаю
        |
        +──> колокольчик: «12» — что случилось без меня
                    |
                    v
            [Центр уведомлений]
                    |
        уведомления новые сверху, непрочитанные отмечены
        точкой + фоном + весом шрифта
                    |
            клик по уведомлению
                    |
                    v
            [Задача] + прокрутка к нужному комментарию
            (уведомление помечено прочитанным, счётчик уменьшился)
```

Поиск в сайдбаре на этом шаге — фильтр по своим активным задачам, **не глобальный**
([D-20](../product/decisions.md#d-20)). Область поиска проговаривается трижды:
заголовком секции над полем, подсказкой под полем при вводе и текстом пустого
результата — иначе поток ломается о неоправданное ожидание
([app-shell.md](./screens/app-shell.md), раздел «Поиск: главный риск экрана»).

## Поток 7. Тупики и выходы из них — сводная таблица

Проверочный список: из любого состояния есть путь дальше.

| Состояние | Выход |
|---|---|
| Нет проектов | «Создать проект» + объяснение про ссылку-приглашение |
| Проект без очередей, я админ | «Создать очередь» + объяснение про ключ |
| Проект без очередей, я участник | «Попросите администратора создать очередь» |
| Очередь без задач | «Создать задачу» (у читателя — пояснение) |
| Фильтр ничего не нашёл | «Сбросить фильтры» |
| Поиск в сайдбаре ничего не нашёл | «Очистить поиск» + объяснение границ поиска |
| Нет активных задач | объяснение, что сюда попадает; кнопки нет — задачу назначают не отсюда |
| Нет уведомлений | объяснение, что здесь появится; кнопки нет |
| Задача не найдена / нет доступа | «К списку задач» |
| Проект не найден | «К списку проектов» |
| Приглашение не действует | «На главную» |
| Доступ к трекеру закрыт | «Выйти» / «Войти другим аккаунтом» |
| Нет прав вести список доступа | «Страница не найдена» — раздела для этого пользователя не существует |
| Сессия истекла | модалка → «Войти», черновики сохранены |
| Нет соединения | полоса офлайна + «Обновить», загруженные данные остаются |
| Ошибка загрузки любого экрана | «Повторить» |
| Ошибка сохранения поля | откат + тост + «Повторить», данные не потеряны |

Экрана, из которого нельзя выйти иначе как кнопкой «Назад» в браузере, в продукте нет.

## Проверочные сценарии для QA

Сквозные проходы, которые стоит прогнать целиком, а не по экранам:

1. **Новый человек по приглашению:** получил ссылку → вход → подтверждение → проект →
   создал задачу → назначил на себя → задача появилась в сайдбаре.
2. **Ссылка на задачу без сессии:** открыл `/issues/DEV-42` → вход → **попал на задачу**.
3. **Протухшее приглашение у постороннего:** → «Доступ к трекеру закрыт», а не
   «приглашение истекло».
4. **Отзыв доступа во время работы:** удалили из списка доступа, пока человек печатал
   комментарий → черновик не потерян → после входа «Доступ закрыт»; владелец увидел
   в тосте, сколько сессий погашено.
5. **Понижение роли на лету:** админ понизил себя до участника → вкладки «Приглашения»
   и «Настройки» исчезли без перезагрузки.
6. **Оптимистичный откат:** отключить сеть, сменить статус → чип вернулся, тост показан,
   история не изменилась.
7. **Два пользователя на одной задаче:** один меняет статус, второй видит изменение
   за ≤ 5 с, при этом его недописанный комментарий не пострадал.
8. **Плотность и производительность:** очередь на 2000 задач, прокрутка от начала
   до конца, курсор клавиатуры не теряется.
9. **Длинные данные:** задача с названием в 255 символов, комментарий из 300 символов
   без пробелов, email в 254 символа — ничего не выходит за границы и не рождает
   горизонтальную прокрутку.
10. **Клавиатура целиком:** от входа до отправки комментария, ни разу не тронув мышь.
