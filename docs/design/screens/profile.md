# Экран: профиль и настройки уведомлений

Маршрут `/me` (канон ADR-0005; `/profile` оставлен постоянным редиректом). Внутри оболочки. Истории — US-04, US-103, US-104.
Общие соглашения — [README.md](./README.md).

> **Частично без контракта.** `GET /api/me` отдаёт имя, email, аватар,
> `isInstanceOwner`, `canManageAccessList` и данные сессии. **Настроек уведомлений
> в контракте пока нет** — секция «Уведомления» описана раньше API (`README.md` 8.5).

## Назначение и главный сценарий

Два сценария, оба редкие:

1. Убедиться, под каким аккаунтом вошёл (US-04) — «я в личном или в рабочем?».
2. Отключить тип уведомлений, который надоел (US-103).

Экран открывается из меню профиля в шапке. Настроек в трекере почти нет,
и это правильно: данные приходят из Яндекс ID и здесь не редактируются.

## Компоненты и токены

### Блок «кто я»

| Элемент | Токены |
|---|---|
| Аватар | `lg` (48), круг |
| Имя | `h2` `textPrimary` |
| Email | `body` `textMuted`, выделяемый мышью (его копируют) |
| Баннер | `info`-баннер (`components.md` 17.2), `accentSurface` + `accentBorder` |

**Поля не редактируются** (US-04). Показываются как текст, не как отключённые поля
ввода: `disabled`-поле обещает, что когда-нибудь станет активным, а здесь этого
не будет никогда. Баннер объясняет причину — без него экран выглядит сломанным.

### Строка настройки уведомления (высота 48)

| Зона | Содержимое |
|---|---|
| Слева | название типа `bodyS` `textPrimary`; при необходимости вторая строка-уточнение `label` `textMuted` |
| Справа | переключатель 32 × 18 (`components.md` 23) |

Разделитель между строками — 1 px `borderSubtle`.

**Формулировка от первого лица и от события**, а не от системы: «Меня упомянули
в тексте», а не «Уведомления об упоминаниях». Общая шапка «Присылать уведомления,
когда:» превращает список в связное предложение — так его читают без усилий.

Шесть типов, ровно как в US-103 и US-104:

| # | Текст | Уточнение |
|---|---|---|
| 1 | Меня назначили исполнителем задачи | — |
| 2 | Меня указали автором задачи | — |
| 3 | Меня упомянули в тексте | — |
| 4 | Изменился статус задачи, на которую я подписан | — |
| 5 | Появился комментарий к задаче, на которую я подписан | — |
| 6 | В проект вступил новый участник | «Только для проектов, где вы администратор» |

По умолчанию включены все (US-103).

**Тип 3 «упоминание» — отдельный от типа 5.** Это принципиально: US-104 требует,
чтобы уведомление об упоминании приходило независимо от того, отключены ли комментарии.
Если пользователь отключит тип 5, но оставит 3, он будет получать только те комментарии,
где его позвали лично, — это самый ценный режим, и он должен быть достижим.
Порядок в списке (3 перед 5) подсказывает эту связку.

### Блок «Сессия»

Кнопка «Выйти» — `secondary` `md` (US-03). Не `danger`: выход — обычное действие,
а не разрушительное.

Списка активных сессий и «выйти на всех устройствах» в MVP нет (US-02).

## Поведение

| Действие | Результат |
|---|---|
| Переключение тумблера | **оптимистично**: положение меняется сразу, запрос уходит следом. Кнопки «Сохранить» нет |
| Ошибка сохранения настройки | тумблер возвращается в прежнее положение за `motionBase`, тост-ошибка «Не удалось сохранить настройку» + «Повторить» |
| Отключение типа | новые уведомления этого типа не создаются вовсе: ни записи, ни счётчика (US-103). Уже полученные остаются в ленте |
| «Выйти» | подтверждения нет: действие обратимо в одно нажатие. Переход на `/login` |
| Копирование email | обычное выделение мышью; отдельной кнопки копирования нет — email копируют редко |

**Отключение всех шести типов** — допустимо и не блокируется, но под списком появляется
баннер `warning`: «Все уведомления отключены. Вы не узнаете о назначенных задачах
и упоминаниях». Не запрещаем, но и не даём сделать это молча.

## Состояния

| Состояние | Что видно |
|---|---|
| **Загрузка** | блок «кто я» — скелетон: круг 48, полоска имени 200 × 20, полоска email 240 × 14. Список настроек — 6 строк-скелетонов по 48 с полоской 60 % и прямоугольником переключателя 32 × 18 |
| **Пусто** | невозможно: у пользователя всегда есть имя, email и шесть настроек |
| **Пусто после фильтра** | невозможно: фильтров нет |
| **Ошибка загрузки** | состояние ошибки на весь экран: «Не удалось загрузить профиль» + «Повторить» |
| **Ошибка загрузки только настроек** | частичная ошибка: блок «кто я» показан, на месте списка — «Не удалось загрузить настройки» + «Повторить» |
| **Нет прав** | невозможно: пользователь видит только свой профиль, чужого не существует ни в UI, ни в API (`permissions.md` 2.6) |
| **Много данных** | невозможно: список фиксирован из шести пунктов |
| **Очень длинное имя** | до 2 строк, `ellipsis`, полное — в тултипе |
| **Очень длинный email** | обрезка посередине (`ivan…@очень-длинный-домен.ru`), полный — в тултипе и доступен выделением |
| **Аватар не загрузился** | инициалы на цветной заливке из `SLAvatarColors`, молча |
| **Имя из Яндекс ID пустое** | показывается email как заголовок, инициалы — первая буква email |
| **Пользователь не администратор ни в одном проекте** | тип 6 остаётся в списке, но получает уточнение `label` `textMuted`: «Сейчас вы не администратор ни в одном проекте». Пункт не скрываем: он появится при первом же назначении, и исчезающие настройки пугают |
| **Пользователь — владелец трекера** | в блоке «кто я» под email появляется бейдж «Владелец трекера» (контурный, как бейдж роли). Пояснение `label` `textMuted`: «Вы можете управлять доступом в трекер. Прав внутри проектов это не даёт» — иначе признак читается как «я тут главный везде» |
| **Все типы отключены** | баннер `warning` под списком, см. выше |
| **Данные обновились после входа** | имя и аватар обновляются из Яндекс ID при каждом входе (US-01); на экране это происходит молча, без уведомления |

## Клавиатура

| Клавиша | Действие |
|---|---|
| `Tab` | по переключателям сверху вниз, затем «Выйти» |
| `Space` | переключить тумблер под фокусом |
| `Enter` на «Выйти» | выход |
| `Esc` | вернуть фокус в шапку экрана |

Порядок фокуса совпадает с визуальным порядком. Блок «кто я» интерактивных элементов
не содержит и в порядок фокуса не входит — кроме выделяемого email.

## Адаптив

| Брейкпоинт | Раскладка |
|---|---|
| `xl` / `lg` | контент 720, одна колонка |
| `md` 768–1023 | то же, ширина минус `space4` |
| `sm` < 768 | аватар уменьшается до `md` (32) и встаёт над именем; строка настройки растёт до 64, если текст занимает две строки; переключатель остаётся справа, зона нажатия 44 × 44; кнопка «Выйти» на всю ширину |

Текст настройки на `sm` **не сокращается**: «Появился комментарий к задаче, на которую
я подписан» переносится на две строки, но остаётся полным. Сокращённая формулировка
(«Комментарии») теряет смысл — непонятно, о чьих комментариях речь.

## Доступность

- Заголовок «Профиль» — `Semantics(header: true)`, фокус при входе.
- «УВЕДОМЛЕНИЯ» и «СЕССИЯ» — тоже заголовки (`header: true`), для навигации
  по заголовкам.
- Переключатель: доступное имя — полный текст настройки, состояние передаётся
  флагом `toggled`, а не словами «включено/выключено» в имени.
  Скринридер сам скажет «включено».
- Список настроек объявляется как группа с меткой «Присылать уведомления, когда».
  Без неё каждый пункт читается как оторванная фраза.
- Уточнения («Только для проектов, где вы администратор») входят в доступное имя
  переключателя, а не существуют отдельным текстом рядом.
- Баннер про Яндекс ID и баннер «все отключены» — `liveRegion: polite`.
- Откат переключателя при ошибке объявляется голосом: «Настройка не сохранена,
  переключатель возвращён».
- Контраст: `textMuted` на `surface` — 5.32:1; переключатель во включённом состоянии
  `accent` — 4.86:1 к `surface`, в выключенном `trackDefault` — различается положением
  бегунка, а не только цветом.
- Зона нажатия переключателя — вся строка 48 (на тач 44 минимум по высоте гарантированы).

## Реализация во Flutter

| Что | Как | Оценка |
|---|---|---|
| Разметка | `Column` + `ConstrainedBox(maxWidth: 720)` | стандарт |
| Переключатель | `Switch` + `SwitchTheme` | стандарт + тема |
| Строка настройки | `InkWell` на всю строку + `Row` | тривиально; клик по строке переключает тумблер |
| Оптимистичное сохранение | Riverpod с откатом при ошибке | стандарт |
| Аватар | `CircleAvatar` + `errorBuilder` | стандарт |
| Обрезка email посередине | своя функция усечения | тривиально, ~10 строк |

Кастомных виджетов экран не требует вовсе — это самый простой экран продукта.

## Открытые вопросы

- **Q-D27 закрыт.** Пункт меню «Доступ к трекеру» ведёт на отдельный экран
  `/me/access` ([access-list.md](./access-list.md)), видимость — по флагу
  `canManageAccessList` из `GET /api/me`. Экран отдельный, а не секция профиля:
  личные настройки и администрирование инстанса не смешиваются.
- **Q-D28.** US-04 говорит, что настройки уведомлений живут на экране профиля.
  Сейчас это один экран с двумя секциями. Если типов уведомлений станет больше
  восьми, секцию придётся выносить отдельно — но не в MVP.
- **Q-D29.** Нужно ли показывать срок жизни сессии? Контракт его отдаёт
  (`MeSessionDto.expiresAt`, плюс `kind`: `cookie` или `bearer`). US-02 показывать
  не требует. Считаю по-прежнему лишним на экране: пользы мало, вопросов много.
  Поле пригодится клиенту для упреждающего продления сессии, а не для отображения.
