# Экран: мои проекты

Маршрут `/` (канон ADR-0005; `/projects` оставлен постоянным редиректом). Внутри оболочки ([app-shell.md](./app-shell.md)).
Истории — US-10, US-11. Общие соглашения — [README.md](./README.md).

## Назначение и главный сценарий

Пользователь видит все проекты, где он состоит, и переходит в нужный. Второй сценарий —
создать проект. Экран открывается редко (обычно человек живёт в очереди или в задаче),
поэтому здесь допустима меньшая плотность, чем в списках задач: карточки, а не таблица.

## Раскладка (`lg` ≥ 1024)

```
+----------------------------------------------------------------------------+
| Мои проекты                                          [+ Создать проект]    |  44
+----------------------------------------------------------------------------+
                                                                               space6
+---------------------------+ +---------------------------+ +----------------+
|                           | |                           | |                |
|      обложка 16:9         | |      обложка 16:9         | |    обложка     |  158
|                           | |                           | |                |
+---------------------------+ +---------------------------+ +----------------+
| Sweet Limit               | | Веб-сайт компании         | | Инфраструктура |  title
| Мобильное приложение для… | | Лендинг и блог            | | —              |  bodyS
|                           | |                           | |                |
| [АИ][ПС][МК] +2   Админ   | | [ПС][МК]          Участник| | [АИ]   Читатель|  28
+---------------------------+ +---------------------------+ +----------------+
       карточка 280 × 268            зазор space4 (16)
```

Сетка: карточки фиксированной ширины 280, выкладываются в ряд с переносом
(`Wrap`), выравнивание по левому краю. Не растягиваются на всю ширину:
на широком мониторе три карточки шириной по 600 px выглядят нелепо.

## Компоненты и токены

### Шапка экрана (высота 44)

| Элемент | Токены |
|---|---|
| Заголовок «Мои проекты» | `h2` `textPrimary` |
| Кнопка «Создать проект» | кнопка `md`, `primary`, иконка `add_rounded` `icon16` |
| Фон | `surface`, нижняя граница 1 px `borderSubtle` |

Кнопка видна **всем** пользователям, прошедшим список доступа: отдельного права
на создание проектов нет (US-11, `permissions.md` 2.1).

### Карточка проекта (280 × 270)

**Геометрия задана числами, а не соотношением сторон.** Высота обложки — ровно 158 px,
`AspectRatio(16 / 9)` использовать нельзя: от ширины 280 он даёт 157,5 и тянет за собой
дробную высоту всей карточки. Дробные размеры на дисплеях с нецелым DPR дают мыло
на границе и мешают выравнивать сетку. 158 вместо 157,5 — это 16:9,04, глазом
не отличимо.

Из чего складывается 270: граница 1 + обложка 158 + padding 12 + название 22 +
описание 36 + подвал 28 + padding 12 + граница 1.

Замер реализации (269,5) был верным — ошибка в моей спеке: я указал 268, забыв границы,
и одновременно задал обложку соотношением. Обе части исправлены здесь.

| Зона | Высота | Содержимое | Токены |
|---|---|---|---|
| Обложка | **158 фиксированно** | изображение `fit: cover` либо заглушка | верхние углы `radiusMd` |
| Название | 22 | `title` `textPrimary`, одна строка, `ellipsis` | padding `space3` |
| Описание | 36 | `bodyS` `textMuted`, **ровно 2 строки**, `ellipsis` | — |
| Подвал | 28 | группа аватаров слева, бейдж роли справа | — |

- Карточка: фон `surface`, граница 1 px `border`, `radiusMd`, **без тени** —
  тень означает всплытие над контентом (`system.md` 10.7).
- **Заглушка обложки** (обложки нет): заливка `surfaceSunken`, по центру монограмма —
  первые две буквы названия, `h1` цветом из `SLAvatarColors` по `hash(projectId) % 8`,
  на подложке того же цвета с прозрачностью 12 %. Так проекты без обложек всё равно
  различаются глазами, а не сливаются в серые прямоугольники.
- **Группа аватаров** — `components.md` 9.3, размер `xs`, первые 3 + счётчик `+N`.
  Число участников читается из группы; отдельной подписи «5 участников» нет.
- **Бейдж роли** — `components.md`, раздел 7. Ширина колонки **по содержимому**
  (минимум 72, максимум 140), а не фиксированные 96: при крупном системном шрифте
  бейдж «Администратор» в 96 px обрезается по краю. Бейдж **никогда не сжимается
  и не обрезается** — он сжимает соседей: при нехватке места первой уступает группа
  аватаров (счётчик `+N` вместо трёх аватаров, затем только счётчик).
  Замеченная реализацией обрезка — дефект моей спеки, а не вёрстки.
- Показывается **всегда**, включая «Участник»:
  на этом экране роль — полезная информация («куда я могу вносить изменения»),
  в отличие от списка участников, где роль по умолчанию не выделяют.
  Это отступление от правила раздела 7 `system.md`, зафиксировано осознанно.

### Состояния карточки

| Состояние | Оформление |
|---|---|
| Обычное | как выше |
| Наведение | граница `borderStrong`, обложка увеличивается до 102 % за `motionFast`. Тени не появляется |
| Фокус | `borderFocusRing` вокруг карточки |
| Нажатое | фон `surfaceHover` |
| Обложка грузится | заливка `skeletonBase` в габаритах обложки |
| Обложка не загрузилась | молча показывается заглушка-монограмма, без иконки «сломанное изображение» |

| `Ctrl/Cmd + клик`, средний клик | в новой вкладке |

### Модалка «Создать проект»

Ширина `sm` (400).

```
+------------------------------------------+
| Создать проект                      [×]  |  48
+------------------------------------------+
| Название *                               |  label textSecondary
| +--------------------------------------+ |
| |                                      | |  поле md
| +--------------------------------------+ |
| Адрес проекта будет:                     |  label textMuted
| /projects/sladkiy-limit                  |  mono 13, textSecondary
|                                          |
| Описание                                 |
| +--------------------------------------+ |
| |                                      | |  многострочное, 3 строки
| +--------------------------------------+ |
+------------------------------------------+
|                   [ Отмена ] [ Создать ] |  56
+------------------------------------------+
```

- **Обязательное поле одно** — название, 1–100 символов, счётчик остатка появляется
  на 80-м символе.
- **Предпросмотр адреса** обновляется по мере ввода названия: транслитерация выполняется
  на клиенте по правилам [D-35](../../product/decisions.md#d-35) («Сладкий Лимит 2026!»
  → `sladkiy-limit-2026`). Это предпросмотр, а не обещание: если сервер добавит суффикс
  из-за коллизии (`-2`), после создания показывается фактический адрес. Расхождение
  пользователя не пугает, если предпросмотр подписан как «будет»,
  а не «адрес проекта».
- Если из названия не выходит ни одного допустимого символа (эмодзи), предпросмотр
  показывает `project-…` с пояснением `label` `textMuted`: «Адрес будет назначен автоматически».
- Обложка при создании **не загружается** — это лишний шаг в самом первом действии
  пользователя. Добавляется потом, на экране проекта (US-12).
- Пустое название: кнопка «Создать» отключена, ошибка у поля по потере фокуса,
  запрос на сервер не уходит (US-11).
- После создания — переход на `/projects/<slug>` с подсказкой следующего шага
  «создайте очередь» (см. [project.md](./project.md), состояние «нет очередей»).

## Клавиатура

| Клавиша | Действие |
|---|---|
| `Tab` | по карточкам в порядке сетки (слева направо, сверху вниз) |
| `Enter` | открыть проект |
| `n` | создать проект (когда фокус не в поле ввода) |
| `Esc` | закрыть модалку создания |
| `Ctrl/Cmd + Enter` | отправить форму создания из любого поля |

Стрелки по сетке карточек **не** используются: `Tab` для десятка карточек достаточно,
а двумерная навигация стрелками потребовала бы кастомной модели фокуса ради редкого экрана.

## Адаптив

| Брейкпоинт | Раскладка |
|---|---|
| `xl` ≥ 1440 | карточки 280, до 5 в ряд, контент центрируется в 1600 |
| `lg` 1024–1439 | карточки 280, 2–3 в ряд (при сайдбаре 280 и окне 1280 содержимое 1000 → 3 карточки с зазорами) |
| `md` 768–1023 | карточки 280, 2 в ряд; сайдбар свёрнут, отступы страницы `space4` |
| `sm` < 768 | **одна колонка**, карточка на всю ширину минус `space4`; обложка 16:9 сохраняется; кнопка «Создать проект» в шапке сжимается до иконочной, подпись уходит |

На `sm` карточка остаётся карточкой (а не строкой списка): обложка — главный способ
узнать проект глазами, и терять её ради плотности на экране, куда заходят раз в день,
не стоит.

## Доступность

- Заголовок «Мои проекты» — `Semantics(header: true)`, на него встаёт фокус при входе.
- Карточка — одна фокусируемая группа с доступным именем:
  «Sweet Limit, мобильное приложение для…, 5 участников, ваша роль: администратор».
  Отдельные аватары и бейдж из порядка фокуса исключены.
- Обложка и монограмма декоративны (`excludeFromSemantics: true`).
- Роль передаётся текстом бейджа, а не только положением или цветом.
- Контраст: `textMuted` описания на `surface` — 5.32:1; граница карточки декоративна
  (1.27:1) и под требование 1.4.11 не подпадает, так как карточка обозначена
  не только границей (обложка, заголовок, фон при наведении).
- Сетка объявляется как список: `Semantics(label: 'Проекты, 7')`.

## Реализация во Flutter

| Что | Как | Оценка |
|---|---|---|
| Сетка карточек | `Wrap(spacing: 16, runSpacing: 16)` | стандарт |
| Сетка при 100+ | `GridView.builder` с `SliverGridDelegateWithMaxCrossAxisExtent` | стандарт |
| Карточка | `InkWell` + `Column`, без `Card` (у `Card` своя тень и свои отступы) | лёгкий кастом |

| Монограмма-заглушка | `Container` + `Text` | тривиально |
| Транслитерация для предпросмотра адреса | своя функция; готового пакета под правила D-35 брать не нужно | **кастом, ~40 строк**; правила и проверочный пример — в D-35 |

## Открытые вопросы

- **Q-D9.** Предпросмотр адреса в модалке создания считается на клиенте и может разойтись
  с серверным (коллизия → суффикс). Предлагаю подпись «Адрес проекта будет:» и молчаливое
  принятие серверного значения. **Контракт подтверждает, что расхождение возможно:**
  `ProjectDto.slug` отдаёт действующее короткое имя, и клиенту предписано заменить адрес
  в строке браузера на него. Остаётся сверить правило транслитерации на клиенте
  и сервере — иначе предпросмотр будет врать не только в случае коллизии.
- **Q-D10 закрыт.** Контракт отдаёт и `members` (первые участники для группы аватаров),
  и `memberCount` (общее число). Группа аватаров строится из `members`, счётчик `+N`
  считается как `memberCount` минус показанные — то есть число участников на карточке
  присутствует, как и просил US-10.
