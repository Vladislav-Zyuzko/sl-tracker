Версия 1.0. Владелец: `sl-designer`. Опирается на
[`../system.md`](../system.md) (токены) и [`../components.md`](../components.md) (компоненты).
Здесь собрано то, что иначе повторялось бы в каждом из одиннадцати файлов.

**Читать перед любой спекой экрана.** Если в спеке экрана что-то противоречит этому файлу —
прав файл экрана, но противоречие надо считать ошибкой и сообщить дизайнеру.

## 2. Брейкпоинты

| Имя | Ширина окна | Что меняется |
|---|---|---|
| `xl` | ≥ 1440 | всё видно; контент центрируется, максимальная ширина рабочей области 1600 |
| `lg` | 1024–1439 | базовая десктопная раскладка, сайдбар 240 развёрнут |
| `md` | 768–1023 | сайдбар свёрнут до 48 (только иконки); часть колонок таблицы скрыта |
| `sm` | < 768 | сайдбар — выдвижная панель поверх контента; таблицы становятся списками |
| min | 360 | минимальная поддерживаемая ширина; горизонтальной прокрутки страницы нет никогда |

Ниже 360 px интерфейс не поддерживается — это зафиксировано, а не забыто.

## 3. Состояния, обязательные для каждого экрана

Спека экрана обязана описать все семь. Если состояние на экране невозможно —
это пишется явно («невозможно, потому что …»), а не опускается.

1. **Загрузка** — скелетон по геометрии реального контента, не спиннер по центру.
   Показывается не раньше 200 мс, держится минимум 400 мс (`components.md` 15).
2. **Пусто** — с объяснением, что это значит, и действием.
3. **Пусто после фильтра/поиска** — другой текст и другое действие, чем у обычного пустого.
4. **Ошибка** — что случилось и кнопка «Повторить».
5. **Нет прав** — контролы не показываются; если открыт чужой объект — «не найдено».
6. **Очень много данных** — виртуализация, пагинация, «99+».
7. **Очень длинный текст** — `ellipsis` + тултип, перенос по символам, ограничение ширины.

## 4. Права: как это выглядит на экране

Роли — `admin` / `member` / `reader` в конкретном проекте
([`permissions.md`](../../product/permissions.md)).

| Правило | Как реализуется в UI |
|---|---|
| Действие не разрешено ролью | контрол **не отображается вообще**. Не «серый и с тултипом» — просто нет |
| Значение поля не редактируется | показывается как текст (`textPrimary`), не как `disabled`-поле |
| Объект не виден пользователю | экран «не найдено», без названия объекта и любых его данных |
| Ответ сервера `403` при видимом объекте | тост-ошибка «Недостаточно прав» + откат оптимистичного изменения |
| Ответ сервера `404` | переход на экран «не найдено» соответствующего типа |

**Читатель** видит все данные и ни одного контрола изменения: ни выпадающих списков,
ни кнопок «Создать», ни поля комментария, ни меню «⋯» с действиями.

Скрытие контрола — удобство, а не защита: сервер обязан отказать независимо
([`permissions.md`](../../product/permissions.md), п. 6).

## 5. Глобальные хоткеи

Работают на любом экране внутри оболочки. Не срабатывают, когда фокус в поле ввода
(кроме тех, что помечены «всегда»).

| Клавиша | Действие |
|---|---|
| `/` | фокус в поиск сайдбара |
| `Ctrl/Cmd + K` | то же, **всегда**, включая поля ввода |
| `g` затем `p` | к списку проектов |
| `g` затем `i` | к списку активных задач (фокус в сайдбар) |
| `g` затем `n` | центр уведомлений |
| `c` | создать задачу (диалог выбора очереди, если контекст неизвестен) |
| `?` | окно со списком горячих клавиш |
| `Esc` | закрыть верхний слой: меню → поповер → модалку → выдвижной сайдбар |

Двухклавишные последовательности (`g` + буква) ждут вторую клавишу 1500 мс, затем сбрасываются.
Индикации ожидания нет — она отвлекает; последовательность либо угадана, либо нет.

## 6. Порядок фокуса — общий скелет

Внутри оболочки `Tab` идёт так:

```
1. «Перейти к содержимому» (скрытая ссылка, видна только при фокусе)
2. Шапка: логотип → создать задачу → уведомления → меню профиля
3. Сайдбар: свернуть → «Мои проекты» → поиск → список активных задач
4. Содержимое экрана
```

Правила:

- при открытии модалки фокус ловится внутри неё и возвращается на вызвавший элемент;
- при переходе между экранами фокус ставится на заголовок `h2` нового экрана
  (`Focus` + `Semantics(header: true)`), чтобы скринридер объявил, куда попал;
- виртуализированные списки не ловят фокус построчно: в список входит `Tab`, внутри
  перемещение стрелками, выход — `Tab`.

## 7. Обновление данных без перезагрузки

[D-26](../../product/decisions.md#d-26): изменения, сделанные другими людьми, появляются
не позднее чем через **5 секунд**. Транспорт — забота фронтенда; дизайн задаёт только
наблюдаемое поведение:

| Что | Как ведёт себя при внешнем изменении |
|---|---|
| Поле в панели задачи | значение меняется на месте; фон поля на 200 мс `accentSurface`, затем гаснет |
| Новый комментарий | добавляется в конец ленты; если пользователь не внизу — плашка «Новых комментариев: 2», по клику прокрутка вниз |
| Счётчик уведомлений | меняется молча, без анимации и без звука |
| Текст, который набирает пользователь | **не трогается никогда**: ни поле комментария, ни открытый редактор описания |
| Список задач очереди, список проектов | не обновляются сами; обновляются при открытии и переходе |

Ни одно внешнее обновление не двигает то, на что пользователь сейчас смотрит,
и не уводит фокус.

## 8. Тексты: общие правила

- Заголовки экранов и кнопок — без точки в конце. Пояснения — с точкой.
- Кнопка называется глаголом действия: «Создать задачу», а не «ОК».
- Сообщение об ошибке говорит, что делать, а не что произошло внутри.
- Числа больше порога: счётчик уведомлений — «99+», счётчик задач — «999+».
- Термины — только из [`glossary.md`](../../product/glossary.md). Запрещённые слова
  («доска», «тикет», «наблюдатель», «спринт», «слаг» в UI) не появляются на экранах.
