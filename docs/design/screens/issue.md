# Экран: задача

Маршрут `/issues/<KEY>-<N>`, например `/issues/DEV-42`. Внутри оболочки.
Истории — US-41 … US-48, US-50 … US-54, US-61, US-70 … US-74, US-90 … US-92.
Общие соглашения — [README.md](./README.md).

> **Состояние контракта.** В `docs/api/openapi.json` есть задача, её поля, история
> и внешние ссылки (`/api/issues/{key}`, `/api/issues/{key}/history`,
> `/api/issues/{key}/links`). **Комментариев и вложений в контракте пока нет** —
> соответствующие разделы этой спеки описывают экран раньше, чем появился API.
> Фронтенду: не начинать их, пока контракт не написан (`README.md` 8.5).

## Назначение и главный сценарий

Самый важный экран продукта. Пользователь открывает задачу по ссылке из чата,
за несколько секунд понимает, о чём речь и в каком она состоянии, и делает одно
из трёх: меняет статус, назначает исполнителя, пишет комментарий.

Отсюда приоритет раскладки: **название и статус — первое, что видно; поле комментария
достижимо без долгой прокрутки; поля задачи не конкурируют с содержанием за внимание.**

## Решение: где живёт история

**История — вкладка рядом с комментариями, а не блок под ними.**

Обоснование:

1. **Две ленты с пагинацией на одной оси прокрутки — ловушка.** И комментарии (100+,
   US-70), и история (US-90) подгружаются порциями. Если история лежит под комментариями,
   до неё нужно прокрутить всю ленту обсуждения и дождаться всех дозагрузок. На задаче
   с сотней комментариев история становится практически недостижимой.
2. **Разная частота обращения.** Комментарии читают каждый визит, историю — когда
   возник спор «кто это поменял». Постоянно показывать редко нужное — терять место.
3. **Разный порядок сортировки.** Комментарии — старые сверху, как переписка (US-70).
   История — новые сверху (US-90). Две соседние ленты с противоположным порядком
   в одном скролле читаются как ошибка. Во вкладках это не смущает никого.
4. **Поле комментария должно быть близко.** Если между лентой и полем ввода вклинивается
   история, главное действие экрана уезжает вниз.

Что теряем: историю не видно, пока на неё не переключишься. Компенсируем — счётчик
у вкладки не показываем (число записей истории ничего не значит), но при наличии
изменений за последний час у вкладки «История» появляется точка `accent` 6 px.

Вкладка по умолчанию — **«Комментарии»**, всегда, даже если комментариев нет.
Возврат на задачу не запоминает выбранную вкладку: обсуждение важнее.

## Компоненты и токены

### Шапка задачи

| Элемент | Токены |
|---|---|
| Хлебные крошки | `bodyS` `textMuted`, разделитель «/» `iconMuted`; «Проект / Очередь». Задача в крошках не повторяется |
| Ключ `DEV-42` | `bodySStrong` `accent`, tabular |
| Кнопка копирования ключа | иконочная `sm`, `content_copy_rounded` `icon16`, тултип «Скопировать ключ» |
| Кнопка копирования адреса | в меню «⋯»: «Скопировать ссылку на задачу» (US-41) |
| Название | `h2` `textPrimary`, редактируется на месте, до 3 строк, дальше `ellipsis` |
| «⋯» | «Скопировать ссылку», «Скопировать ключ», разделитель, «Удалить задачу» (`dangerGhost`, **только админ**, US-44) |

**Редактирование названия на месте.** Клик по названию (у кого есть право) превращает
его в поле `lg` того же кегля; `Enter` — сохранить, `Esc` — отменить, потеря фокуса —
сохранить. Счётчик остатка появляется на 200-м символе из 255 (US-42).
Пустое название не сохраняется: поле подсвечивается `borderDanger`, показывается
сообщение «Название не может быть пустым», прежнее значение остаётся.

### Панель полей (ширина 320)

Поля идут в порядке частоты обращения, а не алфавита:

| Поле | Компонент | Комментарий |
|---|---|---|
| Статус | выпадающий список (`components.md` 5), чип 24 | самое частое действие |
| Приоритет | индикатор приоритета, расширенная форма: `▓ 80 · Высокий` | значение всегда есть (US-50) |
| Сложность | индикатор сложности; не оценена — `Не оценено` `textMuted` | US-51 |
| Автор | селектор пользователя | US-53; слово «Создатель» на экране не используется |
| Исполнитель | селектор пользователя + быстрое действие «Назначить на себя» | US-52 |
| — разделитель — | 1 px `borderSubtle`, отступы `space4` | |
| Очередь | `bodyS` `textSecondary`, ссылка на `/queues/DEV` | не редактируется |
| Создана | `bodyS` `textMuted`, дата; точное время в тултипе | не редактируется |
| Изменена | `bodyS` `textMuted`, относительное время | не редактируется |

Подпись поля — `label` `textSecondary` над значением, отступ `space1`.
Между полями `space4`. Фон панели — `surface`, левая граница 1 px `border`.

**«Назначить на себя»** — текстовая кнопка `sm` под полем исполнителя, показывается
только когда текущий пользователь не исполнитель и имеет право менять поле (US-52).

Все поля редактируются **на месте, без общей кнопки «Сохранить»** (US-54).
Каждое изменение — оптимистичное, с откатом и тостом при ошибке; на сервер уходит
частичное обновление `PATCH /api/issues/{key}`.

**Видимость контролов определяется флагом `permissions.canEdit`, а не ролью**
(`README.md` 8.3). Отдельные коды отказа, которые экран обязан различать:
`assignee_not_member` и `author_not_member` — выбранный человек больше не участник
проекта (например, его исключили, пока список был открыт). Текст тоста:
«<Имя> больше не участник проекта», список участников перезапрашивается.

### Описание

Markdown-блок (`components.md` 18), ширина до 720. Заголовок секции `overline`
`textMuted` «ОПИСАНИЕ», справа текстовая кнопка «Изменить» (`sm`, `ghost`).

Редактор — режим «Написать / Просмотр» (`components.md` 18.3): две вкладки, панель
из шести кнопок форматирования, поле от 8 до 20 строк. Внизу — «Отмена» и «Сохранить»,
подсказка «Ctrl+Enter — сохранить».

- Упоминания через `@` работают и в описании (US-43, US-74).
- **Сервер разметку не санитизирует** (`IssueDto.description`): описание приходит как
  есть, и безопасность рендера целиком на клиенте. Требования `components.md` 18 —
  сырой HTML не исполняется и не рендерится как разметка, схемы кроме `http`, `https`
  и `mailto` не становятся кликабельными — здесь не оформление, а единственная защита.
- Текст `DEV-42` в описании остаётся **обычным текстом**: автоссылок в MVP нет
  ([D-38](../../product/decisions.md#d-38), `components.md` 18.1.1).
- Внешние ссылки открываются в новой вкладке; схемы кроме `http`, `https`, `mailto`
  не становятся кликабельными (US-43).
- Сырой HTML не исполняется и не рендерится как разметка.

**Конфликт редактирования** ([D-27](../../product/decisions.md#d-27)): если во время
редактирования описание изменил другой пользователь, при сохранении показывается
модалка: «Описание изменил <Имя>, пока вы редактировали» с двумя кнопками —
«Перезаписать» (`danger`) и «Отменить мои изменения» (`secondary`), и предупреждением,
что просмотреть чужую версию можно, отменив свои правки. Молча перезаписывать нельзя.

### Вложения

Заголовок `overline` «ВЛОЖЕНИЯ» + счётчик, справа «Прикрепить» (`ghost` `sm`).
Плитки — `components.md` 22: изображения сеткой 160 × 120, остальные файлы строками 48.
Изображения идут первыми, файлы — под ними.

- Перетаскивание файлов на **всю область задачи** (US-46): при перетаскивании вся
  левая колонка получает пунктирную границу 2 px `accent`, фон `accentSurface`
  и надпись по центру «Отпустите файлы, чтобы прикрепить».
- Несколько файлов за раз, у каждого свой прогресс (US-46).
- Файл больше 25 МБ отклоняется сразу, остальные из выбранных загружаются.
- Удалить может админ или тот, кто приложил (US-46); у остальных пункта нет.
- **Блок скрывается целиком, если вложений нет** (US-48): пустого блока не показываем,
  остаётся только кнопка «Прикрепить» в общей строке действий под описанием.

### Ссылки

Заголовок `overline` «ССЫЛКИ» + счётчик, справа «Добавить» (`ghost` `sm`).
Строка 32: иконка `open_in_new_rounded` `icon16` `iconMuted`, подпись `bodyS` `accent`
(если подписи нет — сам адрес, обрезанный посередине), справа при наведении — «⋯»
с пунктом «Удалить».

При 10+ ссылках список сворачивается до 5 с кнопкой «Показать все (N)» —
US-47 оставляет решение дизайнеру.

Блок скрывается целиком, если ссылок нет (US-48).

### Комментарии

Лента — `components.md` 20, порядок **старые сверху** (US-70).
Поле ввода — `components.md` 19, под лентой, свёрнутое до 40 px.

- Упоминания `@`: подсказка показывает **только участников этого проекта**
  ([ADR-0006](../../adr/0006-access-list.md), п. 6). Набранный вручную `@ivan`
  для постороннего остаётся обычным текстом и не подсвечивается (US-74).
- Подсказка `@`: аватар `xs` + имя; email второй строкой только при совпадении имён.
  `Esc` закрывает подсказку, `@` остаётся символом.
- Редактировать можно только свой комментарий, включая администратора (US-72).
  Удалить свой — автор, чужой — только админ проекта (US-73).
- Удалённый комментарий исчезает **полностью**, плашки «комментарий удалён» нет (US-73).
- Подгрузка порциями при 100+ (US-70): кнопка «Показать более ранние» сверху ленты.
- Читатель поля ввода не видит; вместо него строка `label` `textMuted`:
  «У вас нет прав комментировать» (US-71, `permissions.md` 2.5).

### История

Лента — `components.md` 21, порядок **новые сверху** (US-90).

- Первая по времени (то есть самая нижняя) запись всегда «Задача создана» с указанием
  **создателя** — даже если поле «Автор» потом меняли (US-90, D-13).
- Одно действие, изменившее несколько полей, — одна группа с общим временем и автором,
  внутри перечислены поля (US-90).
- Изменение описания — только факт: «Описание изменено», без старого текста (US-91).
  Раскрывающегося diff здесь **нет**: в MVP diff не хранится.
  (`components.md` 21 описывает diff как возможность компонента — на этом экране
  она не используется, и это надо знать, чтобы не реализовать лишнее.)
- Системные изменения (очистка исполнителя при исключении участника) — вместо аватара
  иконка `settings_rounded`, имя «Система» (US-91).
- Названия полей совпадают с подписями в панели полей и с глоссарием (US-92).
- Записи истории не редактируются и не удаляются никем.
- Контракт (`IssueHistoryGroupDto`) уже сгруппировал изменения: группа несёт время
  и автора, внутри — массив `changes`. Клиенту группировать ничего не нужно.
  `actor = null` означает системное изменение — показывается как «Система».
- `oldValue`/`newValue` приходят **читаемыми** (имя человека, название статуса, число),
  а `oldRefId`/`newRefId` — для аватара. `null` означает «пусто» и показывается словами:
  «не назначен», «не оценено», а не пустой строкой (US-91).
- Изменение описания приходит как `kind = description_changed` без текстов —
  показывается «Описание изменено», раскрытия нет.

## Поведение

| Действие | Результат |
|---|---|
| Смена статуса | оптимистично; при ошибке откат + тост «Не удалось изменить статус» + «Повторить» |
| Смена исполнителя, автора, приоритета, сложности | то же |
| Отправка комментария | появляется в ленте сразу с непрозрачностью 60 %; при ошибке — полоса `danger` слева, «Не отправлено», «Повторить» / «Удалить», **текст не теряется** (US-71) |
| Внешнее изменение (другой пользователь) | поле обновляется на месте, фон на 200 мс `accentSurface` (US-45, D-26) |
| Новый чужой комментарий | добавляется в конец; если пользователь не внизу ленты — плашка «Новых комментариев: 2», по клику прокрутка вниз |
| Набор текста при внешнем обновлении | **не прерывается и не сбрасывается никогда** (US-45) |
| Переход по уведомлению об упоминании | открытие задачи + прокрутка к нужному комментарию, подсветка `accentSurface` на 1200 мс (US-102, US-104) |
| Переход к удалённому комментарию | открывается задача, тост `info`: «Комментарий удалён» (US-102) |
| Удаление задачи | модалка подтверждения с перечислением последствий, кнопка `danger`; после — переход в очередь + тост |

## Состояния

| Состояние | Что видно |
|---|---|
| **Загрузка** | крошки и ключ появляются сразу (они есть в URL). Название — полоска 60 % × 20; описание — три полоски 100 / 100 / 60 % × 14; панель полей — 5 пар «подпись + значение» скелетоном; вкладки отрисованы, лента — 3 блока-скелетона комментариев |
| **Пусто: нет описания** | «Описание не заполнено» `body` `textMuted` курсивом + текстовая кнопка «Добавить описание» — у тех, кому можно (US-48) |
| **Пусто: нет вложений и ссылок** | блоки **не отображаются вовсе**, только контролы добавления в строке действий (US-48) |
| **Пусто: нет комментариев** | «Комментариев пока нет» + пояснение «Начните обсуждение — участники задачи получат уведомление». Поле ввода на месте |
| **Пусто: история** | невозможно: минимум одна запись «Задача создана» есть всегда (US-90) |
| **Пусто после фильтра** | невозможно: фильтров на экране нет |
| **Ошибка загрузки задачи** | экран «Не удалось загрузить задачу» + «Повторить» |
| **Задача не найдена / не участник** | «Задача не найдена», **без названия и любых данных** (US-41). Неизвестный ключ `DEV-9999` — тот же экран, отличить снаружи невозможно |
| **Ошибка загрузки одного блока** | частичная ошибка (`components.md` 17.3): на месте ленты комментариев — «Не удалось загрузить комментарии» + «Повторить». Остальная задача работает |
| **Нет прав: читатель** (`permissions.canEdit = false`) | все поля панели — текст без выпадающих списков и кнопок; нет «Изменить» у описания, нет «Прикрепить», нет «Добавить ссылку», нет поля комментария. Всё содержимое видно полностью (US-41) |
| **Нет прав: не админ** (`permissions.canDelete = false`) | пункт «Удалить задачу» отсутствует (US-44). Если при этом `canEdit = true`, меню «⋯» остаётся — в нём копирование ключа и ссылки |
| **Много комментариев (100+)** | подгрузка порциями, кнопка «Показать более ранние» |
| **Много истории** | подгрузка порциями; при 100+ записей лента виртуализируется |
| **Много вложений (20+)** | сетка изображений сворачивается до двух рядов с кнопкой «Показать все (N)» |
| **Очень длинное название** | до 3 строк, дальше `ellipsis` + тултип |
| **Очень длинное описание** | сворачивается на 400 px с градиентной маской и кнопкой «Показать полностью» (`components.md` 18.2) |
| **Строка из 300 символов без пробелов** | переносится по символам, горизонтальной прокрутки страницы не возникает — ни в описании, ни в комментарии, ни в названии |
| **Нет соединения** | полоса офлайна под шапкой + баннер над лентой: «Данные могут быть устаревшими» + «Обновить». Уже загруженное остаётся на экране (US-48) |
| **Задача удалена другим пользователем** | при следующем действии — «Задача не найдена» + тост `info`: «Задачу удалили» |

## Клавиатура

| Клавиша | Действие |
|---|---|
| `s` | меню смены статуса |
| `a` | селектор исполнителя |
| `i` | назначить на себя |
| `e` | редактировать описание |
| `m` | фокус в поле комментария |
| `Ctrl/Cmd + Enter` | отправить комментарий или сохранить описание |
| `Esc` | закрыть редактор или подсказку `@`; при непустом тексте — подтверждение |
| `y` | скопировать ключ задачи |
| `Shift + y` | скопировать ссылку на задачу |
| `←` `→` | переключение вкладок «Комментарии» / «История», когда фокус на ряду вкладок |
| `Ctrl/Cmd + B` / `I` / `K` | форматирование в редакторе |

Порядок фокуса: крошки → ключ → копирование ключа → «⋯» → название → «Изменить»
у описания → описание (ссылки внутри) → вложения → ссылки → вкладки → лента →
поле комментария → **панель полей**.

Панель полей стоит в порядке фокуса последней намеренно: она визуально справа,
но при чтении с клавиатуры содержание важнее. Хоткеи `s`, `a`, `i` дают к ней
прямой доступ без прохода по всему экрану.

## Адаптив

### `xl` ≥ 1440
Контент 720 + панель 320, всё центрируется в 1600.

### `lg` 1024–1439
Базовая раскладка: гибкая колонка (до 720) + залипающая панель 320.

### `md` 768–1023
- Панель полей **уезжает наверх**, под название, и превращается в горизонтальную
  ленту полей в две строки:

```
+--------------------------------------------------------------+
| Статус         Приоритет     Сложность   Автор      Исполн.  |
| [▶ В работе ⌄] ▓80·Высокий   [ 8 ]       [АИ] Анна  [ПС] Пётр|
+--------------------------------------------------------------+
```

- Служебные сведения (очередь, даты) сворачиваются в строку `label` `textMuted`
  под лентой полей.
- Содержимое — на всю ширину, но текст ограничен 720.

### `sm` < 768
- Всё в одну колонку. Порядок: крошки → ключ → название → **панель полей
  свёрнутым блоком** («Статус: В работе · Приоритет 80 · Исполнитель: Пётр»,
  раскрывается тапом) → описание → вложения → ссылки → вкладки → лента → поле ввода.
- Статус выносится **отдельно и всегда развёрнутым** над свёрнутым блоком:
  это действие, ради которого чаще всего открывают задачу с телефона.
- Поле комментария в свёрнутом виде прилипает к низу экрана; при фокусе разворачивается
  на весь экран с кнопкой «Отправить» в шапке.
- Сетка изображений — 2 в ряд.
- Зона нажатия всех полей панели ≥ 44.

## Доступность

- Порядок заголовков: `h2` — название задачи; `overline`-заголовки секций помечаются
  `Semantics(header: true)`, чтобы работала навигация по заголовкам.
- Ключ задачи объявляется по буквам-группам: «DEV дефис 42», а не «DEV-42» слитно.
- Панель полей — группа с меткой «Поля задачи». Каждое поле: «Статус: В работе,
  изменить», «Приоритет 80 из 100, высокий», «Сложность 8 story points»,
  «Исполнитель: Пётр Смирнов, изменить».
- У читателя те же поля объявляются без слова «изменить» — иначе скринридер обещает
  действие, которого нет.
- Вкладки — стандартный таб-паттерн; точка «есть свежие изменения» у вкладки «История»
  дублируется в доступном имени: «История, есть недавние изменения».
- Лента комментариев — `Semantics(label: 'Комментарии, 4')`; каждый комментарий читается
  как «Анна Иванова, 12 февраля в 14:32, комментарий: …».
- Упоминание в тексте объявляется как «упоминание: Анна Иванова», а не как ссылка.
- Поле комментария: подсказка про `Ctrl+Enter` входит в доступное имя, а не только
  в визуальную подпись.
- Оптимистичные изменения и откаты объявляются через `liveRegion`: пользователь,
  не видящий экрана, обязан узнать, что статус вернулся обратно.
- Прокрутка к комментарию по уведомлению переводит на него фокус, а не только
  подсвечивает цветом.
- Контраст: всё содержимое — `textPrimary` / `textSecondary` / `textMuted`
  на `surface`, минимум 5.32:1.

## Реализация во Flutter

| Что | Как | Оценка |
|---|---|---|
| Двухколоночная раскладка | `Row` + `Expanded` + `SizedBox(width: 320)` | стандарт |
| Залипающая панель полей | `CustomScrollView` + `SliverPersistentHeader`, либо отдельный `Scrollable` для колонки | лёгкий кастом |
| Вкладки «Комментарии / История» | `TabBar` + `TabBarView` | стандарт |
| Лента комментариев | `ListView` с динамической высотой (markdown), **виртуализация без `itemExtent`** | стандарт, но следить за производительностью при 100+ |
| Markdown | `flutter_markdown` + свой `MarkdownStyleSheet`; упоминания — свой `MarkdownElementBuilder` | **внешняя зависимость + кастом**, `components.md` 18.4 |
| Подсказка `@` | свой оверлей поверх `TextField` с отслеживанием позиции курсора | **кастом**, самый дорогой элемент экрана |
| Редактирование названия на месте | переключение `Text` ↔ `TextField` с сохранением метрик | лёгкий кастом |
| Перетаскивание файлов из ОС | **встроенного механизма во Flutter Web нет**: внешний пакет или JS-интероп | **отдельная задача**, `components.md` 22 |
| Просмотрщик изображений | `Dialog` + `InteractiveViewer` | стандарт |
| Живое обновление (D-26) | WebSocket + Riverpod | зона фронтенда |
| Определение «пользователь внизу ленты» | `ScrollController.position` | тривиально |

**Предупреждение по объёму.** На этом экране сходятся три самых дорогих элемента
продукта: markdown-рендер с кастомными узлами, подсказка упоминаний и перетаскивание
файлов. Планировать экран одним куском не стоит — это минимум три отдельные задачи
плюс сборка.

## Открытые вопросы

- **Q-D17.** История — вкладка (решено выше). Прошу PM подтвердить: US-90 оставляет
  выбор дизайнеру, но это заметное продуктовое решение, и лучше, чтобы оно было
  проговорено, а не просто принято.
- **Q-D18.** Порядок сортировки: комментарии — старые сверху (US-70, нормативно),
  история — новые сверху (US-90, рекомендация). Порядки противоположны. Я считаю это
  правильным (переписка читается сверху вниз, журнал — с последнего события), но
  каждая лента обязана иметь видимую подпись порядка — она заложена в раскладку.
- **Q-D35.** Комментариев и вложений в контракте ещё нет. Спека на них написана;
  при появлении контракта её надо сверить, а не считать согласованной по умолчанию.
- **Q-D19.** Блоки «Вложения» и «Ссылки» скрываются целиком, когда пусты (US-48).
  Контролы «Прикрепить» и «Добавить ссылку» в этом случае живут в строке действий под

  возникнуть впечатления, что прикрепить файл нельзя.
- **Q-D20.** «Изменена: 2 ч назад» в панели полей — считается ли изменением добавление

  Нужно решение PM, потому что это влияет на API.
