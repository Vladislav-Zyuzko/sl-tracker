# Экран: список задач очереди

Маршрут `/queues/<KEY>` (см. Q-D1 в [README.md](./README.md)).
Внутри оболочки. Истории — US-32, US-40.

## Назначение и главный сценарий

Пользователь просматривает задачи очереди, фильтрует по статусу и открывает нужную.
Это самый нагруженный по данным экран продукта: до 1000 задач в очереди, прокрутка
должна быть гладкой (US-32).

Плотность здесь не стилистическая прихоть, а суть: на экране 1080p помещается
**около 20 строк** — этого достаточно, чтобы окинуть взглядом состояние работы
без прокрутки.

## Компоненты и токены

### Шапка экрана (44)

| Элемент | Токены |
|---|---|
| Название очереди | `h2` `textPrimary` |
| Ключ очереди | `bodySStrong` `textMuted`, отступ `space3`; служит подсказкой, из чего складываются ключи задач |
| «Создать задачу» | кнопка `md` `primary`; **скрыта у читателя** (US-32, US-40) |
| Описание очереди | не в шапке: иконка `info_outline_rounded` рядом с названием, по клику — поповер с markdown-описанием. В шапке оно съело бы строку данных |

### Панель фильтров (44)

| Элемент | Токены |
|---|---|
| Фильтр по статусу | выпадающий список с множественным выбором, кнопка-триггер `md` `secondary` |
| Сортировка | выпадающий список, кнопка-триггер `md` `ghost` |
| Счётчик | `label` `textMuted` справа: «Показано 128» |
| Фон | `surfaceSunken`, нижняя граница 1 px `border` |

**Фильтр по статусу.** Пункты — пять статусов очереди с плашками и чекбоксами,
плюс «Все» сверху. Выбранные статусы отражаются на кнопке-триггере:
«Статус: В работе, Ревью» — при трёх и более «Статус: 3 выбрано».
Выбор **отражается в адресе страницы** (`?status=in_progress,review`), чтобы ссылку
на отфильтрованный список можно было скопировать (US-32).

**Сортировка** — два варианта (US-32):
«По приоритету» (по умолчанию: приоритет ↓, при равенстве номер ↓) и «Сначала новые»
(номер ↓). Тоже отражается в адресе.

### Строка задачи

Компонент целиком описан в [`../components.md`](../components.md), раздел 10.
Здесь — только состав колонок этого экрана:

| Колонка | Ширина | Содержимое |
|---|---|---|
| Чекбокс | 32 | **зарезервирована, но пустая**: массовых операций в MVP нет (US-32). Место оставлено, чтобы добавление в релизе 2 не сдвинуло всю таблицу. **Фронтенду: чекбокс не рисуем** |
| Ключ | 88 | `bodySStrong` `accent`, tabular, не обрезается |
| Название | гибкая | `bodyS` `textPrimary`, одна строка, `ellipsis` |
| Статус | 132 | чип статуса, компактный (20) |
| Исполнитель | 160 | аватар `xs` + имя `bodyS` `textSecondary`, `ellipsis`; нет — «Не назначен» `textMuted` |
| Приоритет | 44 | индикатор приоритета, компактный |
| Сложность | 32 | индикатор сложности; не оценена — `—` `textDisabled` |

Заголовки колонок — `overline` `textMuted` на `surfaceSunken`, высота 32.
Кликом по заголовку сортировка **не меняется**: доступны только два варианта из US-32,
и они живут в явном выпадающем списке. Заголовок, который выглядит кликабельным,
но не сортирует, хуже, чем заголовок, который очевидно статичен.

## Поведение

| Действие | Результат |
|---|---|
| Клик по строке | `/issues/DEV-42` |
| Клик по ключу | то же (ссылка; `Ctrl/Cmd + клик` — новая вкладка) |
| Клик по чипу статуса | меню смены статуса **прямо в списке**; событие не доходит до строки |
| Клик по исполнителю | селектор исполнителя прямо в списке |
| Правый клик | контекстное меню: «Открыть», «Открыть в новой вкладке», «Копировать ключ», «Копировать ссылку», разделитель, «Сменить статус», «Назначить исполнителя» |
| Прокрутка вниз | подгрузка следующей порции (US-32), см. ниже |
| Изменение фильтра | список перезапрашивается, прокрутка сбрасывается наверх, адрес обновляется |

Редактирование статуса и исполнителя прямо из списка — **оптимистичное**
(`components.md` 5 и 6): значение меняется мгновенно, при ошибке откатывается
с подсветкой строки `dangerSurface` и тостом «Не удалось изменить статус DEV-42»
с кнопкой «Повторить». У читателя ни чип, ни исполнитель не кликабельны.

### Подгрузка порциями

- Порция — 50 строк. Запрос следующей уходит, когда до конца списка остаётся 10 строк.
- Внизу списка во время дозагрузки — строка 36 со скелетоном, а не спиннер по центру.
- Ошибка дозагрузки: строка 44 с текстом «Не удалось загрузить ещё» и текстовой кнопкой
  «Повторить». Уже загруженные строки остаются на месте — это ключевое.
- Конец списка не подписывается («Это все задачи»): подпись занимает место
  и ничего не даёт.

### Свежесть данных

Список **не обновляется сам** ([D-26](../../product/decisions.md#d-26) распространяется
на страницу задачи, не на списки; US-45 — вне объёма для списков).
Обновление происходит при открытии экрана и при переходе на него.
Это осознанно: строки, самопроизвольно меняющие порядок под курсором, — источник
ошибочных кликов.

## Состояния

| Состояние | Что видно |
|---|---|
| **Загрузка** | шапка экрана, панель фильтров и **заголовки колонок отрисованы сразу и по-настоящему**. Ниже 12 строк-скелетонов по 36: полоски по ширинам колонок, ширина названия чередуется 40 / 70 / 55 %, чтобы не выглядело сеткой |
| **Пусто: в очереди нет задач** | иконка `inbox_outlined` `icon48`, «В этой очереди пока нет задач», пояснение «Создайте первую — она получит ключ `DEV-1`», кнопка «Создать задачу». У читателя — то же без кнопки и с пояснением «Задачи появятся, когда их создадут участники проекта» |
| **Пусто: фильтр ничего не нашёл** | **другой текст**: «Ничего не найдено», пояснение «Ни одна задача не подходит под выбранные статусы», кнопка «Сбросить фильтры» (`ghost`). Панель фильтров остаётся на месте — иначе пользователь не поймёт, что фильтр применён |
| **Ошибка первой загрузки** | состояние ошибки на весь экран (`components.md` 17.1): «Не удалось загрузить задачи» + «Повторить». Шапка и фильтры остаются |
| **Ошибка дозагрузки** | строка в конце списка, см. выше. Экран не обрушивается |
| **Нет прав: читатель** | кнопки «Создать задачу» нет; чип статуса и исполнитель не кликабельны и показаны как текст; контекстное меню содержит только «Открыть», «Открыть в новой вкладке», «Копировать ключ», «Копировать ссылку» |
| **Нет прав: не участник проекта** | экран «Очередь не найдена» — без названия очереди и проекта (`permissions.md`, п. 5) |
| **Очень много задач (1000+)** | виртуализация `itemExtent: 36` обязательна; счётчик «Показано 128 из 1000+»; прокрутка по позиции, а не по числу строк |
| **Очень длинное название задачи** | одна строка, `ellipsis`, полное — в тултипе через 500 мс |
| **Пустое название** | невозможно: название обязательно (US-42). Если сервер всё же вернул пустое — «Без названия» `textMuted` курсивом, экран не ломается |
| **Очень длинное имя исполнителя** | `ellipsis` в колонке 160, полное — в тултипе |
| **Задача закрыта** | ключ и название `textMuted`; зачёркивания нет (`components.md` 10.2) |
| **Очередь удалена в другой вкладке** | при следующем действии — «Очередь не найдена» + тост `info` |

## Клавиатура

| Клавиша | Действие |
|---|---|
| `↑` `↓` или `k` `j` | перемещение курсора по строкам |
| `Enter` | открыть задачу |
| `Ctrl/Cmd + Enter` | открыть в новой вкладке |
| `s` | меню смены статуса для строки под курсором |
| `a` | селектор исполнителя для строки под курсором |
| `f` | фокус на фильтр по статусу |
| `c` | создать задачу в этой очереди |
| `Home` / `End` | к первой / последней загруженной строке |
| `PageUp` / `PageDown` | на экран вверх / вниз |
| `Esc` | снять курсор со строки, вернуть фокус в панель фильтров |

Курсор клавиатуры (`surfaceHover` + полоса `accent` слева) отличается от наведения
мышью визуально идентичным фоном, но полоса слева есть только у курсора.
При прокрутке курсор удерживается в видимой области (`ensureVisible`, без анимации).

Множественного выбора и хоткея `x` на этом экране **нет**: массовых операций в MVP нет.
Хоткей зарезервирован и не назначается ничему другому.

## Адаптив

### `xl` ≥ 1440
Как описано, ширина контента ограничена 1600.

### `lg` 1024–1439
Базовая раскладка, все семь колонок.

### `md` 768–1023
- Высота строки **40**.
- Скрываются колонки **«Сложность»** и **«Исполнитель»**; вместо исполнителя —
  аватар `xs` без имени, ширина колонки 32.
- Заголовки колонок остаются.
- Панель фильтров: счётчик уходит, остаются фильтр и сортировка.

### `sm` < 768
- Таблица превращается в **список карточек-строк высотой 56**, заголовки колонок скрыты:

```
+-------------------------------------------------+
| DEV-42  Починить экспорт CSV на больших…        |  строка 1: ключ + название
| ▶ В работе      [АИ]              ▓80       8   |  строка 2: статус, исполнитель, П, С
+-------------------------------------------------+
```

- Панель фильтров сворачивается в одну кнопку «Фильтры» с бейджем числа активных;
  по нажатию открывается лист снизу (bottom sheet) с фильтром и сортировкой.
- «Создать задачу» — плавающая кнопка в правом нижнем углу, 44 × 44, `radiusFull`.
- Зона нажатия строки — вся строка, 56 px, что больше требуемых 44.

## Доступность

- Таблица объявляется как список, а не как `table`: во Flutter Web семантика таблицы
  из виртуализированного `ListView` не собирается, и притворяться таблицей — хуже,
  чем честно быть списком.
- Доступное имя строки собирается из всех колонок в фиксированном порядке:
  «DEV-42, Починить экспорт CSV на больших выгрузках, статус: В работе,
  исполнитель: Анна Иванова, приоритет 80 из 100, высокий, сложность 8 story points».
- Заголовки колонок помечены `Semantics(header: true)` и не входят в порядок фокуса.
- Счётчик «Показано 128» — `liveRegion: polite`, объявляется после смены фильтра.
- Статус — цвет + иконка + текст; приоритет — число + шкала + цвет; сложность — число.
  Ни одно значение не передаётся цветом единолично.
- Курсор клавиатуры отражается в семантике как `selected: true`.
- Контраст всех текстов в строке — не ниже 5.32:1 на `surface` и 4.63:1 на выделенной
  строке (`system.md` 3.3).

## Реализация во Flutter

| Что | Как | Оценка |
|---|---|---|
| Список | `ListView.builder(itemExtent: 36)` — **обязательно фиксированный** | стандарт, но см. `components.md` 10.6 |
| Строка | `Row` + `SizedBox` фикс. ширины + один `Expanded` | **кастом, ключевой по производительности** |
| Залипшая шапка таблицы | `CustomScrollView` + `SliverPersistentHeader(pinned: true)` | стандарт |
| Фильтр с множественным выбором | `MenuAnchor` + `CheckboxMenuButton` | стандарт + тема |
| Синхронизация фильтров с URL | `go_router` query-параметры | стандарт |
| Подгрузка порциями | слушатель `ScrollController` + Riverpod-провайдер страницы | стандарт |
| Контекстное меню по правой кнопке | `GestureDetector(onSecondaryTapDown)` + `showMenu` | **кастом**: в вебе надо ещё погасить нативное меню браузера |
| Общий тултип на длинные названия | один оверлей на список, а не `Tooltip` на строку | **кастом**, см. `components.md` 10.6 |

**Профилирование обязательно** до того, как на этом экране начнут строить что-то ещё:
`flutter run --profile`, 2000 строк, непрерывная прокрутка. Это единственный экран,
где производительность — часть приёмки, а не пожелание.

## Открытые вопросы

- **Q-D14.** Колонка чекбокса зарезервирована (32 px), но в MVP пуста. Альтернатива —
  не резервировать и сдвинуть таблицу в релизе 2. Считаю резерв правильным: сдвиг всех
  колонок ломает мышечную память. Подтвердить у PM, что массовые операции планируются.
- **Q-D15.** Фильтр по статусу — единственный в MVP (US-32). Фильтры по исполнителю
  и приоритету — релиз 2. Панель спроектирована так, что третий и четвёртый фильтр
  встают в тот же ряд без перестройки.
- **Q-D16.** Счётчик «Показано 128» при активном фильтре — это число отфильтрованных.
  Нужно ли рядом общее число задач очереди? Предлагаю показывать «Показано 128 из 340»
  только когда фильтр активен. Уточнить у PM.
