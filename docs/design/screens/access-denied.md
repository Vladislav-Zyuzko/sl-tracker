# Экран: доступ к трекеру закрыт

Маршрут `/access-denied?ticket=<тикет>`. Вне оболочки. История — US-05,
решение — [ADR-0006](../../adr/0006-access-list.md).
Общие соглашения — [README.md](./README.md).

## Назначение и главный сценарий

Человек успешно вошёл в Яндекс ID, но его email не в списке доступа и действующего
приглашения у него нет. Экран должен:

1. Понятно сказать, что дело не в поломке и не в его аккаунте, а в отсутствии доступа.
2. Подсказать единственный работающий путь дальше — попросить ссылку-приглашение.
3. **Не раскрыть о трекере ничего.**

Третий пункт — главный. Этот экран видит посторонний человек, возможно, подбирающий
доступ. Всё, что он здесь узнает, — это то, что по адресу что-то есть.

---

## Что экран не показывает — нормативный список

Ни при каких условиях, ни в вёрстке, ни в тексте, ни в ответе API, ни в заголовке вкладки:

- название организации, команды, инстанса;
- имена, email или аватары администраторов и владельца;
- список проектов, их число, названия;
- число пользователей трекера;
- контакты для связи, конкретный email «напишите сюда»;
- подсказку, есть ли такой email в списке (это делает экран оракулом для перебора);
- различие между «вас нет в списке» и «ваше приглашение просрочено» — оба случая
  выглядят одинаково (US-21: по просроченной ссылке человек попадает **сюда**).

Единственное, что показывается персонального, — **email, под которым человек вошёл**.
Это не утечка: он и так его знает. Зато это снимает самый частый реальный случай —
человек вошёл не тем аккаунтом (личным вместо рабочего).

### Откуда берётся email: обмен тикета

Адреса **нет в адресной строке**. Колбэк редиректит на `/access-denied?ticket=<тикет>`,
и экран обменивает тикет на адрес запросом `GET /api/auth/access-denied/{ticket}`
(`AccessDeniedInfoDto`).

Так сделано намеренно, и дизайн обязан это поддержать: email в query-параметре попал бы
в историю браузера, в логи прокси и в реферер — то есть утёк бы ровно там, где его
никто не ждёт. Тикет одноразовый и живёт недолго.

Практическое следствие для экрана: **email появляется не сразу**, и у экрана есть
состояние загрузки и состояние «тикет уже недействителен». Оба описаны ниже.

Заголовок вкладки браузера — «SL Tracker», без уточнений.

## Раскладка

```
                    +----------------------------------+
                    |                                  |
                    |              [🔒]                |  icon48, iconMuted
                    |                                  |  space4
                    |    Доступ к трекеру закрыт        |  title (16/22/600)
                    |                                  |  space2
                    |  Вы вошли как ivan@yandex.ru.    |  body textMuted,
                    |  Этого аккаунта нет среди тех,   |  по центру, макс. 360
                    |  кому открыт доступ.             |
                    |                                  |
                    |  Чтобы попасть внутрь, попросите |
                    |  ссылку-приглашение у того, кто  |
                    |  позвал вас в команду.           |
                    |                                  |
                    |            space6                |
                    |                                  |
                    |  +----------------------------+  |
                    |  |          Выйти             |  |  кнопка md, secondary
```

Фон — `surfaceSunken`. Иконка `lock_outline_rounded`, цвет `iconMuted` —
**не `danger`**: человек ничего не сломал и не нарушил, красный замок здесь обвиняет.

## Компоненты и токены

| Элемент | Компонент / токены |
|---|---|
| Иконка | `icon48`, цвет `iconMuted` |
| Заголовок | `title` `textPrimary` |
| Текст | `body` `textMuted`, `maxWidth` 360, выравнивание по центру |
| Email в тексте | `bodyStrong` `textPrimary` внутри абзаца — единственный акцент |
| «Выйти» | кнопка `md`, вариант `secondary`, ширина блока |
| «Войти другим аккаунтом» | текстовая кнопка `sm`, `ghost` |
| Фон | `surfaceSunken` |

Основной кнопки (`primary`) на экране нет намеренно: главного действия здесь не существует.
Обе кнопки — способы уйти, а не продолжить.

## Поведение

| Действие | Результат |
|---|---|
| «Выйти» | сессии у этого человека нет и не было — cookie не выдавалась. Кнопка просто уводит на `/login`, дополнительно вызывая `POST /api/auth/logout` для очистки возможных остатков. Сессия в Яндексе не трогается (US-03) |
| «Войти другим аккаунтом» | выход + переход на `/login`; далее пользователь сам выбирает аккаунт на стороне Яндекса |
| Обновление страницы (F5) | тикет уже использован → экран без адреса. Содержание и выходы прежние |
| Прямой переход на `/` | редирект на `/login`, оттуда — снова сюда после входа |
| Пришёл по просроченному приглашению | тот же экран, тот же текст, без упоминания приглашения |

**Сессия не создаётся.** Пользователю не выдаётся cookie, в БД он не заводится (US-05).
Экран показывается по результату колбэка; закрыл вкладку — при следующем открытии
увидит экран входа.

## Состояния

| Состояние | Что видно |
|---|---|
| **Обычное** | описанная раскладка, email получен обменом тикета |
| **Загрузка (обмен тикета)** | блок отрисован целиком, на месте адреса — скелетон-полоска 180 × 14. Заголовок, иконка и кнопки видны сразу: главное сообщение экрана не зависит от тикета и ждать его не должно |
| **Тикет недействителен или отсутствует** (`404`, повторное открытие, F5) | тот же экран **без адреса**: «Этот аккаунт не входит в число тех, кому открыт доступ». Ошибку не показываем и повторить не предлагаем — тикет одноразовый, и это нормальный исход, а не сбой |
| **Пусто** | невозможно: данных на экране нет |
| **Пусто после фильтра** | невозможно |
| **Ошибка сети при обмене тикета** | ведём себя как при недействительном тикете: экран без адреса. Отдельного «Повторить» нет — адрес здесь подсказка, а не содержание |
| **Ошибка выхода** | если «Выйти» не сработал (сеть) — тост-ошибка «Не удалось выйти» + «Повторить». Экран остаётся; пользователь не заперт: «Войти другим аккаунтом» работает независимо |
| **Нет прав** | это и есть экран «нет прав». Более узкого состояния не бывает |
| **Много данных** | невозможно |
| **Очень длинный текст** | переменная часть одна — email. Обрезается посередине с `ellipsis` на 320 px, полностью виден в тултипе. Даже 320-символьный адрес (предел контракта) не ломает раскладку |
| **Email не получен от провайдера** | текст без email, как при недействительном тикете |

## Клавиатура

| Клавиша | Действие |
|---|---|
| `Tab` | «Выйти» → «Войти другим аккаунтом» |
| `Enter` / `Space` | активация |

Фокус при открытии — на заголовке, чтобы скринридер объявил суть экрана.
Автофокуса на «Выйти» нет: случайный `Enter` не должен выкидывать человека до того,
как он прочитал, что произошло.

## Адаптив

- **`xl`, `lg`, `md`:** блок 400 по центру.
- **`sm` < 768:** ширина минус `space4` с каждой стороны, максимум 400. Кнопки на всю
  ширину. Отступ сверху `space8` вместо вертикального центрирования.
- **Высота < 480:** иконка уменьшается до `icon24`, отступы `space4`.

## Доступность

- `Semantics(header: true)` на заголовке; фокус при входе на экран — туда же.
- Иконка замка декоративна: `excludeFromSemantics: true`. Смысл несёт текст.
- Весь блок объявляется как одна группа, чтобы скринридер прочитал ситуацию целиком,
  а не по фразе.
- Появление адреса после обмена тикета объявляется через `liveRegion: polite`:
  иначе для незрячего пользователя экран молча меняется.
- Контраст: `textMuted` на `surfaceSunken` — 4.95:1; `textPrimary` — 10.75:1;
  граница `secondary`-кнопки `borderStrong` — 3.26:1 к фону.
- Зона нажатия кнопок ≥ 44 на тач.
- Текст не полагается на цвет: единственный цветной элемент — иконка, и она декоративна.

## Реализация во Flutter

Полностью стандартно: `Center` + `Column` + `ConstrainedBox`. Кастома нет.
Две неочевидности:

1. экран не должен быть частью `ShellRoute`, иначе вокруг него отрисуется сайдбар
   с чужими данными;
2. запрос `GET /api/auth/access-denied/{ticket}` идёт **без сессии** — клиент API
   не должен на `401`/`404` здесь запускать общий сценарий «сессия истекла».

## Открытые вопросы

- **Q-D7.** Стоит ли давать действие «Попросить доступ» (уведомление владельцу инстанса)?
  В US-05 это явно вне объёма, и я согласен: такая кнопка превращает экран в форму
  для посторонних. Фиксирую как сознательно не сделанное, а не забытое.
- **Q-D8.** Текст «попросите ссылку-приглашение у того, кто позвал вас в команду» —
  формулировка не называет никого конкретного и ничего не раскрывает. Прошу PM
  подтвердить её дословно: это единственная фраза продукта, которую читает посторонний.
