# Экран: вход

Маршрут `/login`. Вне оболочки: ни шапки, ни сайдбара.
Общие соглашения — [README.md](./README.md). Истории — US-01, US-02, US-03.

## Назначение и главный сценарий

Пользователь нажимает одну кнопку, уходит в Яндекс ID, возвращается вошедшим — и попадает
**туда, куда шёл**, а не на главный экран (US-01).

Это единственный экран продукта, который видит неаутентифицированный человек. Поэтому он
не содержит ничего, кроме входа: ни описания продукта, ни ссылок, ни формы регистрации.

## Раскладка (все брейкпоинты — одна колонка по центру)

```
                    +--------------------------------+
                    |                                |
                    |          SL Tracker            |  h1 (24/32/700)
                    |                                |  space2
                    |    Трекер задач для команды     |  body textMuted
                    |                                |
                    |            space8              |
                    |                                |
                    |  +--------------------------+  |
                    |  |  [Я]  Войти через Яндекс |  |  кнопка lg (40), primary
                    |  +--------------------------+  |
                    |                                |
                    |            space4              |
                    |                                |
                    |   Вход только для участников   |  label textMuted,
                    |   команды. Нужен доступ —      |  по центру, макс. 320
                    |   попросите ссылку-приглашение |
                    |   у администратора проекта.    |
                    +--------------------------------+
                          ширина блока 360
```

Блок центрирован по вертикали и горизонтали. Фон страницы — `surfaceSunken`,
карточка блока — **без карточки**: просто контент на фоне. Рамка вокруг одной кнопки
выглядит как форма, которой здесь нет.

## Компоненты и токены

| Элемент | Компонент / токены |
|---|---|
| Заголовок | `h1` `textPrimary` |
| Подзаголовок | `body` `textMuted` |
| Кнопка входа | кнопка `lg` (высота 40), вариант `primary`, ширина блока 100 % (360 max) |
| Логотип Яндекса в кнопке | 20 × 20, слева, отступ `space2` до текста |
| Пояснение снизу | `label` `textMuted`, выравнивание по центру, `maxWidth` 320 |
| Сообщение об ошибке | баннер ошибки (`components.md` 17.2), ширина блока, отступ `space4` над кнопкой |
| Фон | `surfaceSunken` |

**Про кнопку «Войти через Яндекс».** У Яндекса есть требования к оформлению кнопки входа
(логотип, наименование, отступы). Я их по памяти не воспроизвожу — **перед реализацией
свериться с актуальным брендбуком Яндекс ID**. Если требования конфликтуют с нашими
токенами (например, требуют свой цвет заливки), приоритет у требований Яндекса,
и это исключение фиксируется в `system.md` как единственный литеральный цвет в продукте.
Это открытый вопрос Q-D5, а не забытая деталь.

## Поведение

| Шаг | Что происходит |
|---|---|
| 1. Нажатие «Войти через Яндекс» | кнопка переходит в состояние загрузки (спиннер, ширина зафиксирована), браузер уходит на `GET /api/auth/yandex/start` — полный переход страницы, не всплывающее окно |
| 2. Возврат из Яндекса | экран показывает состояние «Завершаем вход» (см. ниже), фронт зовёт `GET /api/me` |
| 3. Успех | переход по сохранённому адресу назначения либо на `/projects` |
| 3′. Нет в списке доступа | переход на `/access-denied` ([access-denied.md](./access-denied.md)) |
| 3″. Ошибка | остаёмся на `/login`, показываем баннер (таблица ошибок ниже) |

**Возврат к цели.** Пользователь, открывший `/issues/DEV-42` без сессии, после входа
попадает **на эту задачу** (US-01). Адрес назначения сохраняется до ухода на Яндекс
и подхватывается после возврата. То же для `/invite/<token>` (US-21): после входа
обработка приглашения продолжается автоматически.

**Всплывающее окно не используется.** Полный редирект переживает блокировщики попапов
и работает на мобильном браузере; поток OAuth и так серверный (`CLAUDE.md`, решение 2).

## Состояния

| Состояние | Что видно |
|---|---|
| **Обычное** | заголовок, кнопка, пояснение |
| **Загрузка (переход на Яндекс)** | кнопка в состоянии загрузки, текст скрыт, спиннер 14 px `textOnAccent`. Кнопка не отключается визуально, повторные нажатия игнорируются |
| **Загрузка (возврат, проверяем сессию)** | вместо кнопки — строка: спиннер 16 px `accent` + «Завершаем вход…» `bodyS` `textMuted`. Заголовок остаётся. **Скелетона здесь нет**: показывать скелет несуществующего контента нечестно |
| **Пусто** | невозможно: на экране нет данных, которые могли бы отсутствовать |
| **Пусто после фильтра** | невозможно: фильтров нет |
| **Ошибка** | баннер над кнопкой, кнопка активна и доступна для повтора. Тексты — таблица ниже |
| **Нет прав** | не на этом экране: «нет доступа» — отдельный экран 3 |
| **Много данных / длинный текст** | невозможно: содержимое статично. Единственный переменный текст — сообщение об ошибке, оно ограничено 3 строками и переносится по словам |
| **Уже вошёл, открыл `/login`** | немедленный редирект на `/projects`, экран не мигает |
| **Сессия истекла на другом экране** | пришли сюда с баннером `info`: «Сессия истекла. Войдите снова» (US-02) |
| **Вернулся кнопкой «Назад» после выхода** | показывается экран входа, а **не** кэш предыдущей страницы (US-03) |

### Ошибки OAuth — тексты

Экран не пересказывает пользователю технические коды. Код показывается только
в раскрывающемся блоке «Подробности» для баг-репорта.

| Причина | Заголовок баннера | Пояснение | Тип |
|---|---|---|---|
| Пользователь отказал в доступе на стороне Яндекса (`access_denied`) | Вход отменён | «Вы не подтвердили доступ. Нажмите «Войти через Яндекс» ещё раз» | `info` |
| **`unauthorized_client`** — приложение ещё не прошло модерацию в Яндексе | Вход временно недоступен | «Приложение ещё проверяется на стороне Яндекса. Попробуйте позже или напишите администратору» | `warning` |
| `invalid_state` / истёк `state` | Не удалось завершить вход | «Страница входа устарела. Начните заново» | `danger` |
| Сеть, таймаут, 5xx на нашей стороне | Не удалось войти | «Проверьте соединение и попробуйте ещё раз» | `danger` |
| Неизвестная ошибка | Не удалось войти | «Что-то пошло не так. Попробуйте ещё раз» | `danger` |

Про `unauthorized_client` отдельно: это **штатное состояние на старте проекта**, пока
OAuth-приложение проходит модерацию (`CLAUDE.md`, решение 7). Пользователь не должен
видеть в этот момент «Ошибка 401» — он должен понять, что дело не в нём. Поэтому это
`warning`, а не `danger`, и текст говорит про проверку на стороне Яндекса.

**Важно:** экран входа **не** сообщает, есть ли данный email в списке доступа —
это выясняется только после успешной аутентификации и приводит на экран 3.
Иначе экран входа превращается в способ проверять, кто работает в компании.

## Клавиатура

| Клавиша | Действие |
|---|---|
| `Tab` | на кнопку входа (первый и единственный интерактивный элемент) |
| `Enter` / `Space` | вход |
| `Tab` дальше | на «Подробности» в баннере ошибки, если баннер есть |

Фокус при открытии экрана ставится на заголовок (для объявления скринридером),
но **не** на кнопку: автофокус на кнопке, ведущей на внешний сайт, — плохая идея.

## Адаптив

- **`xl`, `lg`, `md`:** блок 360 по центру экрана.
- **`sm` < 768:** блок на всю ширину минус `space4` с каждой стороны, но не шире 360.
  Кнопка на всю ширину блока. Вертикально — не по центру, а с отступом `space8` сверху:
  на низком экране с открытой клавиатурой центрирование выталкивает кнопку за экран.
- **Высота < 480:** блок прижимается к верху, отступы `space6` вместо `space8`.

## Доступность

- Экран — один `main` с `Semantics(header: true)` на заголовке.
- Кнопка входа: доступное имя «Войти через Яндекс». Логотип внутри кнопки декоративен
  (`excludeFromSemantics: true`).
- Баннер ошибки — `liveRegion: true`, объявляется сразу при появлении.
  Для ошибок — настойчиво (`assertive`), для «Вход отменён» — спокойно (`polite`).
- Состояние «Завершаем вход…» — тоже `liveRegion`, иначе для незрячего пользователя
  экран просто молчит.
- Контраст: `textMuted` на `surfaceSunken` — 4.95:1, `textOnAccent` на `accent` — 4.86:1.
- Зона нажатия кнопки 40 px по высоте, на тач — 44 через `MaterialTapTargetSize.padded`.

## Реализация во Flutter

| Что | Как | Оценка |
|---|---|---|
| Разметка | `Center` + `Column` + `ConstrainedBox(maxWidth: 360)` | стандарт |
| Переход на OAuth | полная навигация браузера на `/api/auth/yandex/start` (`web.window.location.href`) | **веб-специфично**: обычный `go_router` тут не подходит, нужен выход за пределы приложения |
| Сохранение адреса назначения | query-параметр `?next=` либо `sessionStorage` до редиректа | решает фронтенд, дизайну безразлично |
| Логотип Яндекса | SVG-ассет | требует получения актуального ассета, см. Q-D5 |
