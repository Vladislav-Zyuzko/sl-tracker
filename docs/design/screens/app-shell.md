# Экран: оболочка приложения

Каркас, внутри которого живут все экраны после входа. Сам по себе не является страницей.
Общие соглашения — [README.md](./README.md).

## Назначение и главный сценарий

Пользователь всегда видит, что он делает прямо сейчас (список активных задач), и может
за один шаг попасть в любую свою задачу, в проекты и в уведомления — с любого экрана,
не возвращаясь на главный (US-80).

Сайдбар отвечает ровно на один вопрос: **«что делаю лично я»** ([D-19](../../product/decisions.md#d-19)).
Он не показывает всё, что происходит в трекере, и не должен пытаться.

## Компоненты и токены

### Шапка (высота 48)

| Зона | Содержимое | Токены |
|---|---|---|
| Слева | логотип-текст «SL Tracker», `bodySStrong` `textPrimary`, кликабелен → `/projects` | padding слева `space4` |
| Центр | кнопка «Создать задачу», `primary` `md`, иконка `add_rounded` `icon16` | — |
| Справа | колокольчик + меню профиля | зазор `space3`, padding справа `space4` |
| Фон | `surface`, нижняя граница 1 px `border` | без тени, пока страница не прокручена |

- **Колокольчик** — `IconButton` `md`, иконка `notifications_none_rounded` `icon20`,
  цвет `iconDefault`. Счётчик непрочитанных — счётчик-пилюля в акцентном варианте
  (фон `accent`, текст `textOnAccent`), смещён вправо-вверх на 4 px. Точное число до 99,
  далее «99+» (US-103). При нуле пилюля не рисуется, иконка остаётся.
- **Меню профиля** — аватар `sm` (24) + имя `bodyS` `textPrimary` + шеврон `icon16`.
  На `md` и `sm` имя скрывается, остаётся только аватар.
  Пункты меню: «Профиль», «Доступ к трекеру» (условно, см. ниже), разделитель, «Выйти».
- **«Доступ к трекеру»** показывается только тем, у кого есть право вести список доступа
  (см. [access-list.md](./access-list.md), раздел «Как экран подан в навигации»).
  Обычный участник этого пункта не видит и о существовании экрана не узнаёт.

### Сайдбар (ширина 240 / свёрнутый 48)

Фон `surfaceSunken`, правая граница 1 px `border`, вертикальный padding `space2`.

| Блок | Компонент | Высота |
|---|---|---|
| Кнопка сворачивания | иконочная кнопка `sm`, иконки `chevron_left/right_rounded` | 24 |
| «Мои проекты» | элемент сайдбара (`components.md` 11), иконка `folder_outlined` | 32 |
| Поиск | поле ввода `md` с иконкой `search_rounded`, ширина 240 − 2·`space2` | 32 |
| Заголовок списка | `overline` `textMuted` «МОИ АКТИВНЫЕ ЗАДАЧИ» + счётчик справа `label` `textMuted` | 24 |
| Строка задачи | см. ниже | **36**, фиксированный `itemExtent` |

### Строка активной задачи в сайдбаре

```
+---------------------------------------+
|▓80  DEV-42  Починить экспорт CSV на…  |  36
+---------------------------------------+
 ^     ^      ^
 |     |      название, bodyS textPrimary, ellipsis, одна строка
 |     ключ, bodySStrong accent, tabular, не обрезается никогда
 индикатор приоритета, компактный (34×20 → здесь сжат до 26: шкала + число)
```

- Слева индикатор приоритета, затем ключ, затем название. Порядок задан US-81:
  ключ виден всегда, название обрезается первым.
- Принадлежность к проекту и очереди читается из ключа (`DEV-42`) — отдельной строки
  с названием проекта нет, она удвоила бы высоту и убила плотность.
  Полное «Проект → Очередь → Название» показывается в тултипе.
- Сортировка: по убыванию приоритета, при равенстве — сначала недавно изменённые (US-81).
- Текущая открытая задача — состояние «выбрана»: фон `surfaceSelected`,
  слева `borderSelectionBar`.

## Поведение

| Действие | Результат |
|---|---|
| Клик по строке | открыть задачу в области содержимого; сайдбар остаётся |
| `Ctrl/Cmd + клик`, средний клик | открыть в новой вкладке |
| Клик по «Мои проекты» | `/projects` |
| Сворачивание сайдбара | ширина 240 → 48 за `motionSlow` (320 мс); **состояние сохраняется между визитами** (US-80) в локальном хранилище |
| Ввод в поиск | фильтрация списка ниже, дебаунс 250 мс (US-82 требует ≤ 300 мс) |
| Изменение состава активных задач | список обновляется в течение 5 с без перезагрузки (US-81): назначил на себя — задача появилась; закрыл — исчезла |
| Задача исчезает из списка | строка сворачивается по высоте за `motionBase`, соседние сдвигаются. Если исчезающая строка — текущая открытая, она **не исчезает**, а остаётся с пометкой «завершена» до перехода на другой экран: выдёргивать из-под пользователя то, что он читает, нельзя |

### Поиск: главный риск экрана

Поиск ищет **только по моим активным задачам** ([D-20](../../product/decisions.md#d-20)) —
ни по чужим, ни по закрытым, ни по описаниям. Пользователь этого не ожидает и решит,
что поиск сломан. Три меры против этого, все обязательны:

1. **Плейсхолдер называет область поиска:** «Поиск по моим активным задачам».
   На `md`/`sm`, где поле уже, — «Поиск по моим задачам». Обрезать до «Поиск» **нельзя**:
   именно обрезанный плейсхолдер и создаёт ощущение поломки.
2. **Пустой результат объясняет границы:** «Ничего не найдено среди ваших активных задач»
   и второй строкой `label` `textMuted` — «Поиск работает только по задачам, где вы
   исполнитель и которые не закрыты».
3. **Подпись под полем при непустом запросе:** `label` `textMuted`, «Ищем только среди
   ваших активных задач». Появляется, когда в поле есть текст, и не занимает места,
   когда поле пустое.

Глобального поиска в MVP нет, и **имитировать его нельзя**: никаких «показать все
результаты» — этой страницы не существует.

## Состояния

| Состояние | Оболочка |
|---|---|
| **Загрузка** | шапка и сайдбар отрисованы сразу, реальные. В сайдбаре 8 строк-скелетонов по 36; счётчик у заголовка — скелетон-точка 20 × 12; колокольчик без пилюли. Область содержимого — скелетон своего экрана |
| **Пусто: нет активных задач** | в области списка: иконка `check_circle_outline_rounded` `icon24` `iconMuted`, «Нет активных задач» `bodyS` `textPrimary`, ниже `label` `textMuted`: «Сюда попадают задачи, где вы исполнитель и которые ещё не закрыты». Кнопки нет: задачу назначают не отсюда |
| **Пусто: поиск ничего не нашёл** | см. выше, п. 2. Плюс текстовая кнопка «Очистить поиск» |
| **Ошибка загрузки списка** | в области списка `label` `textMuted` «Не удалось загрузить задачи» + текстовая кнопка «Повторить». Шапка, поиск и остальная оболочка работают: сбой одного блока не обрушивает приложение |
| **Нет прав** | у оболочки нет состояния «нет прав»: пользователь либо внутри (прошёл список доступа), либо видит экран 2 или 3. Пункт «Доступ к трекеру» в меню профиля скрывается — это единственное различие |
| **Очень много задач (200+)** | список виртуализирован (`itemExtent: 36`), счётчик показывает точное число до 999, далее «999+». Прокрутка сайдбара независима от прокрутки контента |
| **Очень длинный текст** | название задачи — `ellipsis` + тултип с полным путём «Проект → Очередь → Название». Имя пользователя в шапке — `ellipsis` на 160 px. Логотип не сжимается |
| **Сессия истекла** | любое действие → модалка «Сессия истекла. Войдите снова» с кнопкой «Войти». Несохранённый текст (комментарий, описание) **сохраняется в черновик локально** и восстанавливается после входа — US-02 требует не терять данные молча |
| **Доступ отозван** (запись удалена из списка доступа, сессия погашена, [ADR-0006](../../adr/0006-access-list.md)) | то же, что «сессия истекла», но после нажатия «Войти» пользователь попадает на экран 3 «Доступ к трекеру закрыт». Оболочка не пытается объяснить причину сама — она её не знает |
| **Нет соединения** | полоса офлайна под шапкой (`components.md` 17.4). Сайдбар показывает последние загруженные данные |

## Адаптив

### `xl` ≥ 1440
Сайдбар 240. Область содержимого центрируется, максимальная ширина 1600 px,
по краям `surfaceSunken`.

### `lg` 1024–1439
Базовая раскладка. Сайдбар 240, разворачивается и сворачивается пользователем.

### `md` 768–1023
- Сайдбар **принудительно свёрнут** до 48: иконки «Мои проекты», «Поиск», «Активные задачи».
- Клик по иконке поиска или списка раскрывает сайдбар поверх контента (оверлей 240 px,
  `shadowMd`), клик вне — закрывает.
- В шапке имя пользователя скрыто, остаётся аватар.

### `sm` < 768
- Сайдбара на экране нет. В шапке слева — кнопка-бургер `menu_rounded`.
- Сайдбар — выдвижная панель (`Drawer`) шириной 280 поверх контента, с затемнением `scrim`.
  **Закрывается автоматически после перехода по ссылке** (US-80).
- Шапка 52. Кнопка «Создать задачу» сжимается до иконочной (только `+`), подпись уходит.
- Строка активной задачи — 44 (зона нажатия), название на одной строке с `ellipsis`.
- Колокольчик и аватар остаются в шапке всегда: это две самые частые точки входа.

## Доступность

- Структура: `header` (шапка) → `navigation` (сайдбар) → `main` (содержимое).
  Во Flutter — `Semantics(container: true, ...)` с соответствующими флагами и метками.
- Первым в порядке фокуса — скрытая ссылка «Перейти к содержимому», видимая только
  при фокусе (иначе клавиатурный пользователь каждый раз проходит весь сайдбар).
- Список активных задач — `Semantics(label: 'Мои активные задачи, 14')`; каждая строка
  читается как «DEV-42, Починить экспорт CSV, приоритет 80 из 100, высокий».
- Колокольчик: доступное имя «Уведомления, 12 непрочитанных». При нуле — «Уведомления».
  Счётчик — не только цвет: он и число, и часть доступного имени.
- Кнопка сворачивания сайдбара: `tooltip` и доступное имя меняются
  («Свернуть панель» / «Развернуть панель»), состояние объявляется через `expanded`.
- Выдвижной сайдбар на `sm` — focus trap, `Esc` закрывает, фокус возвращается на бургер.
- Контраст: всё в шапке и сайдбаре — `textPrimary`/`textSecondary`/`textMuted`
  на `surface`/`surfaceSunken`, минимум 4.95:1 (`system.md` 3.3).

## Реализация во Flutter

| Что | Как | Оценка |

## Открытые вопросы

  Нужно ли запоминать последнюю выбранную очередь и подставлять её по умолчанию?
