# SL Tracker — каталог компонентов

Версия 1.2. Владелец файла: `sl-designer`.
Опирается на `docs/design/system.md`; здесь **не встречается ни одного hex** — только
имена ролей и токенов. Если компоненту понадобился цвет, которого нет в системе,
сначала добавляется роль в `system.md`, потом используется здесь.

Все размеры даны для десктопа (≥ 1024). Отличия для планшета и телефона указаны
в разделе «Адаптив» каждого компонента либо в таблице плотности `system.md` 10.2.

## 0. Сводка: что стандартно во Flutter, что кастом

| Компонент | Основа | Оценка |
|---|---|---|
| Кнопка (все варианты) | `FilledButton` / `OutlinedButton` / `TextButton` | стандарт + тема |
| Иконочная кнопка | `IconButton` | стандарт + тема |
| Поле ввода, многострочное поле | `TextField` + `InputDecorationTheme` | стандарт + тема |
| Поиск | `TextField` + `Autocomplete` | стандарт + тема |
| Выпадающий список статуса | `MenuAnchor` | стандарт + тема |
| Селектор пользователя | `MenuAnchor` + `TextField` + свой список | **лёгкий кастом** |
| Чип статуса | `Container` + `Row` | кастом, тривиальный |
| Индикатор приоритета | `CustomPaint` или `Stack` c `FractionallySizedBox` | кастом, тривиальный |
| Индикатор сложности | `Container` + `Text` | кастом, тривиальный |
| Аватар, группа аватаров | `CircleAvatar`; группа — `Stack` | стандарт + лёгкий кастом |
| Строка списка задач | `Row` внутри `InkWell` в `ListView.builder(itemExtent:)` | **кастом, ключевой** |
| Элемент сайдбара | `InkWell` + `Row` | кастом, тривиальный |
| Вкладки | `TabBar` | стандарт + тема |
| Модальное окно | `showDialog` + `Dialog` | стандарт + тема |
| Тост | `Overlay` + свой контроллер | **кастом**, `SnackBar` не подходит |
| Скелетон | `AnimatedBuilder` + `ShaderMask` | кастом; в Sweet Limit есть готовый `SLShimmeringEffect` |
| Пустое состояние, состояние ошибки | `Column` | кастом, тривиальный |
| Markdown-контент | пакет `flutter_markdown` со своим `MarkdownStyleSheet` | **внешняя зависимость, см. 18** |
| Поле комментария | `TextField` + `Actions`/`Shortcuts` | стандарт + лёгкий кастом |
| Элемент комментария | `Row` + `Column` | кастом, тривиальный |
| Элемент истории изменений | `Wrap` из `TextSpan` | кастом, тривиальный |
| Плитка вложения | `Image.network` в `AspectRatio` / `Row` | кастом, тривиальный |
| Кольцо фокуса | `FocusableActionDetector` + своя отрисовка | **кастом, нужен один раз для всех** |
| Тултип | `Tooltip` | стандарт + тема |
| Чекбокс | `Checkbox` | стандарт + тема |

Три места, где придётся потратить время заметно больше ожидаемого, и об этом стоит
знать заранее:

1. **Строка списка задач** — от неё зависит производительность всего продукта.
   Фиксированный `itemExtent`, никаких `IntrinsicHeight`, никаких `Expanded` с
   пересчётом текста. Подробности в 10.
2. **Тост** — `SnackBar` в Material прибит к низу экрана и к одному экземпляру за раз.
   Нам нужен стек уведомлений справа сверху с очередью. Это свой `OverlayEntry`.
3. **Markdown** — рендер, редактор и вставка изображений. Оценивать отдельно, см. 18.

## 1. Общие правила состояний

Каждый интерактивный компонент обязан иметь семь состояний. Если для компонента
какое-то состояние не имеет смысла, это пишется явно, а не опускается молча.

| Состояние | Как выглядит по умолчанию |
|---|---|
| Обычное | базовые токены компонента |
| Наведение (hover) | фон `surfaceHover` либо `overlayHover` поверх заливки; 120 мс |
| Фокус (клавиатурный) | **в `borderFocus` ровно один контур.** Если своя рамка не меняет цвет (или её нет) — кольцо `borderFocusRing` снаружи с зазором 1 px. Если своя рамка окрашивается в `borderFocus` — `borderFocusThick`, то есть она утолщается до 2 px, а кольцо не добавляется (`system.md` 10.6.1). Фон не меняется ни в том, ни в другом случае |
| Нажатое (pressed) | фон `surfacePressed` либо `overlayOnAccentPressed`; 0 мс, мгновенно |
| Отключённое (disabled) | фон `surfaceDisabled`, текст и иконка `textDisabled`, курсор `basic`, из порядка табуляции исключён |
| Загрузка | контент остаётся на месте, поверх — индикатор; размеры не меняются |
| Ошибка | граница `borderDanger`, текст ошибки под элементом цветом `danger` |

Правила, действующие везде:

- **Фокус виден всегда.** Индикатор не убирается «потому что мышью и так понятно».
- **Два синих контура — дефект.** Если своя рамка элемента окрашивается в `borderFocus`,
  кольцо к ней не добавляется: получится «рамка внутри рамки». Какой из двух способов
  применять — определяется поведением рамки, а не вкусом (`system.md` 10.6.1).
  Показывать только при клавиатурной навигации допустимо (`FocusableActionDetector`
  различает источник), но при навигации клавишами — обязательно.
- **Наведение и фокус — разные вещи** и оформляются по-разному. Не подменять одно другим.
- **Курсор.** Кликабельное — `SystemMouseCursors.click`; текстовое поле — `text`;
  отключённое — `basic`; перетаскиваемое — `grab` и `grabbing`.
- **Тултип** появляется через 500 мс после наведения, исчезает мгновенно.
  Обязателен для любой иконочной кнопки.
- **Zero-width состояние.** Любой компонент, показывающий текст пользователя, обязан
  корректно вести себя при пустой строке, при 300 символах без пробелов и при тексте
  на языке справа налево (последнее — не ломаться, а не поддерживать полноценно).

## 2. Кнопки

### 2.1. Варианты

| Вариант | Заливка | Текст | Граница | Где применяется |
|---|---|---|---|---|
| Основная (`primary`) | `accent` | `textOnAccent` | нет | одно главное действие на экране или в модалке |
| Вторичная (`secondary`) | `surface` | `textPrimary` | `borderControl` | частые второстепенные действия, «Отмена» в модалке |
| Текстовая (`ghost`) | прозрачная | `accent` | нет | третьестепенное: «Сбросить фильтры», «Показать ещё» |
| Опасная (`danger`) | `danger` | `textOnAccent` | нет | удаление, необратимое действие |
| Опасная контурная (`dangerGhost`) | прозрачная | `danger` | `1 px danger` | удаление в плотном контексте: меню, строка списка |

**Правило одного действия.** На экране одна основная кнопка. Если кажется, что нужны
две — одна из них вторичная. В модалке основная кнопка справа, вторичная слева от неё.

### 2.2. Размеры

| Размер | Высота | Padding по горизонтали | Текст | Иконка | Зазор иконка—текст |
|---|---|---|---|---|---|
| `sm` | 24 | `space2` (8) | `bodyS` | `icon16` | `space1` (4) |
| `md` (по умолчанию) | 32 | `space3` (12) | `bodySStrong` | `icon16` | `space1` (4) |
| `lg` | 40 | `space4` (16) | `bodySStrong` | `icon20` | `space2` (8) |

Радиус — `radiusSm`. Минимальная ширина кнопки — 64 px, чтобы «ОК» не превращался
в квадратик. Кнопка только с иконкой — квадратная: 24 / 32 / 40.

### 2.3. Состояния

| Состояние | primary | secondary | ghost | danger |
|---|---|---|---|---|
| Обычное | фон `accent` | фон `surface`, граница `borderControl` | прозрачный | фон `danger` |
| Наведение | фон `accentHover` | фон `surfaceHover` | фон `surfaceHover` | фон `dangerHover` |
| Фокус | + `borderFocusRing` | + `borderFocusRing`, рамка остаётся `borderControl` | + `borderFocusRing` | + `borderFocusRing` |
| Нажатое | фон `accentPressed` | фон `surfacePressed` | фон `surfacePressed` | фон `danger` + `overlayOnAccentPressed` |
| Отключённое | фон `surfaceDisabled`, текст `textDisabled` | фон `surfaceDisabled`, граница `border`, текст `textDisabled` | текст `textDisabled` | фон `surfaceDisabled`, текст `textDisabled` |
| Загрузка | текст скрывается, на его месте спиннер 14 px цветом `textOnAccent`; **ширина кнопки фиксируется** по исходному тексту, кнопка не «схлопывается» | так же, спиннер `textSecondary` | так же | так же |
| Ошибка | у кнопки нет состояния ошибки: ошибка живёт в тосте либо в баннере рядом | — | — | — |

Во время загрузки кнопка `disabled` для нажатий, но **не** получает вид `disabled`:
она остаётся цветной, чтобы не мигать. Повторное нажатие игнорируется.

Кнопка опасного действия **никогда не выполняет действие сразу**, если оно необратимо:
сначала модалка подтверждения (см. 13.4).

### 2.4. Клавиатура и доступность

- `Tab` — вход, `Enter` и `Space` — нажатие.
- У кнопки-иконки обязателен `tooltip`; он же становится доступным именем.
- Состояние загрузки объявляется как `Semantics(label: '<текст>, выполняется')`.
- `Semantics(button: true)` даёт `FilledButton` автоматически, вручную не дублировать.

### 2.5. Flutter

Стандартные `FilledButton`, `OutlinedButton`, `TextButton`, `IconButton`
с переопределённым `ButtonStyle`. Нужно явно задать:
`minimumSize`, `fixedSize` по высоте, `padding`, `visualDensity: VisualDensity.compact`,
`tapTargetSize: MaterialTapTargetSize.shrinkWrap` на десктопе и `padded` на тач-платформах,
`splashFactory: NoSplash.splashFactory`, `overlayColor` через `WidgetStateProperty`.
Кастом не требуется.

## 3. Поле ввода

### 3.1. Анатомия

```
Подпись                                   ← label, textSecondary, отступ снизу space1
+------------------------------------+
| Значение или плейсхолдер        [x] |   ← высота 32 (md), padding 0 space2
+------------------------------------+
Подсказка либо текст ошибки               ← label, textMuted / danger, отступ сверху space1
```

- Высота `md` 32, `lg` 40. Радиус `radiusSm`. Граница `borderControl`.
- Текст значения — `bodyS`, цвет `textPrimary`.
- Плейсхолдер — `bodyS`, цвет `textMuted` (проходит AA, в отличие от типичного серого).
- Иконка слева, если она осмысленна (поиск, календарь) — `icon16`, `iconMuted`,
  отступ `space2` с обеих сторон.
- Кнопка очистки справа появляется только когда поле непустое: `icon16`, `iconDefault`,
  зона нажатия 24 × 24 на десктопе и 44 × 44 на тач.

### 3.2. Состояния

| Состояние | Оформление |
|---|---|
| Обычное | фон `surface`, граница `borderControl` |
| Наведение | граница `textMuted` (на один шаг темнее), фон не меняется |
| Фокус | граница `borderFocusThick`: **та же рамка, утолщённая до 2 px**, цвет `borderFocus`. Кольца снаружи нет, зазора нет, габариты не меняются. Контраст на всех подложках, где встречается поле, — от 4.06:1 (`system.md` 10.6.2) |
| Заполненное | как обычное, текст `textPrimary` |
| Отключённое | фон `surfaceDisabled`, граница `border`, текст `textDisabled` |
| Только для чтения (нет прав) | фон `surface`, границы **нет**, текст `textPrimary`, курсор `basic`. Отличается от disabled: данные читаемы и выделяемы мышью |
| Загрузка (значение подгружается) | скелетон-полоска внутри поля, высота 12, ширина 60 %, цвет `skeletonBase` |
| Ошибка | граница `borderDanger` 1 px, под полем текст ошибки `label` цветом `danger` с иконкой `error_outline_rounded` 12 px |
| Ошибка + фокус | граница **`borderDanger` 2 px** — цвет остаётся «ошибочным», фокус передаётся утолщением. Синей рамки у поля с ошибкой не бывает: ошибка важнее, чем расположение каретки |

### 3.3. Многострочное поле

- Минимум 3 строки (высота 72), максимум 12 строк, дальше внутренняя прокрутка.
- Растёт по содержимому (`minLines` / `maxLines`), padding `space2` со всех сторон.
- В форме создания задачи описание — многострочное поле с переключателем
  «Написать / Просмотр» (см. 18.3).

### 3.4. Валидация

- Валидация **по потере фокуса**, не по каждому символу. Исключение — счётчик длины
  для полей с жёстким лимитом: он живой.
- Сообщение об ошибке описывает, что сделать: не «Некорректное значение»,
  а «Тема не может быть пустой».
- Ошибка сервера, относящаяся к конкретному полю, показывается на этом поле;
  общая ошибка формы — баннером над кнопками (см. 17.2).

### 3.5. Клавиатура и доступность

- `Tab` и `Shift+Tab` — переход. `Esc` — очистить, если в поле есть кнопка очистки.
- Подпись связывается с полем (`InputDecoration.labelText` даёт связь автоматически);
  плейсхолдер **не заменяет подпись** — подпись остаётся видимой всегда.
- Ошибка объявляется через `Semantics(liveRegion: true)` рядом с полем.

### 3.6. Flutter

`TextField` с глобальным `InputDecorationTheme`. Требуемые переопределения:
`isDense: true`, `contentPadding`, `constraints` по высоте, и все четыре границы через
`OutlineInputBorder(borderRadius: radiusSm)`:

| Свойство | `borderSide` |
|---|---|
| `enabledBorder` | `borderStrong`, width 1 |
| `focusedBorder` | `borderFocus`, **width 2** |
| `errorBorder` | `borderDanger`, width 1 |
| `focusedErrorBorder` | `borderDanger`, **width 2** |
| `disabledBorder` | `border`, width 1 |

**`SLFocusRing` к полям ввода не применяется.** Это ровно то место, где обёртка
и создала «поле внутри поля»: `TextField` уже рисует свою рамку, и внешнее кольцо
того же цвета дало три контура. Если `SLFocusRing` где-то надет на `TextField` —
его надо снять, а не перекрашивать.

Про сдвиг содержимого: `contentPadding` задаётся одинаковым во всех состояниях,
утолщение с 1 до 2 px уходит внутрь, в горизонтальный отступ 8 px. Текст и каретка
при получении фокуса **не должны сдвигаться** — это проверяемое требование, а не
пожелание.

## 4. Поиск

Отдельный компонент, а не «поле ввода с иконкой»: у него своя геометрия
(`system.md` 10.3.1), своё поведение и свои правила текста.

### 4.1. Два вида поиска

| Вид | Где | Оформление |
|---|---|---|
| **Самостоятельный** | сайдбар, список доступа, шапка экрана | высота **36**, рамка `borderControl`, `radiusSm`, фон `surface`, минимальная ширина 240 |
| **Встроенный** | внутри меню, поповера, выпадающего списка | высота **32**, **рамки нет**, снизу разделитель 1 px `borderSubtle`, во всю ширину меню |

**Почему у встроенного нет рамки.** Меню уже имеет свою рамку и радиус; поле с рамкой
внутри поля с рамкой даёт «коробку в коробке» — тот же дефект, из-за которого мы
переделывали фокус (`system.md` 10.6.1). Внутри меню границу несёт разделитель,
а не контур.

```
Самостоятельный, высота 36:
+------------------------------------------+
| ⌕  Название или ключ                 [×] |
+------------------------------------------+
 8  16  8                             16  8    служебное: 40, с очисткой 64

Встроенный в меню, высота 32:
+------------------------------------------+
| ⌕  Начните вводить имя                   |
|------------------------------------------|  ← разделитель borderSubtle
| [АИ] Анна Иванова                        |
```

### 4.2. Правило плейсхолдера

**Плейсхолдер говорит, что вводить, а не какова область поиска.**

Это правило появилось из дефекта: плейсхолдер «Поиск по моим активным задачам»
(≈ 207 px) не помещался в поле сайдбара (184 px под текст) и обрезался. Попытка
объяснить область поиска внутри плейсхолдера всегда упирается в ширину — область
описывается предложением, а плейсхолдер вмещает пару слов.

| Что | Где живёт |
|---|---|
| **Что вводить** | плейсхолдер: «Название или ключ», «Поиск по адресу» |
| **Область поиска** | заголовок секции **прямо над полем** — виден всегда |
| **Напоминание об области** | подпись под полем `label` `textMuted`, **появляется, когда в поле есть текст** |
| **Границы поиска** | текст пустого результата: называет область целиком |

Так область поиска сообщается **трижды и в нужный момент**, а не один раз обрезанной
строкой. Ограничение по длине — не длиннее 176 px (≈ 26 символов) при 13 px,
проверяется на минимальной ширине 240.

### 4.3. Поведение

- Ввод дебаунсится **250 мс**. Меньше двух символов запрос не отправляется.
- Кнопка очистки появляется, только когда поле непустое: `icon16`, `iconDefault`,
  зона нажатия 24 × 24 на десктопе и 44 × 44 на тач.
- Совпавший фрагмент в результатах выделяется **весом 600**, не цветом и не фоном.
- Поиск выполняет сервер везде, где список подгружается порциями: фильтровать
  на клиенте то, что на клиенте лежит не целиком, нельзя.

### 4.4. Выпадающие результаты

Появляются, только если поиск **не фильтрует список на месте**. Поиск в сайдбаре
и в списке доступа фильтрует список под собой — выпадающего слоя у них нет.

```
+--------------------------------------------------+
| ⌕  Название или ключ                         [×] |
+--------------------------------------------------+
| SL-12  Починить экспорт CSV            в работе  |  строка 32, максимум 8
| SL-98  Экспорт не открывается в Excel  открыт    |
+--------------------------------------------------+
```

Слой: фон `surface`, `border`, `radiusMd`, `shadowMd`. Строка результата: ключ
(`bodySStrong`, `accent`), название (`bodyS`, `textPrimary`, `ellipsis`), плашка
статуса справа.

### Состояния

| Состояние | Оформление |
|---|---|
| Пустое, без фокуса | плейсхолдер + бейдж `/` |
| Фокус | рамка утолщается до 2 px `borderFocus` (`system.md` 10.6.1); у встроенного в меню — разделитель снизу утолщается до 2 px, рамка не появляется |
| В фокусе, пустой запрос | у поиска с выпадающим слоем — блок «Недавние»: до 5 последних открытых задач; у фильтрующего на месте — полный список без изменений |
| Загрузка | в строке поиска справа спиннер 14 px; предыдущие результаты не стираются и приглушаются до 60 % непрозрачности |
| Фокус в поле | рамка поля утолщается до 2 px `borderFocus`; выпадающий список результатов своей рамки фокуса не получает — фокус остаётся в поле |
| Есть результаты | список, первый элемент подсвечен как активный (`surfaceSelected`) |
| Ничего не найдено | одна строка высотой 64: «Ничего не найдено по запросу «…»» + подсказка «Проверьте раскладку или попробуйте часть слова» |
| Ошибка | строка 64: «Не удалось выполнить поиск» + текстовая кнопка «Повторить» |
| Слишком много результатов | показываются 8, внизу «Показать все результаты (N)»; при N > 999 пишем «999+» |

### Клавиатура

| Клавиша | Действие |
|---|---|
| `/` | фокус в поиск из любого места, если фокус не в поле ввода |
| `Ctrl/Cmd + K` | то же, работает всегда, включая поля ввода |
| `↑` `↓` | перемещение по результатам |
| `Enter` | открыть выделенный результат |
| `Ctrl/Cmd + Enter` | открыть результат в новой вкладке |
| `Esc` | закрыть список; повторный `Esc` — очистить поле и снять фокус |

Доступность: поле — `role=combobox` с `aria-expanded`; во Flutter это
`Semantics(textField: true, expanded: ...)` плюс объявление количества результатов
через `liveRegion`.

### Flutter

`TextField` c `InputDecorationTheme`, переопределённым под высоту 36 (`isDense`,
`constraints`, `contentPadding`). Для выпадающего слоя — `RawAutocomplete`
либо `MenuAnchor`.
Стандартный `Autocomplete` подходит по механике, но его оформление придётся заменить
целиком. Дебаунс и «недавние» — свой контроллер (Riverpod).

## 5. Выпадающий список (смена статуса)

Основной сценарий — смена статуса задачи, поэтому проектируется под него.

```
Кнопка-триггер: плашка статуса + шеврон
+-------------------------+
| ▶ В работе          ⌄  |    высота 24, radiusFull, фон statusSurface
+-------------------------+

Меню:
+-------------------------------+
| ○ Открыт                      |   строка 32, текст bodyS
| ▶ В работе                 ✓  |   текущий: фон surfaceSelected, галочка справа
| ◉ Ревью                       |
| ⚗ Тестирование                |
| ✓ Закрыт                      |
+-------------------------------+
```

- Меню: фон `surface`, `border`, `radiusMd`, `shadowMd`, вертикальный padding `space1`.
- Строка меню: высота 32, padding `space3`, иконка `icon16` цветом статуса, текст `bodyS`
  цветом `textPrimary`. Активная — фон `surfaceSelected`, галочка `icon16` цветом `accent`.
- В MVP разрешены все переходы между пятью статусами: настраиваемых воркфлоу-переходов
  нет (`docs/product/glossary.md`, раздел 6). Строка меню становится `textDisabled`
  только когда действие запрещено ролью, и тогда тултип называет причину:
  «Недостаточно прав для смены статуса».
- Ширина меню = ширина самого длинного пункта, минимум ширины триггера, максимум 280.

### Состояния

| Состояние | Оформление |
|---|---|
| Обычное | плашка статуса + шеврон `icon16` цветом текста статуса |
| Наведение | плашка темнеет на `overlayHover` |
| Фокус | `borderFocusRing` вокруг плашки — у плашки статуса своей рамки нет, кольцо уместно |
| Открыто | шеврон повёрнут на 180°, анимация 120 мс |
| Отключено (нет прав) | плашка без шеврона, не кликабельна, тултип «Недостаточно прав для смены статуса» |
| Загрузка (переход применяется) | **оптимистично**: плашка сразу принимает новый статус, справа на месте шеврона спиннер 12 px, 300 мс не показывается вовсе, чтобы не мигать на быстрой сети |
| Ошибка | плашка возвращается к прежнему статусу с анимацией 200 мс, показывается тост-ошибка с кнопкой «Повторить»; на 400 мс плашка получает обводку `1 px danger`, затем она гаснет |

Откат описан подробно намеренно: это самое частое действие в трекере,
и оно обязано ощущаться мгновенно, а при сбое — честно.

### Клавиатура

`Enter` или `Space` — открыть; `↑` `↓` — перемещение; `Enter` — выбрать;
`Esc` — закрыть без изменений; ввод буквы — переход к первому пункту на эту букву.
При закрытии фокус возвращается на триггер.

### Flutter

`MenuAnchor` + `MenuItemButton` (Material 3), тема через `MenuThemeData`.
Триггер — свой виджет. `DropdownButton` не использовать: у него своя разметка
и трудноуправляемая высота.

## 6. Селектор пользователя

Выбор исполнителя и автора задачи, выбор участника. Поиск по мере ввода.
Термина «наблюдатель» в продукте нет: поля «Наблюдатели» не существует, подписка на задачу
неявная ([D-17](../product/decisions.md#d-17), `glossary.md`, раздел 6).

```
Триггер (пустой):        [ ⊕ ] Не назначен          ← аватар-заглушка 20 + bodyS textMuted
Триггер (заполненный):   [ АИ ] Анна Иванова        ← аватар 20 + bodyS textPrimary
Триггер (наведение):     [ АИ ] Анна Иванова    ⌄

Меню:
+-------------------------------------+
| ⌕ Начните вводить имя               |   встроенный поиск 32, без рамки
|-------------------------------------|   ← разделитель borderSubtle
+-------------------------------------+
| [АИ] Анна Иванова                ✓  |   строка 32
|      anna@example.com               |   ← вторая строка только если есть тёзки
| [ПС] Пётр Смирнов                   |
| [МК] Мария Ковалёва                 |
+-------------------------------------+
| ⊘ Снять назначение                  |   строка 32, текст textSecondary
+-------------------------------------+
```

- Строка пользователя: аватар 20, имя `bodyS` цвета `textPrimary`, отступ `space2`.
- Email показывается второй строкой (`label`, `textMuted`) **только при неоднозначности** —
  когда в результатах есть полные тёзки. Иначе строка остаётся 32 px.
- Наверху списка — «Назначить на себя», если текущий пользователь не выбран.
  Это самое частое действие, и оно достойно первой позиции.
- Максимум 20 результатов, дальше — подсказка «Уточните запрос».

### Состояния

| Состояние | Оформление |
|---|---|
| Пусто | аватар-заглушка: круг `surfaceSunken` с иконкой `person_outline_rounded` `iconMuted`; текст «Не назначен» цветом `textMuted` |
| Загрузка списка | 5 строк-скелетонов: круг 20 + полоска 120 × 12 |
| Пустой результат поиска | строка 64: «Никого не нашли» + подсказка «Возможно, участника нет в этой очереди» |
| Ошибка загрузки | строка 64: «Не удалось загрузить список» + «Повторить» |
| Применение выбора | **оптимистично**: триггер сразу показывает нового исполнителя; при ошибке возвращается прежний + тост |
| Нет прав | триггер без шеврона, некликабельный, тултип «Недостаточно прав» |
| Очень длинное имя | обрезается по ширине триггера с `ellipsis`, полное имя в тултипе |

### Flutter

`MenuAnchor` + встроенный поиск (`components.md` 4.1: без рамки, с разделителем снизу)
+ `ListView` с `itemExtent: 32`. Ширина меню — не меньше 240, чтобы поле поиска
соответствовало минимальной ширине.
Лёгкий кастом: стандартного «комбобокса с аватарами» в Material нет.
Список результатов виртуализировать обязательно — в крупном проекте участников сотни.

## 7. Чип статуса

Описан в `system.md` 4. Здесь — только анатомия и поведение.

```
Компактный (строка списка), высота 20:
+---------------+
| ▶ В работе    |   иконка icon12 + space1 + текст caption (11/16/600)
+---------------+   padding 2 / space2, radiusFull

Обычный (карточка задачи), высота 24:
+-----------------+
| ▶ В работе   ⌄  |   иконка icon16 + space1 + текст labelStrong (12/16/600)
+-----------------+   padding 4 / space2, radiusFull, кликабелен
```

- Фон — `statusSurface[code]`, текст и иконка — `statusText[code]`.
- Ширина по содержимому. Текст статуса **не обрезается никогда**: если места нет,
  сжимается всё остальное в строке. Это единственный элемент строки с таким приоритетом.
- Некликабельный вариант (в списке, в истории) — без шеврона, курсор `basic`.
- Доступное имя: «Статус: В работе». Для кликабельного — «Статус: В работе, изменить».

Состояния: обычное, наведение (`overlayHover`), фокус (кольцо), нажатое,
отключённое (без шеврона), загрузка и ошибка — см. 5.

Flutter: `Container` + `Row`. Стандартный `Chip` не подходит: у него минимальная
высота 32 и своя внутренняя геометрия, ломать её дороже, чем написать 20 строк.

### 9.2. Аватар

| Размер | px | Текст инициалов | Где |

### 9.3. Группа аватаров

## 10. Строка списка задач

Ключевой компонент продукта. От него зависит и плотность, и производительность.

### 10.1. Анатомия (десктоп, высота ровно 36)

```
|<-32->|<--88-->|<------------- гибкая ------------->|<-132->|<-160->|<44>|<32>|<-96->|
+------+--------+------------------------------------+-------+-------+----+----+------+
| [v]  | DEV-42 | Починить экспорт CSV на больших…   |▶В раб.| [АИ] А|▓ 80| 8  |12 фев|
+------+--------+------------------------------------+-------+-------+----+----+------+
  чек-   ключ     тема (ellipsis, одна строка)         статус  исполн. прио слож дата
  бокс
```

- Разделитель между строками: нижняя граница 1 px `borderSubtle`. Не рамка вокруг.
- Горизонтальный padding контейнера — `space4` (16) слева и справа.
- Зазор между колонками — `space3` (12).
- Тема — единственная гибкая колонка, `Expanded`, `maxLines: 1`, `ellipsis`.
- Чекбокс появляется при наведении на строку либо когда выделен хотя бы один элемент;
  в остальное время его место занято, но пусто (ширина 32 резервируется всегда,
  иначе строка «дёргается» при наведении).

### 10.2. Состояния

| Состояние | Оформление |
|---|---|
| Обычное | фон `surface` |
| Наведение | фон `surfaceHover`, мгновенно (`motionInstant`); появляется чекбокс и кнопка «⋯» справа |
| Курсор клавиатуры | фон `surfaceHover` + слева вертикальная полоса 2 px `accent`. Отличается от выделения намеренно |
| Выделена (чекбокс) | фон `surfaceSelected`, чекбокс отмечен |
| Выделена + наведение | фон `surfaceSelectedHover` |
| Фокус | `borderFocusRing` внутрь строки, с отступом 2 px от краёв (кольцо снаружи обрезалось бы соседями) |
| Прочитана/непрочитана | непрочитанная — тема `bodySStrong` вместо `bodyS`; точка `accent` 6 px слева от ключа. Цвет не единственный носитель: разница в весе шрифта видна и без цвета |
| Задача закрыта | ключ и тема цветом `textMuted`; **зачёркивание не применяется** — оно мешает читать |
| Загрузка | скелетон, см. 15 |
| Оптимистичное изменение | изменённая ячейка обновляется мгновенно; на 200 мс её фон подсвечивается `accentSurface`, затем возвращается |
| Откат после ошибки | ячейка возвращает прежнее значение за 200 мс, фон на 400 мс становится `dangerSurface`, затем гаснет; в тосте — «Не удалось изменить статус DEV-42» + «Повторить» |
| Нет прав на изменение | чекбокс не появляется, «⋯» не появляется, строка остаётся кликабельной для открытия |
| Очень длинная тема | `ellipsis`; полный текст в тултипе после 500 мс наведения |
| Пустая тема | «Без темы» цветом `textMuted` курсивом |

### 10.3. Взаимодействие

| Действие | Результат |
|---|---|
| Клик по строке | открыть задачу |
| Клик по ключу | открыть задачу (это ссылка, работает `Ctrl/Cmd + клик` в новой вкладке) |
| Клик по плашке статуса | открыть меню статусов, **не** открывать задачу |
| Клик по чекбоксу | выделить, не открывать |
| `Shift + клик` по чекбоксу | выделить диапазон от последнего выделенного |
| Правый клик | контекстное меню: сменить статус, назначить, приоритет, копировать ключ, копировать ссылку, открыть в новой вкладке |
| Средний клик | открыть в новой вкладке |

Правило: **вложенные интерактивные зоны гасят событие строки**. Иначе клик по статусу
и открывает меню, и уходит на другую страницу — классическая ошибка.

### 10.4. Адаптив

- **768–1023:** высота 40. Скрываются колонки «дата» и «сложность».
- **< 768:** высота 56, две строки. Первая: ключ + тема (ellipsis).
  Вторая: плашка статуса + аватар исполнителя + индикатор приоритета.
  Чекбокс — только в режиме множественного выбора, включаемом долгим нажатием.

### 10.5. Клавиатура

| Клавиша | Действие |
|---|---|
| `↑` `↓` или `k` `j` | перемещение курсора по строкам |
| `Enter` | открыть задачу |
| `Space` | выделить/снять выделение |
| `Shift + ↑/↓` | расширить выделение |
| `x` | выделить/снять выделение (альтернатива, привычная по почтовым клиентам) |
| `s` | открыть меню смены статуса для строки под курсором |
| `a` | открыть селектор исполнителя |
| `Home` / `End` | к первой / последней строке |
| `PageUp` / `PageDown` | на экран вверх / вниз |
| `Esc` | снять всё выделение |

Курсор клавиатуры при прокрутке всегда остаётся в видимой области
(`Scrollable.ensureVisible`, без анимации).

### 10.6. Flutter — критично для производительности

- `ListView.builder` с **обязательным** `itemExtent: 36` (или `prototypeItem`).
  Без фиксированного экстента `Scrollbar` и `ensureVisible` начинают считать
  весь список, и на 2000 задачах это заметно.
- Внутри строки — только `Row` и `SizedBox` фиксированной ширины плюс один `Expanded`.
  Запрещены `IntrinsicWidth`, `IntrinsicHeight`, вложенные `LayoutBuilder`.
- Строка — `const`-конструируемый `StatelessWidget`, состояние наведения хранится
  в родителе (индекс наведённой строки), а не в `StatefulWidget` каждой строки.
- Разделитель рисуется как `Border(bottom:)` в `DecoratedBox` самой строки,
  а не отдельным виджетом-делителем: это на треть меньше виджетов.
- Тултип на длинную тему создавать лениво: `Tooltip` на каждой строке — дорого.
  Использовать один общий тултип-оверлей по наведению.

Это единственный компонент, который стоит проверить на профилировании
(`flutter run --profile`, 2000 строк, прокрутка) до того, как на нём построят экраны.

## 11. Элемент сайдбара

```
+------------------------------------------+
| ▸ ⌗ Разработка                       124 |   высота 32
+------------------------------------------+
| |  ⌗ Бэкенд                          47  |   вложенный: отступ слева +space4
+------------------------------------------+
```

- `Semantics(scopesRoute: true, namesRoute: true, label: <заголовок>)`.

Flutter: `showDialog` + `Dialog` с `DialogTheme`. Focus trap `showDialog` даёт сам.
Возврат фокуса — проверить руками, стандартное поведение не всегда срабатывает
при закрытии по клику вне окна.

```
+-------------------------------------------------+
```

  Три носителя смысла, цвет — не единственный.
- Текст — `bodyS` `textPrimary`; второй строкой действие — текстовая кнопка `sm`.

| Тип | Иконка | Полоса и иконка | Автозакрытие |
|---|---|---|---|
| Успех | `check_circle_rounded` | `success` | 4 с |
| Информация | `info_outline_rounded` | `info` | 4 с |
| Предупреждение | `warning_amber_rounded` | `warningAccent`, иконка `warning` | 6 с |
| Ошибка | `error_outline_rounded` | `danger` | **не закрывается сам** |

## 15. Скелетон

Скелетон, а не спиннер по центру. Спиннер допустим только внутри кнопки и в поиске.

- Базовый элемент: прямоугольник `radiusSm`, заливка `skeletonBase`.
- Шиммер: линейный градиент `skeletonBase → skeletonHighlight → skeletonBase` под углом 100°, проход 1400 мс,
  бесконечно, `Curves.linear`.
- При `disableAnimations` шиммер отключается, остаётся статичная заливка `skeletonBase`.
- Скелетон **повторяет геометрию реального контента**: те же высоты строк, те же
  ширины колонок. Иначе при загрузке экран «прыгает».

| Место | Что показываем |
|---|---|
| Список задач | 12 строк по 36 px; шапка таблицы отрисована сразу и по-настоящему; в каждой строке полоски по ширинам колонок, ширина темы чередуется 40/70/55 % чтобы не выглядело сеткой |
| Страница задачи | заголовок 60 % × 20, три полоски описания 100/100/60 % × 14, сайдбар — 6 пар «подпись + значение» |
| Сайдбар | 8 строк по 32 с полосками 140 × 12 |
| Комментарии | 3 блока: круг 24 + полоска 120 × 12 + две полоски текста |
| Селектор пользователя | 5 строк: круг 20 + полоска 120 × 12 |

Правило: скелетон показывается **не раньше 200 мс** после начала загрузки.
Если данные пришли быстрее, пользователь не увидит вспышку. И держится минимум 400 мс,
если уже показан, чтобы не мигнуть.

Flutter: `AnimatedBuilder` + `ShaderMask` с `LinearGradient`. В Sweet Limit есть
готовый `SLShimmeringEffect` (`lib/shared/uikit/effects/`) — механика оттуда
переносится, значения берутся отсюда.

## 17. Состояние ошибки

### 17.1. Ошибка на весь экран

Та же композиция, что у пустого состояния, но иконка `error_outline_rounded` цветом
`danger`, и кнопка «Повторить» — вариант `secondary`.

| Причина | Заголовок | Пояснение | Действие |
|---|---|---|---|
| Сеть или сервер | «Не удалось загрузить задачи» | «Проверьте соединение и попробуйте ещё раз» | «Повторить» |
| 403 — роли не хватает | «Недостаточно прав» | «Ваша роль в проекте — читатель. Попросите администратора изменить её» | «Назад» |
| 404 — объекта нет либо доступа нет вовсе | «Задача не найдена» | «Возможно, она удалена, или у вас нет доступа к её проекту» | «К списку задач» |
| 500 | «Что-то сломалось на нашей стороне» | «Мы уже знаем о проблеме. Попробуйте повторить через минуту» | «Повторить» |

Технические подробности (код, `requestId`) прячутся под раскрывающийся
«Подробности» — `mono` 11 px цветом `textMuted`, с кнопкой «Скопировать».
Пользователю они не нужны, а в баг-репорте бесценны.

### 17.2. Баннер ошибки (внутри формы или панели)

```
+---------------------------------------------------------+
| ⚠  Не удалось сохранить изменения.                  [×] |
|    Проверьте обязательные поля и повторите.             |
+---------------------------------------------------------+
```

- Фон `dangerSurface`, левая полоса 3 px `danger`, граница `dangerBorder`,
  `radiusSm`, padding `space3`. Текст `bodyS` `textPrimary`, иконка `danger`.
- Варианты: `danger`, `warning` (`warningSurface` + `warningAccent`),
  `info` (`accentSurface` + `accentBorder`), `success` (`successSurface` + `successBorder`).
- Баннер `liveRegion`; при появлении фокус на него **не** переводится, но при отправке
  формы фокус ставится на первое поле с ошибкой.

### 17.3. Частичная ошибка

Если часть данных загрузилась, а часть нет (например, задачи есть, а счётчики нет) —
показываем то, что есть, а на месте сбойного блока строку `label` цветом `textMuted`:
«Не удалось загрузить» + текстовая кнопка «Повторить». Не обрушивать весь экран
из-за одного виджета.

### 17.4. Офлайн

Полоса на всю ширину под шапкой, высота 28, фон `warningSurface`, текст `label`
цветом `warning`: «Нет соединения. Изменения не сохраняются». Пропадает автоматически
при восстановлении, с тостом «Соединение восстановлено».

### 18.1.1. Отложено до релиза 2 — **не реализовывать в MVP**

| Что | Почему отложено |
|---|---|
| Автораспознавание ключа задачи `DEV-42` в тексте и превращение его в ссылку | [D-38](../product/decisions.md#d-38): рендер ссылки требует проверки прав на каждую упомянутую задачу — иначе ссылка раскрывает существование задачи из чужого проекта. В MVP `DEV-42` в описании и комментарии остаётся обычным текстом (US-43, US-74) |
| Поповер-превью задачи по наведению на ключ | то же решение: превью потребовало бы отдавать название и статус чужой задачи |

Фронтенду: строки выше в MVP **в работу не берутся**. Если ключ в тексте выглядит как
обычный текст — это правильное поведение, а не дефект.

### 18.3. Редактор

MVP — простой режим: `TextField` с моноширинным вводом плюс переключатель
«Написать / Просмотр» (две вкладки), плюс панель из 6 кнопок:
жирный, курсив, код, ссылка, список, цитата. Каждая — `IconButton` `sm`, вставляет
разметку вокруг выделения. Хоткеи: `Ctrl/Cmd + B`, `I`, `K` (ссылка).

WYSIWYG в MVP не делаем — это отдельный крупный проект.

### 18.4. Flutter — предупреждение о цене

Своего рендера Markdown во Flutter нет. Варианты:

- пакет **`flutter_markdown`** — покрывает 90 % таблицы выше через `MarkdownStyleSheet`
  и `builders`. Не покрывает из коробки: ссылки на задачи, упоминания, поповеры,
  кнопку «Копировать» у блока кода, сворачивание длинного текста. Это пишется
  как кастомные `MarkdownElementBuilder` и обёртки;
- писать свой рендер — не стоит того.

**Оценка для планирования:** базовый рендер — недорого; кастомные элементы
(ключи задач, упоминания, поповеры, сворачивание) — сопоставимо по объёму с базовым.
Считать markdown-контент отдельной задачей, а не «частью экрана задачи».
Отмечу отдельно: актуальный статус сопровождения `flutter_markdown` надо проверить
перед подключением — я не могу этого подтвердить по памяти.

## 19. Поле комментария

```
+---------------------------------------------------------+
| [АИ] | Написать комментарий…                            |   свёрнутое: высота 40
+---------------------------------------------------------+

Развёрнутое:
+---------------------------------------------------------+
| Написать  |  Просмотр                                   |   вкладки 32
+---------------------------------------------------------+
| B  I  <>  🔗  •  ❝                              📎      |   панель 32
+---------------------------------------------------------+
|                                                         |
| Текст комментария…                                      |   минимум 72, максимум 240
|                                                         |
+---------------------------------------------------------+
| Ctrl+Enter — отправить            [Отмена] [Отправить]  |   подвал 40
+---------------------------------------------------------+
```

- Свёрнутое состояние — одна строка 40 px, фон `surface`, граница `borderControl`.
  По клику или по фокусу разворачивается.
- Развёрнутое — карточка: `border`, `radiusMd`, фон `surface`.
- Подсказка о хоткее — `label` цветом `textMuted`, слева в подвале.
- Кнопка «Отправить» отключена при пустом поле.

### Состояния

| Состояние | Оформление |
|---|---|
| Свёрнутое | плейсхолдер «Написать комментарий…» `textMuted` |
| В фокусе | развёрнуто, кольцо фокуса вокруг области ввода |
| Отправка | кнопка в состоянии загрузки, поле read-only, но текст виден |
| Успех | поле очищается и сворачивается, новый комментарий появляется в списке; тост не показываем — результат виден и так |
| Ошибка отправки | баннер ошибки над подвалом, **текст сохраняется**, кнопка снова активна. Потерять набранный комментарий недопустимо |
| Черновик | при уходе со страницы текст сохраняется локально и восстанавливается при возврате; в свёрнутом виде показывается «Черновик: первые 40 символов…» цветом `textMuted` |
| Нет прав на комментирование | поле не отображается; вместо него строка `label` `textMuted`: «У вас нет прав комментировать эту задачу» |
| Загрузка вложения | под панелью полоска прогресса 2 px `accent` и плитка вложения в состоянии загрузки |

### Клавиатура

| Клавиша | Действие |
|---|---|
| `Ctrl/Cmd + Enter` | отправить |
| `Esc` | свернуть; если текст непустой — спросить подтверждение |
| `Ctrl/Cmd + B` / `I` / `K` | жирный, курсив, ссылка |
| `@` | открыть автодополнение упоминаний |
| `Tab` из поля | на кнопку «Отправить», не в панель форматирования |

Flutter: `TextField` + `Shortcuts`/`Actions` для `Ctrl+Enter`
(`SingleActivator(LogicalKeyboardKey.enter, control: true)` и вариант с `meta` для macOS —
проверять обе). Автодополнение упоминаний — свой оверлей, механика та же, что у поиска.

## 21. Элемент истории изменений

Самый плотный компонент интерфейса. Строка одна, если помещается.

```
[АИ] Анна Иванова изменила статус  ○ Открыт → ▶ В работе       12 фев, 14:32
[ПС] Пётр Смирнов назначил исполнителем [МК] Марию Ковалёву    12 фев, 15:01
[АИ] Анна Иванова изменила приоритет  ▓50 → ▓80                12 фев, 15:04
[АИ] Анна Иванова изменила описание                            12 фев, 15:10
     ▸ показать изменения
```

- Высота строки 28, при переносе — авто. Отступ между записями `space2`.
- Аватар `xs` (20), имя `bodySStrong` `textPrimary`, действие `bodyS` `textSecondary`,
  время `label` `textMuted` справа, выравнивание по правому краю колонки.
- Старое значение → новое: сами компоненты (плашка статуса, индикатор приоритета,
  аватар), а не текст. Стрелка «→» `icon12` `iconMuted`.
- Удалённое значение показывается как есть, без зачёркивания: слева от стрелки —
  уже достаточно однозначно.
- Изменение описания и других длинных текстов не разворачивается в строке:
  ссылка «показать изменения» раскрывает diff (добавленное — фон `successSurface`,
  удалённое — фон `dangerSurface` с зачёркиванием; **дублируется знаками `+` и `−`**,
  потому что цвет не может быть единственным носителем).

### Состояния

| Состояние | Оформление |
|---|---|
| Обычное | см. выше |
| Наведение | фон `surfaceHover` |
| Загрузка | 6 строк-скелетонов по 28 |
| Пусто | «История пуста» `body` `textMuted` — бывает только у только что созданной задачи |
| Много записей | показываются последние 50, кнопка «Показать более ранние» подгружает ещё 50 |

## 24. Чек-лист приёмки компонента

Компонент считается готовым, когда:

- [ ] реализованы все семь состояний из раздела 1 либо явно указано, каких нет и почему;
- [ ] ни одного hex в коде — только роли из `SLColorScheme` и токены размеров;
- [ ] проверено на клавиатуре без мыши: вход, выход, действие, `Esc`;
- [ ] индикатор фокуса видно и не обрезается соседями;
- [ ] у элемента ровно **один** контур фокуса, а не два одного цвета;
- [ ] содержимое поля не сдвигается при получении фокуса;
- [ ] есть доступное имя; иконки без текста имеют `tooltip`;
- [ ] проверен текст длиной 300 символов без пробелов и пустая строка;
- [ ] на тач-устройстве зона нажатия не меньше 44 × 44;
- [ ] при `disableAnimations` компонент не анимируется и остаётся рабочим;
- [ ] в виртуализированном списке компонент не создаёт `StatefulWidget` на строку.
