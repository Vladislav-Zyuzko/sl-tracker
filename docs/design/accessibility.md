# SL Tracker — доступность

Версия 1.1. Владелец: `sl-designer`.

Этот документ **не дублирует** [`system.md`](./system.md) и [`components.md`](./components.md),
а собирает разбросанные там требования в проверяемый список. Конкретные значения
(цвета, размеры, состояния) остаются в своих файлах — здесь ссылки на них и правила,
которые нигде больше не записаны.

**Целевой уровень — WCAG 2.1 AA.** Не потому, что кто-то требует сертификации,
а потому что это набор проверок, которые ловят реальные дефекты плотного интерфейса:
нечитаемый серый текст, невидимый фокус, статус, закодированный одним лишь цветом.

---

## 1. Что уже гарантировано системой

Эти вещи выполнены на уровне токенов и компонентов. Разработчику достаточно
не изобретать своё.

| Требование | Где обеспечено |
|---|---|
| Контраст обычного текста ≥ 4.5:1 | [`system.md` 3.3](./system.md) — три уровня текста проверены на всех поверхностях **в обеих схемах** |
| Контраст границ интерактивных элементов ≥ 3:1 | `system.md` 3.2 — роль `borderStrong`: 3.50:1 в светлой, 5.08:1 в тёмной |
| Контраст графических индикаторов ≥ 3:1 | `system.md` 5 — заливки шкалы приоритета |
| Видимый фокус у всего интерактивного | `system.md` 10.6.1 — два способа: кольцо `borderFocusRing` у элементов без своей рамки, утолщение рамки `borderFocusThick` у элементов с рамкой. Контраст `borderFocus` на всех подложках ≥ 4.06:1 в светлой и ≥ 5.08:1 в тёмной |
| Зона нажатия ≥ 44 × 44 на тач | `system.md` 10.2 |
| Уважение к `prefers-reduced-motion` | `system.md` 11 |
| Уважение к `prefers-color-scheme` | `system.md` 12.5 — по умолчанию тема следует за системой, выбор пользователя перекрывает её и запоминается |
| Статус не только цветом | `system.md` 4 — цвет + иконка + текст |
| Приоритет не только цветом | `system.md` 5 — число + форма шкалы + цвет |

**Единственная запрещённая пара** в системе: `textMuted` на `surfaceSelectedHover`
(4.44:1 в светлой схеме). В тёмной та же пара даёт 5.08:1, но запрет действует в обеих:
правило одно, иначе компонент придётся писать с ветвлением по теме.
Правило тинтов — `system.md` 3.3.

## 2. Правила, которых нет в других файлах

### 2.1. Цвет никогда не единственный носитель смысла

Полный перечень мест, где смысл кодируется, и чем он продублирован:

| Что кодируем | Цвет | Чем продублировано |
|---|---|---|
| Статус задачи | 5 оттенков | иконка + текст статуса, всегда |
| Диапазон приоритета | 4 оттенка | число 0–100 + высота шкалы |
| Сложность | не кодируется цветом вовсе | число |
| Роль участника | не кодируется цветом | текст бейджа |
| Непрочитанное уведомление | точка `accent` | фон строки + вес шрифта + слово «Непрочитанное» в доступном имени |
| Непрочитанная задача в списке | точка `accent` | вес шрифта названия |
| Источник записи доступа | 2 оттенка плашки | текст «Конфигурация» / «Приглашение» + иконка |
| Состояние приглашения | 3 оттенка плашки | текст «Действует» / «Истекло» / «Отозвано» |
| Тип тоста | полоса слева | иконка + текст, называющий результат |
| Diff в истории (релиз 2) | зелёный / красный фон | знаки `+` и `−` |
| Ошибка поля | граница `danger` | текст ошибки под полем + иконка |

Проверка: **сделать скриншот в оттенках серого**. Если что-то стало неразличимо —
это дефект, а не «мелочь».

### 2.2. Отличие фокуса от наведения и от выделения

Три разных состояния, которые в плотном списке легко слить в одно:

| Состояние | Как выглядит | Кому адресовано |
|---|---|---|
| Наведение | фон `surfaceHover` | мышь |
| Курсор клавиатуры | фон `surfaceHover` + полоса 2 px `accent` слева | клавиатура |
| Выделение (выбрано) | фон `surfaceSelected` | обе |
| Фокус | кольцо `borderFocusRing` (элементы без своей рамки) либо рамка 2 px `borderFocusThick` (элементы с рамкой) | клавиатура |

Курсор клавиатуры отражается в семантике как `selected: true`.
Полоса слева — единственное, что отличает его от наведения мышью, и убирать её нельзя.

### 2.3. Что объявляется голосом (`liveRegion`)

Незрячий пользователь не видит тостов и подсветок. Обязательны к объявлению:

| Событие | Настойчивость |
|---|---|
| Ошибка отправки формы | `assertive` |
| Откат оптимистичного изменения | `assertive` — иначе человек уверен, что статус сменился |
| Приглашение недействительно | `assertive` |
| Успешное действие (тост `success`) | `polite` |
| Смена счётчика уведомлений | `polite`, один раз, без повторов |
| Число результатов после фильтра или поиска | `polite` |
| Состояние «Завершаем вход…» | `polite` — иначе экран молчит |
| Появление нового чужого комментария | `polite` |

Не объявляются: наведение, прокрутка, появление скелетона, декоративные анимации.

### 2.4. Доступные имена: правила составления

- **Имя описывает результат, а не внешний вид.** «Скопировать адрес проекта.
  Ссылка не даёт доступа» — а не «Кнопка со звеном цепи».
- **Контекст входит в имя, если рядом есть однотипные элементы.**
  Четыре кнопки «⋯» в списке — это «Действия для ivan@yandex.ru», а не четыре «Ещё».
- **Визуальная подпись рядом не заменяет имя.** Пояснение, написанное под кнопкой,
  для скринридера может не связаться с ней — включаем его в имя.
- **Предупреждение о последствиях входит в имя опасного действия.**
  «Удалить доступ для ivan@yandex.ru», «Удалить проект, необратимо».
- **Имя не обещает того, чего нет.** У читателя поля объявляются без слова «изменить».
- **Состояние передаётся флагами** (`toggled`, `selected`, `expanded`, `checked`),
  а не словами внутри имени: скринридер скажет их сам, иначе выйдет «включено включено».

### 2.5. Порядок фокуса и заголовки

- Порядок фокуса совпадает с визуальным порядком чтения. Исключение одно и осознанное:
  на экране задачи **панель полей идёт последней**, хотя визуально она справа —
  содержание важнее полей. Компенсируется хоткеями `s`, `a`, `i`
  ([issue.md](./screens/issue.md)).
- Первым в порядке фокуса на каждом экране внутри оболочки — скрытая ссылка
  «Перейти к содержимому», видимая только при фокусе.
- При переходе между экранами фокус ставится на заголовок `h2` нового экрана.
- Заголовки образуют иерархию: `h2` — экран, `title` и `overline` секций помечаются
  `Semantics(header: true)`. Уровень `h1` в рабочих экранах не используется.
- Модалка: focus trap, фокус внутрь, `Esc` закрывает, **фокус возвращается на элемент,
  который её открыл** — это проверяется руками, стандартное поведение Flutter
  срабатывает не всегда (`components.md` 13).
- У опасных подтверждений фокус ставится на безопасную кнопку («Отмена»),
  чтобы случайный `Enter` ничего не разрушил.

### 2.6. Виртуализированные списки

Плотные списки — самое проблемное место для скринридера.

- Список объявляется как список с общим числом: «Задачи, 128».
- Строка читается **одной фразой в фиксированном порядке**, а не по ячейкам:
  «DEV-42, Починить экспорт CSV, статус: В работе, исполнитель: Анна Иванова,
  приоритет 80 из 100, высокий, сложность 8 story points».
- Таблица задач объявляется **списком, а не таблицей**: семантика таблицы
  из виртуализированного `ListView` во Flutter Web не собирается, и притворяться
  ею — хуже, чем честно быть списком ([queue-issues.md](./screens/queue-issues.md)).
- Внутрь списка `Tab` входит один раз; дальше — стрелки; выход — `Tab`.
  Построчная табуляция по 128 строкам недопустима.
- Дозагрузка порций не сбрасывает позицию фокуса и не объявляет каждую порцию.

### 2.7. Формы и ошибки

- Подпись поля видима всегда; плейсхолдер её **не заменяет**.
- Валидация — по потере фокуса, не по каждому символу: живая ругань во время набора
  мешает и зрячим, и незрячим.
- Сообщение об ошибке связано с полем и объявляется `liveRegion`.
- При отправке формы с ошибками фокус ставится **на первое поле с ошибкой**.
- Ошибка говорит, что сделать: «Название не может быть пустым», а не «Некорректное
  значение».
- Read-only (нет прав) и disabled — разные вещи: read-only показывается обычным
  `textPrimary` и остаётся читаемым и выделяемым; disabled применяется только
  к реально неактивным контролам (`system.md` 3.3).

### 2.8. Тексты и язык

- Интерфейс на русском; `lang` документа выставлен соответственно, иначе скринридер
  читает русский текст английскими правилами.
- Ключ задачи объявляется по группам: «DEV дефис 42».
- Даты в доступном имени — полные и однозначные («12 февраля в 14:32»),
  даже если визуально показано «2 часа назад».
- Аббревиатур и технических идентификаторов (`status_id`, UUID) в интерфейсе нет
  (US-92).

### 2.9. Движение и время

- При `disableAnimations` все длительности → 0, шиммер скелетона → статичная заливка.
- Автоматически исчезающие уведомления: таймер останавливается при наведении
  **и при фокусе внутри тоста**. Тосты-ошибки не исчезают сами вовсе.
- Ограничений по времени на действия пользователя в продукте нет: ни одна форма
  не отваливается по таймауту, кроме истечения сессии (30 дней, US-02).
- Ничего не мигает: частота мерцания выше 3 Гц в продукте отсутствует по построению.

### 2.10. Масштабирование и адаптив

- Интерфейс работоспособен при масштабе браузера 200 % — это эквивалентно переходу
  на брейкпоинт на ступень ниже, а они все спроектированы.
- Горизонтальной прокрутки страницы не возникает ни на одном брейкпоинте вплоть
  до 360 px.
- Текст не обрезается при увеличении системного размера шрифта: высоты строк заданы
  в px, но текст внутри переносится или получает `ellipsis` с тултипом, а не исчезает.
- **Известное ограничение:** плотный список с фиксированным `itemExtent: 36`
  при крупном системном шрифте покажет обрезанный текст. Смягчение — `ellipsis`
  и тултип; полноценное решение (переключатель плотности) — вне MVP, зафиксировано
  как сознательный компромисс, см. раздел 5.

## 3. Чек-лист приёмки экрана

Проходится по каждому экрану перед сдачей. Дополняет чек-лист компонента
(`components.md` 24), не заменяет его.

**Клавиатура**

- [ ] экран проходится целиком без мыши: вход, все действия, выход;
- [ ] порядок фокуса совпадает с визуальным (кроме задокументированного исключения);
- [ ] фокус виден на каждом шаге и не обрезается соседними элементами;
- [ ] у элемента ровно один контур фокуса: «рамка внутри рамки» — дефект (`system.md` 10.6.1);
- [ ] содержимое поля ввода не сдвигается при получении фокуса;
- [ ] `Esc` закрывает верхний слой и не делает ничего разрушительного;
- [ ] фокус после закрытия модалки вернулся на вызвавший элемент;
- [ ] хоткеи экрана не срабатывают, когда фокус в поле ввода (кроме `Ctrl/Cmd+K`);
- [ ] в списке `Tab` не проходит построчно.

**Скринридер**

- [ ] у каждого интерактивного элемента есть доступное имя, описывающее результат;
- [ ] однотипные кнопки различимы по имени;
- [ ] строка списка читается одной осмысленной фразой;
- [ ] состояния переданы флагами, а не словами в имени;
- [ ] ошибки, откаты и результаты действий объявляются;
- [ ] декоративные иконки и изображения исключены из семантики.

**Цвет и контраст**

- [ ] скриншот в оттенках серого остаётся понятным;
- [ ] ни один текст не ниже 4.5:1 (крупный — 3:1);
- [ ] границы интерактивных элементов не ниже 3:1;
- [ ] не использована запрещённая пара `textMuted` на `surfaceSelectedHover`
      (в тёмной схеме она формально проходит — запрет всё равно действует,
      правило одно для обеих схем);
- [ ] **экран проверен в обеих схемах**, а не только в той, что стоит у разработчика;
      отдельно — состояния наведения, фокуса, ошибки и скелетон.

**Состояния**

- [ ] описаны и реализованы все семь состояний из `screens/README.md`, раздел 3;
- [ ] пустое состояние объясняет, что это значит, и даёт действие;
- [ ] у ошибки есть «Повторить»;
- [ ] у состояния «нет прав» контролы отсутствуют, а не отключены.

**Тексты и данные**

- [ ] проверено на строке из 300 символов без пробелов;
- [ ] проверено на пустых значениях;
- [ ] проверено на 1000+ записей (виртуализация, «99+», «999+»);
- [ ] термины только из глоссария.

**Тач и масштаб**

- [ ] зона нажатия ≥ 44 × 44 на тач-брейкпоинтах;
- [ ] при масштабе 200 % нет горизонтальной прокрутки и обрезанного текста;
- [ ] при `disableAnimations` экран работоспособен.

## 4. Как это проверять

| Проверка | Чем |
|---|---|
| Контраст | вручную по формуле WCAG либо любым калькулятором; значения уже посчитаны в `system.md` |
| Оттенки серого | скриншот + обесцвечивание |
| Клавиатура | руками, мышь физически убрать |
| Скринридер | NVDA на Windows и VoiceOver на macOS; Flutter Web отдаёт семантику через ARIA-дерево, поэтому проверяем в браузере, а не в приложении |
| Масштаб 200 % | масштаб браузера, не системный |
| `prefers-reduced-motion` | системная настройка ОС; **проверить, что Flutter её действительно получает** — см. раздел 5 |
| Виртуализация | `flutter run --profile`, 2000 строк |

**Важно для QA:** семантика Flutter Web включается флагом доступности и не всегда
активна по умолчанию. Проверка «скринридер молчит» может означать не отсутствие
семантики, а невключённый режим. Это первое, что надо исключить.

## 5. Известные ограничения и сознательные компромиссы

Честный список того, что мы не делаем в MVP. Ни один пункт не является случайным.

| Ограничение | Почему | Что вместо |
|---|---|---|
| **Обе схемы проверены по отдельности** | тёмная схема добавлена в `system.md` 1.3 | контрасты пересчитаны заново, а не «унаследованы»; минимумы: обычный текст 4.63:1 (светлая) и 5.08:1 (тёмная), границы контролов 3.05:1 и 3.69:1 |
| **Плотность не переключается** | одна плотность = один набор высот = предсказуемая виртуализация | масштаб браузера 200 % как обходной путь |
| **Фиксированный `itemExtent` в списках** | без него прокрутка 2000 задач деградирует | `ellipsis` + тултип для длинного текста |
| **Таблица задач — список, а не `table`** | семантика таблицы из виртуализированного списка во Flutter Web не собирается | строка читается одной осмысленной фразой |
| **`prefers-reduced-motion`: поведение платформы не подтверждено** | не уверен, прокидывает ли Flutter Web системную настройку в `MediaQuery.disableAnimations` на текущей версии SDK | **обязательно проверить**; если нет — JS-интероп. Это первое, что должен выяснить фронтендер |
| **Кнопка входа через Яндекс ID вне дизайн-системы** | требования Яндекса запрещают менять цвет, содержимое и отступы кнопки | единственное задокументированное исключение; контраст текста 21:1, AA проходит. В тёмной схеме берётся белый вариант кнопки Яндекса — чёрный на тёмном фоне даёт 1.14:1 и не отделяется. См. [login.md](./screens/login.md) |
| **Локализация одна (русский)** | [D-36](../product/decisions.md#d-36) | тексты лежат в ресурсах локализации, второй язык добавляется без переработки |
| **Часовой пояс не настраивается** | вне MVP | точное время в тултипе и в доступном имени |
| **Нет режима высокой контрастности ОС** | Flutter Web его не подхватывает автоматически | базовые контрасты с запасом: основной текст 11.55:1 в светлой схеме и 13.34:1 в тёмной |

Ни одно из ограничений не нарушает AA. Каждое — про то, чего мы не делаем сверх AA.

## 6. Что делать при конфликте требований

Порядок разрешения, если требования спорят:

1. **Доступность против плотности.** Побеждает доступность, но ищется решение,
   сохраняющее плотность: не увеличить строку до 56, а дать `ellipsis` и тултип.
2. **Доступность против красоты.** Побеждает доступность без обсуждения.
   Так `borderStrong` стал темнее, чем «красиво» (`system.md` 3.2).
3. **Доступность против требований внешнего бренда** (кнопка Яндекс ID).
   Побеждают требования бренда. В светлой схеме конфликта нет: чёрный фон с белым
   текстом даёт 21:1, высота 44 совпадает с нашей минимальной зоной нажатия.
   В тёмной схеме конфликт возник — чёрная кнопка на тёмном фоне даёт 1.14:1
   и не опознаётся как контрол (WCAG 1.4.11 требует 3:1). Разрешён без нарушения
   бренда: берём **белый вариант кнопки, опубликованный самим Яндексом**.
   Выбор между двумя вариантами бренда — не изменение кнопки. Исключение
