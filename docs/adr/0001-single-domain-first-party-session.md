# ADR-0001. Фронт и API на одном домене, сессия в first-party cookie

- Дата: 2026-09-06
- Статус: принято
- Решает: оркестратор

## Контекст

Клиент — Flutter Web, сервер — NestJS. Их можно развести на разные домены
(`app.example.com` и `api.example.com`) или держать на одном.

Разные домены означают: CORS с `credentials`, преflight-запросы на каждый нетривиальный вызов,
и — главное — cookie сессии становится **сторонней (third-party)**. Браузеры такие куки режут:
Safari блокирует их по умолчанию много лет, Chrome ограничивает. Обходные пути (CNAME на
поддомен, отправка токена в заголовке из JS) либо хрупкие, либо требуют хранить токен
в доступном скрипту месте, что хуже с точки зрения XSS.

## Решение

Фронт и API живут на **одном домене**. Caddy отдаёт:

- `/api/*` → проксируется в NestJS;
- всё остальное → статика Flutter, с фолбэком на `index.html` для неизвестных путей
  (нужно для глубоких ссылок вида `/issues/DEV-42` при перезагрузке страницы).

Сессия — httpOnly Secure SameSite=Lax cookie. Она first-party, её никто не режет,
и JS до неё не дотягивается.

## Последствия

- CORS для веб-клиента не нужен вовсе. Это убирает целый класс ошибок.
- Cookie недоступна из Dart-кода — сессию нельзя случайно залогировать или утащить через XSS.
- `dio` на вебе обязан работать через browser-адаптер с `withCredentials: true`,
  иначе cookie не уйдёт. Это требование к фронтенду, а не рекомендация.
- Caddy становится обязательным звеном и в проде, и (желательно) в локальной разработке —
  иначе локально поведение отличается от боевого.
- Масштабировать фронт и API независимо (разные CDN, разные домены) станет сложнее.
  Для одного VPS это неактуально.

## Альтернативы

- **Разные домены + CORS.** Отвергнуто: третьесторонние куки ненадёжны, а хранение токена
  в `localStorage` открывает его для XSS.
- **Токен в заголовке `Authorization` для веба.** Отвергнуто как основной путь по той же
  причине. Но bearer-режим на сервере всё равно реализуется — он нужен будущему мобильному
  клиенту, см. [ADR-0002](./0002-oauth-through-backend.md).
