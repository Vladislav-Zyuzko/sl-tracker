# ADR-0007. Персональные токены доступа для машинных клиентов

- Дата: 2026-09-24
- Статус: принято
- Решает: пользователь; записал оркестратор
- Основание: `RFC-MCP-SERVER.md`, `SPEC-PAT-API.md`
- История: US-200 в `docs/product/stories/auth.md`

## Контекст

Рядом с трекером ставится внешний MCP-сервер `sl-tracker-mcp` — через него агенты
(dsh-term, Claude Code) работают с задачами: создают, читают, комментируют, меняют
статус и описание. Код этого сервера живёт вне репозитория трекера.

Функциональности API для этого уже достаточно: все пять операций и нужные справочники
существуют и описаны в OpenAPI. Не хватает ровно одного — **способа предъявить API
машинный доступ**. Сессию сегодня создаёт только OAuth-колбэк Яндекса (ADR-0002),
а он требует живого человека в браузере. Неинтерактивный клиент войти не может.

Рассматривались три пути: статический токен в переменных окружения трекера,
CLI-скрипт выпуска токенов на сервере и самообслуживаемые PAT-эндпоинты.

## Решение

**1. PAT — это сессия с назначением `pat`, а не новая сущность.**
В таблицу `sessions` добавлены три аддитивные колонки (`label`, `purpose`, `token_prefix`).
`SessionGuard` и `extractToken` не меняются вовсе: bearer-стратегия существует
с ADR-0002. Альтернатива — отдельная таблица `api_tokens` со своим путём проверки —
отвергнута: это второй механизм аутентификации в горячем пути запроса и дублирование
хеширования, кэша и семантики отзыва. Расширение `sessions` даёт то же одной миграцией.

**2. Отдельной машинной идентичности нет.** Токен принадлежит человеку-участнику
проекта, и объём его прав равен роли этого человека (`admin`/`member`/`reader`).
Ни пользователей, ни записей списка доступа, ни членства, ни ролей для агента
не заводится. Следствия приняты сознательно:

- скоуп токена не может разойтись с тем, что владелец видит в интерфейсе;
- задачи и комментарии подписаны человеком, выдавшим токен, — авторство честное;
- **токен даёт права человека целиком, включая необратимые действия**. Это и есть
  цена решения; она гасится сроком токена, видимым `lastSeenAt` и предохранителями
  на стороне MCP-сервера (`SL_MCP_READONLY`, allowlist очередей).

**3. Срок конечен, продления нет.** По умолчанию 365 дней, пресеты 30/90/365,
допустимо 1..3650. Бессрочных токенов не бывает: вечный секрет в конфиге — это то,
что потом забывают отозвать. Обычная сессия продлевается при использовании (30 дней
скользящим окном), PAT — нет: «тихое» продление токена, лежащего в env контейнера,
означало бы бессрочный доступ. `lastSeenAt` при этом обновляется — чтобы мёртвый
токен было видно в списке.

**4. Токеном нельзя управлять токенами.** `POST`, `GET` и `DELETE /api/tokens`
требуют браузерной cookie-сессии; запрос с PAT получает `403 pat_cannot_manage_tokens`.
Так утечка токена не размножается: украденным токеном нельзя ни выпустить новый,
ни отозвать существующие, ни даже перечислить их.

**5. Отзыв работает на двух уровнях.** `DELETE /api/tokens/{id}` гасит один токен.
Отзыв доступа человеку (ADR-0006) вызывает `destroyAllForUser` и гасит **все** его
сессии вместе с токенами — отдельный kill-switch для машинного доступа не нужен.

**6. Секрет показывается один раз.** В БД и в Redis лежит только HMAC-SHA256
от верификатора с `SESSION_SECRET`, как у обычной сессии. Восстановить токен нельзя
ни из дампа базы, ни через API. В списке виден только префикс — первые 8 символов,
он же начало идентификатора сессии; в проверке подлинности префикс не участвует.

## Последствия

- Машинный доступ появляется без новых механизмов аутентификации и без изменений
  в горячем пути проверки сессии.
- Выпуск первого токена возможен из интерфейса (профиль → Доступ → Токены доступа),
  без захода на сервер по SSH и без CLI-скриптов.
- Миграция безопасна на живой базе: только `ADD COLUMN` с дефолтом и новый enum-тип.
  Откат — возврат предыдущего образа API, схема остаётся совместимой.
- `lastSeenAt` обновляется не чаще раза в сутки (общий порог с обычными сессиями),
  поэтому «последний раз использован» имеет точность до суток. Это осознанный размен:
  иначе каждый запрос агента превращался бы в запись в PostgreSQL.
- Переменных окружения у трекера не прибавилось: настройки MCP-сервера живут
  в его собственном контейнере, а не в API.

## Что осталось за рамками

OAuth для MCP-сервера (RFC 9728, protected resource metadata), MCP-ресурсы и промпты,
локальный логин по паролю, выдача токена «за другого пользователя».
