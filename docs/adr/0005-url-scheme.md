# ADR-0005. Схема адресов приложения

- Дата: 2026-09-06
- Статус: принято
- Решает: оркестратор

## Контекст

Приложение за логином, SEO не нужен — но ссылки внутри команды ходят постоянно:
«посмотри DEV-42», «вот проект». Адреса должны быть читаемыми, стабильными
и работать при прямом заходе, а не только при переходе внутри приложения.

Flutter Web по умолчанию использует hash-стратегию (`/#/issues/DEV-42`). Это выглядит
как ссылка из 2010 года и мешает серверу понимать, что запрошено.

## Решение

**Path-стратегия, без `#`.** Во Flutter включается `usePathUrlStrategy()`.
Caddy отдаёт `index.html` на любой неизвестный путь, иначе перезагрузка страницы
на `/issues/DEV-42` вернёт 404.

**Карта адресов:**

| Адрес | Что открывает |
|---|---|
| `/` | Список моих проектов |
| `/projects/<slug>` | Проект: очереди, участники, настройки |
| `/queues/<KEY>` | Список задач очереди |
| `/issues/<KEY>-<N>` | Задача |
| `/invite/<token>` | Приём приглашения в проект |
| `/me` | Профиль и настройки уведомлений |
| `/api/*` | Проксируется в NestJS, приложением не обрабатывается |

**Проект адресуется slug'ом, а не id.** Ссылку на проект копируют и отправляют людям —
`/projects/sweet-limit` понятнее, чем `/projects/8f3a1c22-...`. Slug генерируется из названия,
уникален глобально, и **не меняется при переименовании проекта** — иначе уже отправленные
ссылки перестанут работать. Сменить slug можно только явным действием администратора,
с предупреждением, что старые ссылки сломаются.

**Задача адресуется ключом, а не id.** Ключ и так уникален глобально (см.
[ADR-0004](./0004-issue-keys.md)), поэтому проект в адресе задачи не нужен.

## Последствия

- Любой экран открывается по прямой ссылке и переживает F5. Это требование к фронтенду
  и к конфигурации Caddy одновременно — сломать можно с обеих сторон.
- `/api/*` зарезервирован. Ни один пользовательский маршрут не может начинаться с `/api`.
- Slug требует проверки уникальности при создании проекта и транслитерации кириллицы
  (проект «Сладкий лимит» → `sladkiy-limit`).
- Ключ очереди в адресе задачи означает, что смена очереди у задачи сменит адрес —
  ещё одна причина, по которой переноса между очередями в MVP нет.

## Альтернативы

- **Hash-роутинг** (`/#/issues/DEV-42`). Не требует настройки сервера, но адреса уродливы,
  и сервер не видит путь. Отвергнуто.
- **Проект в адресе задачи** (`/projects/alpha/issues/DEV-42`). Избыточно: ключ и так
  однозначен, а длинные адреса хуже читаются.
- **id вместо slug для проекта.** Проще (нет уникальности, нет транслитерации),
  но ссылка становится нечитаемой. Отвергнуто ради сценария «скинь ссылку на проект».
