Приглашения вынесены в отдельный файл: [invitations.md](./invitations.md).

## US-10. Список моих проектов

**Как** пользователь трекера
**я хочу** видеть все проекты, в которых я состою,
**чтобы** переключаться между направлениями работы.

*Если этого нет:* попасть в проект можно будет только по прямой ссылке.

### Критерии приёмки
- [ ] На главном экране показаны все проекты, где пользователь является участником
      (в любой роли), и только они.
- [ ] Карточка проекта показывает обложку (или заглушку, если обложки нет), название,
      число участников и роль текущего пользователя в этом проекте.
- [ ] Проекты, где пользователь не состоит, в списке отсутствуют, даже если он знает их адрес.
- [ ] Если проектов нет, показывается пустое состояние с кнопкой «Создать проект»
      и пояснением, что в чужой проект попадают по ссылке-приглашению.
- [ ] Список проектов доступен из сайдбара на любом экране приложения.

### Не входит в объём
- Избранные проекты, ручная сортировка, архив проектов, поиск по проектам.

## US-11. Создание проекта

**Как** пользователь
**я хочу** создать проект,
**чтобы** собрать в нём команду и задачи по направлению.

### Критерии приёмки
- [ ] Создать проект может любой пользователь, прошедший список доступа
      ([auth](./auth.md), US-05); отдельного права на создание проектов нет.
- [ ] Обязательное поле — название (1–100 символов). Описание и обложка необязательны
      и добавляются как при создании, так и позже.
- [ ] Создатель автоматически становится администратором проекта и единственным его участником.
- [ ] Сразу после создания пользователь попадает на страницу нового проекта, где видит
      подсказку следующего шага: создать очередь.
- [ ] Проект создаётся без очередей; список очередей показывает пустое состояние.
- [ ] Попытка создать проект с пустым названием блокируется с сообщением у поля;
      запрос на сервер не уходит.
- [ ] Одинаковые названия проектов у разных пользователей допустимы и не вызывают ошибку:
      различаются они коротким именем в адресе ([US-18](#us-18-короткое-имя-в-адресе-проекта)).
- [ ] При создании проект автоматически получает короткое имя в адресе, полученное
      из названия (US-18); отдельно вводить его при создании не требуется.

### Не входит в объём
- Шаблоны проектов, копирование проекта, импорт из других трекеров.
- Ограничение числа проектов на пользователя.

## US-12. Описание и обложка проекта

**Как** администратор проекта
**я хочу** добавить проекту описание и картинку,
**чтобы** новый участник понимал, куда попал, а проект узнавался в списке.

### Критерии приёмки
- [ ] Администратор может изменить название и описание проекта; описание — Markdown,
      до 5000 символов, отображается отрендеренным на странице проекта (правила разметки —
      [D-22](../decisions.md#d-22)).
- [ ] Администратор может загрузить обложку: один файл `image/png`, `image/jpeg` или
      `image/webp` размером до 5 МБ. Загрузка второй обложки заменяет предыдущую.
- [ ] Обложку можно удалить; тогда в списке и в шапке показывается заглушка.
- [ ] Файл неподдерживаемого типа или больше 5 МБ отклоняется с понятным сообщением
      («Допустимы PNG, JPEG, WEBP до 5 МБ»), прежняя обложка остаётся на месте.
- [ ] Участник и читатель видят описание и обложку, но не видят элементов редактирования;
      прямой вызов API на изменение возвращает 403.
- [ ] Обложка не открывается по прямой ссылке пользователем, не состоящим в проекте.

### Не входит в объём
- Кадрирование и редактирование изображения, галерея изображений проекта, цвет/иконка проекта
  вместо картинки.

## US-13. Копирование адреса проекта

**Как** участник проекта
**я хочу** скопировать адрес проекта одной кнопкой,
**чтобы** отправить его коллеге в чат.

*Если этого нет:* адрес копируют из строки браузера, что рождает ссылки с лишними параметрами
и путаницу со ссылкой-приглашением.

### Критерии приёмки
- [ ] На странице проекта есть кнопка «Скопировать адрес проекта», доступная всем участникам,
      включая читателя.
- [ ] Нажатие копирует в буфер обмена полный абсолютный адрес проекта
      (`https://<домен>/projects/<короткое-имя>`) и показывает подтверждение
      «Адрес скопирован». Адрес всегда содержит актуальное короткое имя.
- [ ] Рядом с кнопкой есть пояснение, что ссылка не даёт доступа и откроется только
      у участников проекта.
- [ ] Пользователь, не состоящий в проекте, перешедший по этому адресу, видит экран
      «Проект не найден» без каких-либо данных проекта (в том числе без названия).
- [ ] Кнопка «Скопировать адрес проекта» визуально отличима от кнопки создания
      ссылки-приглашения ([invitations](./invitations.md), US-20) — это разные вещи
      ([D-04](../decisions.md#d-04)).

### Не входит в объём
- Короткие ссылки, QR-код, кнопки «поделиться» в мессенджеры.

## US-14. Список участников проекта

**Как** участник проекта
**я хочу** видеть, кто в проекте и с какой ролью,
**чтобы** понимать, к кому идти и кого назначать исполнителем.

### Критерии приёмки
- [ ] На вкладке «Участники» показаны все участники: аватар, имя, email и роль.
- [ ] Список виден всем участникам проекта, включая читателя.
- [ ] Текущий пользователь помечен в списке.
- [ ] Указано, когда участник присоединился к проекту.
- [ ] Элементы управления (сменить роль, исключить) видны только администратору.

### Не входит в объём
- Поиск и фильтрация по списку участников (актуально при 50+ участниках, у нас 3–15).
- Группы участников, отделы.

## US-15. Изменение роли участника

**Как** администратор проекта
**я хочу** менять роль участника,
**чтобы** выдать права на управление или, наоборот, ограничить доступ до чтения.

### Критерии приёмки
- [ ] Администратор может изменить роль любого участника на администратор / участник / читатель.
- [ ] Изменение вступает в силу немедленно: у затронутого пользователя после следующего
      действия набор доступных операций соответствует новой роли.
- [ ] Понижение роли последнего администратора запрещено: действие блокируется с сообщением
      «В проекте должен остаться хотя бы один администратор», серверный ответ — 409.
- [ ] Администратор может понизить сам себя, если он не последний администратор; после этого
      элементы управления проектом исчезают без перезагрузки страницы.
- [ ] Участник и читатель не видят контролов смены роли; прямой вызов API возвращает 403.

### Не входит в объём
- Кастомные роли и точечная настройка прав.
- Журнал изменений состава участников (история ведётся только по задачам).

## US-16. Исключение участника и выход из проекта

**Как** администратор проекта
**я хочу** исключить человека из проекта,
**чтобы** после его ухода из команды закрыть доступ к рабочим задачам.

### Критерии приёмки
- [ ] Администратор может исключить любого участника, кроме последнего администратора.
- [ ] Исключение требует подтверждения в диалоге.
- [ ] После исключения пользователь теряет доступ немедленно: проект пропадает из его списка,
      прямой переход в проект и в его задачи даёт «не найдено».
- [ ] Задачи, где исключённый был исполнителем, остаются, поле «Исполнитель» очищается,
      в историю каждой такой задачи пишется запись об этом (подтверждено пользователем,
      [D-31](../decisions.md#d-31)).
- [ ] Поле «Автор» и авторство комментариев исключённого сохраняются; его имя и аватар
      продолжают отображаться.
- [ ] Любой участник может выйти из проекта сам; последний администратор выйти не может
      и получает сообщение с объяснением.
- [ ] Исключённого человека можно пригласить снова; при повторном вступлении он получает
      роль из нового приглашения, старая роль не восстанавливается автоматически.
- [ ] Исключение из проекта **не** закрывает человеку вход в трекер: он остаётся в списке
      доступа и после входа видит список проектов без этого проекта
      ([D-33](../decisions.md#d-33), вопрос Q16).
- [ ] Исключённый перестаёт появляться в подсказке упоминаний и в выборе исполнителя
      этого проекта.

### Не входит в объём
- Передача задач другому исполнителю при исключении (только очистка поля).
- Временная блокировка участника без исключения.

## US-17. Удаление проекта

**Как** администратор проекта
**я хочу** удалить проект,
**чтобы** убрать из трекера тестовый или закрытый проект.

### Критерии приёмки
- [ ] Удаление доступно только администратору проекта, из настроек проекта.
- [ ] Для подтверждения нужно ввести точное название проекта; пока введено не то, кнопка
      удаления неактивна.
- [ ] Диалог предупреждает, что будут удалены все очереди, задачи, комментарии и вложения,
      и что действие необратимо.
- [ ] После удаления проект исчезает из списков у всех участников; ссылки на его задачи
      возвращают «не найдено».
- [ ] Ключи очередей удалённого проекта остаются занятыми и не выдаются новым очередям
      ([D-25](../decisions.md#d-25)).
- [ ] Участник и читатель не видят раздела удаления; прямой вызов API возвращает 403.

### Не входит в объём
- Корзина и восстановление проекта силами пользователя.
- Архивирование проекта (скрыть, но сохранить) — кандидат в релиз 2.
- Экспорт данных проекта перед удалением.

## US-18. Короткое имя в адресе проекта

**Как** администратор проекта
**я хочу**, чтобы адрес проекта был читаемым и не ломался,
**чтобы** ссылку можно было отправить человеку, а после переименования проекта она
продолжала работать.

*Если этого нет:* адрес выглядит как `/projects/7f3a1c…` — такую ссылку неприятно отправлять
и невозможно узнать глазами; а если делать его из названия «на лету», разосланные ссылки
будут молча ломаться при каждом переименовании.

### Критерии приёмки
- [ ] Проект адресуется как `/projects/<короткое-имя>`; короткое имя состоит из строчных
      латинских букв, цифр и дефисов.
- [ ] При создании короткое имя формируется автоматически из названия проекта: кириллица
      транслитерируется латиницей, регистр приводится к нижнему, пробелы и знаки препинания
      заменяются дефисом, повторные дефисы схлопываются, крайние обрезаются, длина
      ограничена 40 символами. Проверяемо: «Сладкий Лимит 2026!» даёт `sladkiy-limit-2026`.
- [ ] Если из названия не получилось ни одного допустимого символа (название из эмодзи
      или знаков), выдаётся имя вида `project-7`.
- [ ] Короткое имя уникально на весь трекер; при совпадении добавляется числовой суффикс
      (`sweet-limit-2`), пользователь при создании этого не замечает.
- [ ] **Переименование проекта короткое имя не меняет**: адрес остаётся прежним,
      ранее отправленные ссылки продолжают работать.
- [ ] Администратор может изменить короткое имя вручную в настройках проекта; поле
      показывает предпросмотр итогового адреса и предупреждение о том, что адрес изменится.
- [ ] После смены короткого имени **старый адрес продолжает открывать проект**: переход
      по нему приводит на проект, адрес в строке браузера заменяется на актуальный.
- [ ] Прежние короткие имена проекта остаются занятыми и не могут достаться другому проекту.
- [ ] Занятое короткое имя при ручном вводе даёт ошибку «Такой адрес уже занят» без указания,
      каким проектом; серверный ответ — 409.
- [ ] Ввод недопустимых символов (кириллица, пробелы, заглавные буквы) в поле не принимается
      либо автоматически приводится к допустимому виду с показом результата.
- [ ] Короткое имя не может совпадать с системными адресами приложения (`issues`, `invite`,
      `projects`, `profile`, `api` и подобными) — такой ввод отклоняется.
- [ ] Участник и читатель не видят поле редактирования короткого имени; прямой вызов API
      возвращает 403.

### Не входит в объём
- Полностью произвольные адреса проекта (свой домен, адрес без префикса `/projects/`).
- Автоматическая смена короткого имени вслед за названием.
- Освобождение прежних коротких имён и их повторное использование.
- Аналогичный механизм для очередей: ключ очереди неизменяем ([D-06](../decisions.md#d-06)).
