# Приглашения в проект (US-20 … US-23)

Блок 3 MVP. Единственный способ добавить человека в проект ([D-03](../decisions.md#d-03)).
Не путать с адресом проекта ([projects](./projects.md), US-13) — это разные ссылки
([D-04](../decisions.md#d-04)).

---

## US-20. Создание ссылки-приглашения

**Как** администратор проекта
**я хочу** сгенерировать ссылку-приглашение с нужной ролью и сроком жизни,
**чтобы** позвать человека в проект, не заводя ему ничего вручную.

*Если этого нет:* в проекте навсегда остаётся один человек — его создатель.

### Критерии приёмки
- [ ] Создать ссылку-приглашение может только администратор проекта; участник и читатель
      не видят этот раздел, прямой вызов API возвращает 403.
- [ ] При создании администратор выбирает роль по умолчанию: участник или читатель.
      Роль «администратор» в списке отсутствует ([D-05](../decisions.md#d-05)).
- [ ] При создании администратор выбирает срок жизни: 1 день, 7 дней или 30 дней.
      Значение по умолчанию — 7 дней. Бессрочных приглашений нет.
- [ ] После создания ссылка сразу показана и копируется одной кнопкой; показывается
      подтверждение «Ссылка скопирована».
- [ ] Одна ссылка рассчитана на нескольких человек: по ней может вступить любое число
      пользователей, пока она действует и не отозвана.
- [ ] Одновременно у проекта может существовать несколько действующих приглашений
      (например, отдельное для участников и отдельное для читателей).
- [ ] Ссылка содержит непредсказуемый токен; по адресу проекта или его названию угадать
      приглашение невозможно.

### Не входит в объём
- Приглашение конкретного человека по email — требует почтового канала, релиз 2.
- Одноразовые приглашения и лимит числа использований.
- Приглашение сразу в роли администратора.

## US-21. Вступление в проект по ссылке-приглашению

**Как** человек, получивший ссылку-приглашение,
**я хочу** перейти по ней и оказаться в проекте,
**чтобы** начать работать без переписки с администратором.

### Критерии приёмки
- [ ] Пользователь без сессии, открывший ссылку-приглашение, проходит вход через Яндекс ID
      и после этого автоматически возвращается к обработке того же приглашения.
- [ ] Приглашение действует **в обход списка доступа**: человек, которого нет в списке,
      по действующей ссылке попадает в трекер ([D-33](../decisions.md#d-33), [auth](./auth.md) US-05).
- [ ] При принятии приглашения email вступившего добавляется в список доступа автоматически,
      с источником «приглашение»; при следующих входах ссылка-приглашение ему уже не нужна.
- [ ] Перед вступлением показывается экран подтверждения: название проекта, обложка,
      роль, которую он получит, и кнопка «Присоединиться».
- [ ] После подтверждения пользователь становится участником проекта с ролью из приглашения
      и попадает на страницу проекта.
- [ ] Пользователь, уже состоящий в проекте, при переходе по ссылке попадает на страницу
      проекта; его текущая роль не меняется (в том числе не понижается).
- [ ] Просроченная или отозванная ссылка показывает экран «Приглашение больше не действует»
      с предложением попросить новую ссылку; членство не выдаётся.
- [ ] Если по просроченной ссылке пришёл человек, которого нет в списке доступа, он не попадает
      в трекер и видит экран «Доступ к трекеру закрыт» ([auth](./auth.md), US-05):
      просроченное приглашение доступа не даёт.
- [ ] Неизвестный токен показывает «Приглашение не найдено»; по сообщению нельзя понять,
      существует ли такой проект.
- [ ] Экран подтверждения не раскрывает содержимое проекта: видны только название, обложка
      и роль — ни задач, ни списка участников.
- [ ] Новый участник появляется в списке участников проекта без перезагрузки страницы
      у администратора, открывшего этот список (в пределах 5 секунд, [D-26](../decisions.md#d-26)).
- [ ] *(релиз 2, [D-42](../decisions.md#d-42) — в поставленном MVP не выполняется)*
      Массовый онбординг не упирается в защиту от перебора: **15 человек, выходящих
      в интернет через один сетевой адрес, принимают свои приглашения в течение одной минуты,
      и ни один не получает отказ «слишком много попыток»**. Подбор несуществующего токена
      при этом по-прежнему упирается в отказ. Сегодня счёт идёт по сетевому адресу, порог —
      20 попыток в минуту на адрес, то есть за общим NAT отказ возможен.

### Не входит в объём
- Заявки на вступление с подтверждением администратором.
- Автоматическое вступление по email-домену компании.
- Ограничение числа вступлений по одной ссылке (приглашение многоразовое по замыслу).

## US-22. Просмотр и отзыв приглашений

**Как** администратор проекта
**я хочу** видеть действующие приглашения и отзывать их,
**чтобы** закрыть доступ, если ссылка утекла.

### Критерии приёмки
- [ ] Администратор видит список приглашений проекта: кто создал, когда, роль, срок действия,
      состояние (действует / истекло / отозвано) и сколько человек по нему вступили.
- [ ] Администратор может отозвать любое действующее приглашение проекта, в том числе
      созданное другим администратором.
- [ ] Сразу после отзыва переход по этой ссылке даёт «Приглашение больше не действует»;
      серверный ответ — 410.
- [ ] Отзыв приглашения не затрагивает тех, кто уже вступил по нему: они остаются участниками.
- [ ] Истёкшие и отозванные приглашения остаются в списке (видно, что они были), но повторно
      активировать их нельзя.
- [ ] Полный текст ссылки для действующего приглашения можно скопировать повторно из списка.

### Не входит в объём
- Уведомление администратору о каждом использовании приглашения.
- Отзыв доступа у всех, кто вступил по конкретной ссылке, одним действием.

## US-23. Уведомление о новом участнике

**Как** администратор проекта
**я хочу** узнавать, что в проект кто-то вступил,
**чтобы** сразу назначить человеку работу и заметить чужого.

### Критерии приёмки
- [ ] При вступлении нового участника все администраторы проекта получают in-app уведомление
      «<Имя> присоединился к проекту <Название>».
- [ ] Уведомление не приходит тому, кто вступил, и обычным участникам и читателям.
- [ ] Нажатие на уведомление открывает список участников проекта.
- [ ] Тип уведомления можно отключить в настройках профиля
      (см. [notifications](./notifications.md), US-103).

### Не входит в объём
- Письмо на почту — в MVP канала email нет ([D-18](../decisions.md#d-18)).
