# Задачи: создание, просмотр, содержимое (US-40 … US-48)

Блоки 5 и 8 MVP. Поля задачи (статус, приоритет, сложность, автор, исполнитель) вынесены
в [issue-fields.md](./issue-fields.md), смена статуса — в [workflow.md](./workflow.md).

---

## US-40. Создание задачи и генерация ключа

**Как** участник проекта
**я хочу** создать задачу в очереди,
**чтобы** зафиксировать работу и не потерять её.

*Если этого нет:* продукта не существует.

### Критерии приёмки
- [ ] Создать задачу могут администратор и участник проекта; читатель — нет (кнопки не видит,
      прямой вызов API возвращает 403).
- [ ] Обязательное поле одно — название (1–255 символов). Всё остальное можно заполнить позже.
- [ ] При создании задача получает ключ `<КЛЮЧ_ОЧЕРЕДИ>-<НОМЕР>`, где номер — следующий
      по возрастанию в этой очереди. Первая задача очереди `DEV` получает ключ `DEV-1`.
- [ ] Номера не повторяются внутри очереди никогда, в том числе после удаления задач;
      пропуски в нумерации допустимы ([D-07](../decisions.md#d-07)).
- [ ] При одновременном создании двух задач в одной очереди двумя пользователями выдаются
      разные номера; проверяемо: 50 параллельных созданий дают 50 различных ключей.
- [ ] Значения по умолчанию у новой задачи: статус — первый статус очереди («Открыт»),
      приоритет — 50, сложность — не задана, автор — создатель, исполнитель — не назначен.
- [ ] После создания пользователь попадает на страницу задачи и видит её ключ.
- [ ] В историю задачи пишется запись о создании с указанием создателя и времени
      ([history](./history.md)).
- [ ] Задачу можно создать двумя путями: из списка очереди и из общей кнопки «Создать задачу»,
      где очередь выбирается из списка доступных пользователю очередей.

### Не входит в объём
- Тип задачи, подзадачи, связи между задачами, шаблоны описания ([D-23](../decisions.md#d-23)).
- Создание задачи по email или из внешних систем.
- Черновики задач.

## US-41. Просмотр задачи по ключу

**Как** участник проекта, получивший ссылку в чате,
**я хочу** открыть задачу по её ключу,
**чтобы** сразу увидеть, о чём речь.

### Критерии приёмки
- [ ] Задача открывается по адресу `/issues/DEV-42`; адрес не содержит идентификаторов
      проекта и очереди.
- [ ] Ключ в адресе нечувствителен к регистру: `/issues/dev-42` открывает ту же задачу.
- [ ] На странице задачи видны: ключ, название, описание, вложения, ссылки, комментарии,
      история и панель полей.
- [ ] Хлебные крошки показывают проект и очередь и позволяют перейти к ним.
- [ ] Ключ задачи можно скопировать одной кнопкой; отдельной кнопкой копируется полный адрес
      задачи.
- [ ] Пользователь, не состоящий в проекте, видит «Задача не найдена» без каких-либо данных
      задачи (в том числе без названия); серверный ответ — 404.
- [ ] Несуществующий ключ (`DEV-9999`) даёт то же самое «Задача не найдена».
- [ ] Читатель видит задачу полностью, но без контролов изменения.

### Не входит в объём
- Печать и экспорт задачи, постоянные короткие ссылки помимо ключа.
- Открытие задачи в модальном окне поверх списка.

## US-42. Название задачи

**Как** участник проекта
**я хочу** править название задачи,
**чтобы** формулировка отражала суть работы.

### Критерии приёмки
- [ ] Название редактируется прямо на странице задачи администратором и участником проекта
      (в том числе у чужой задачи, [D-11](../decisions.md#d-11)).
- [ ] Пустое название сохранить нельзя; при попытке показывается ошибка, прежнее значение
      остаётся.
- [ ] Длина ограничена 255 символами; ввод сверх лимита не принимается, счётчик остатка виден.
- [ ] Изменение названия попадает в историю: кто, когда, старое и новое значение.
- [ ] Читатель не видит возможности редактирования; прямой вызов API возвращает 403.

### Не входит в объём
- Форматирование в названии (только простой текст).

## US-43. Описание задачи в Markdown

**Как** участник проекта
**я хочу** описывать задачу в Markdown и видеть готовую разметку,
**чтобы** оформлять требования списками, кодом и ссылками.

### Критерии приёмки
- [ ] Описание вводится как Markdown; при просмотре задачи оно показано отрендеренным,
      без «сырых» символов разметки.
- [ ] Поддерживаются: заголовки, жирный, курсив, зачёркнутый, маркированные и нумерованные
      списки, чек-листы, ссылки, строчный код и блоки кода, цитаты, горизонтальная линия,
      таблицы, изображения по URL ([D-22](../decisions.md#d-22)).
- [ ] Сырой HTML в описании не исполняется и не отображается как разметка; вставка
      `<script>alert(1)</script>` выводится как текст либо вырезается — но не выполняется.
- [ ] Ссылки со схемами, отличными от `http`, `https`, `mailto` (например, `javascript:`),
      не превращаются в кликабельные ссылки.
- [ ] Внешние ссылки в описании открываются в новой вкладке.
- [ ] У редактора есть режим предпросмотра или живой рендер (решает дизайнер) и подсказка
      по синтаксису Markdown.
- [ ] В описании работают упоминания участников через `@` по тем же правилам, что
      и в комментариях ([comments](./comments.md), US-74).
- [ ] Незавершённое редактирование не теряется при случайном закрытии редактора: показывается
      подтверждение «Отменить изменения?».
- [ ] Изменение описания попадает в историю как факт изменения (кто и когда); полные тексты
      старой и новой версии в истории не показываются ([history](./history.md), US-91).
- [ ] Если во время редактирования описание изменил другой пользователь, при сохранении
      показывается предупреждение и выбор — перезаписать или отменить
      ([D-27](../decisions.md#d-27)).
- [ ] Ограничение длины — 100 000 символов.

### Не входит в объём
- WYSIWYG-редактор и вставка изображения перетаскиванием прямо в текст (изображения
  прикладываются как вложения, US-46).
- Автоссылки на другие задачи по ключу и поповер превью — релиз 2
  ([D-38](../decisions.md#d-38)): текст `DEV-42` в описании остаётся обычным текстом.
- Версионирование описания и просмотр старых версий.

## US-44. Удаление задачи

**Как** администратор проекта
**я хочу** удалить ошибочно созданную задачу,
**чтобы** она не мешала в списках.

### Критерии приёмки
- [ ] Удалять задачи может только администратор проекта ([D-12](../decisions.md#d-12));
      участник и читатель не видят пункт удаления, прямой вызов API возвращает 403.
- [ ] Удаление требует подтверждения; диалог предупреждает, что комментарии и вложения
      будут удалены и действие необратимо.
- [ ] После удаления ссылка на задачу отдаёт «Задача не найдена».
- [ ] Номер удалённой задачи не переиспользуется.
- [ ] Задача исчезает из сайдбара активных задач у своего исполнителя.

### Не входит в объём
- Корзина и восстановление задачи.
- Массовое удаление.

## US-45. Свежесть данных на странице задачи

**Как** участник, обсуждающий задачу вместе с коллегой,
**я хочу** видеть чужие изменения без перезагрузки,
**чтобы** не спорить с устаревшим экраном.

### Критерии приёмки
- [ ] Если другой пользователь изменил статус, исполнителя, приоритет, сложность или автора,
      изменение отображается на открытой странице задачи не позднее чем через 5 секунд
      без действий пользователя ([D-26](../decisions.md#d-26)).
- [ ] Новый комментарий появляется в ленте открытой задачи в тот же срок.
- [ ] Обновление не сбрасывает текст, который пользователь набирает в поле комментария,
      и не закрывает открытый редактор описания.

### Не входит в объём
- Индикатор «пользователь сейчас смотрит задачу» и «печатает…».
- Живое обновление списков задач и сайдбара (обновляются при открытии/переходе).

## US-46. Вложения

**Как** участник проекта
**я хочу** прикладывать к задаче файлы и скриншоты,
**чтобы** не пересказывать словами то, что видно на картинке.

### Критерии приёмки
- [ ] Администратор и участник могут приложить к задаче файл любого типа размером до 25 МБ
      ([D-21](../decisions.md#d-21)).
- [ ] Файл можно приложить и выбором из диалога, и перетаскиванием на область задачи.
- [ ] Можно приложить несколько файлов за раз; для каждого показывается прогресс загрузки.
- [ ] Файл больше 25 МБ отклоняется с сообщением «Файл больше 25 МБ», остальные файлы
      из выбранных загружаются.
- [ ] Изображения (`png`, `jpeg`, `webp`, `gif`) показываются превью в задаче; нажатие
      открывает изображение в полном размере.
- [ ] Остальные файлы показываются списком: имя, размер, кто и когда приложил, кнопка скачать.
- [ ] Вложение доступно только участникам проекта: открытие ссылки на файл в браузере
      без сессии или под пользователем не из проекта не отдаёт содержимое.
- [ ] Удалить вложение может администратор проекта или тот, кто его приложил; читатель —
      нет, участник не может удалить чужое вложение.
- [ ] Добавление и удаление вложения попадает в историю задачи (имя файла, кто, когда).
- [ ] При ошибке загрузки показывается сообщение и возможность повторить; частично
      загруженный файл не появляется в списке.

### Не входит в объём
- Проверка файлов антивирусом и ограничение по типам. Общей квоты на проект нет — подтверждено
  пользователем, лимит только на файл ([D-21](../decisions.md#d-21)).
- Версии одного файла, редактирование изображений, галерея-просмотрщик со стрелками.
- Вложения к комментариям (в MVP файлы прикладываются к задаче, не к комментарию).

## US-47. Внешние ссылки в задаче

**Как** участник проекта
**я хочу** приложить к задаче ссылки на макет, документ или страницу,
**чтобы** не искать их потом в переписке.

### Критерии приёмки
- [ ] Администратор и участник могут добавить к задаче ссылку: адрес (обязательно)
      и подпись (необязательно, до 100 символов; при пустой подписи показывается сам адрес).
- [ ] Принимаются только адреса со схемой `http` или `https`; остальные отклоняются
      с сообщением.
- [ ] Ссылки показаны на странице задачи отдельным блоком и открываются в новой вкладке.
- [ ] Ссылку можно удалить; удалить может администратор или любой участник проекта.
- [ ] Добавление и удаление ссылки попадает в историю задачи.
- [ ] Число ссылок на задачу не ограничено; при большом количестве блок остаётся читаемым
      (решение по отображению — за дизайнером).

### Не входит в объём
- Автоматическое получение заголовка и превью страницы по ссылке.
- Связи между задачами трекера (это другая сущность, релиз 3) — здесь только внешние адреса.

## US-48. Пустые и ошибочные состояния задачи

**Как** пользователь
**я хочу** понимать, что происходит, когда данных нет или что-то сломалось,
**чтобы** не считать продукт сломанным.

### Критерии приёмки
- [ ] Задача без описания показывает пустое состояние с приглашением добавить описание
      (у тех, кому это разрешено).
- [ ] Задача без вложений и ссылок не показывает пустые блоки — только контролы добавления.
- [ ] Задача без комментариев показывает «Комментариев пока нет».
- [ ] При потере соединения страница задачи показывает уведомление о том, что данные могут
      быть устаревшими, и предлагает повторить загрузку; ранее загруженные данные остаются
      на экране.
- [ ] Ошибка сохранения любого поля не приводит к молчаливой потере: показывается сообщение
      об ошибке, значение в интерфейсе возвращается к последнему сохранённому.

### Не входит в объём
- Полноценная офлайн-работа и очередь отложенных изменений.
