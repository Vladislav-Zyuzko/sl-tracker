# Статусы и смена статуса (US-60 … US-61)

Блок 7 MVP. Статусы хранятся данными на уровне очереди ([D-08](../decisions.md#d-08)),
переходы в MVP свободные ([D-10](../decisions.md#d-10)).

---

## US-60. Статусы очереди по умолчанию

**Как** администратор, создавший очередь,
**я хочу** сразу иметь готовый набор статусов,
**чтобы** начать работать, ничего не настраивая.

*Если этого нет:* новая очередь бесполезна — задачу некуда двигать.

### Критерии приёмки
- [ ] При создании очереди в ней автоматически создаются пять статусов в фиксированном
      порядке: Открыт, В работе, Ревью, Тестирование, Закрыт.
- [ ] Каждый статус имеет категорию: «Открыт» — `open`; «В работе», «Ревью», «Тестирование» —
      `in_progress`; «Закрыт» — `done` ([D-09](../decisions.md#d-09)).
- [ ] Статусы принадлежат конкретной очереди: изменение статусов одной очереди в будущем
      не затронет другие (проверяется на уровне данных, UI редактирования в MVP нет).
- [ ] Первый статус очереди («Открыт») используется как статус новой задачи по умолчанию.
- [ ] Порядок статусов одинаков во всех местах интерфейса: в панели задачи, в фильтре списка
      задач, в истории.
- [ ] Пользователь не может создать, переименовать, переупорядочить или удалить статус —
      таких экранов и операций API в MVP нет.

### Не входит в объём
- Редактор статусов очереди — релиз 3.
- Свои категории статусов, статусы уровня проекта, разные наборы статусов для разных
  типов задач.

---

## US-61. Смена статуса задачи

**Как** участник проекта
**я хочу** менять статус задачи выпадающим списком,
**чтобы** команда видела актуальное состояние работы.

### Критерии приёмки
- [ ] Статус меняется выпадающим списком в панели задачи; в списке присутствуют все пять
      статусов очереди, к которой принадлежит задача.
- [ ] Переход разрешён из любого статуса в любой другой, включая возврат назад
      (например, из «Тестирование» в «В работе») и закрытие из любого статуса.
- [ ] Текущий статус отмечен в списке; выбор текущего статуса повторно не создаёт запись
      в истории и не шлёт уведомлений.
- [ ] Смена статуса сохраняется сразу и создаёт запись в истории: кто, когда, с какого
      на какой ([history](./history.md)).
- [ ] Смена статуса задачи создаёт уведомление для подписчиков задачи, кроме того, кто
      её изменил ([notifications](./notifications.md), US-101).
- [ ] Менять статус могут администратор и участник проекта, в том числе у чужой задачи.
      Читатель не видит выпадающий список (видит статус как текст) и получает 403
      при прямом вызове API.
- [ ] Перевод задачи в статус категории `done` («Закрыт») убирает её из сайдбара активных
      задач исполнителя; возврат в любой другой статус возвращает её туда
      ([sidebar](./sidebar.md), [D-19](../decisions.md#d-19)).
- [ ] Изменение статуса, сделанное другим пользователем, отображается на открытой странице
      задачи не позднее чем через 5 секунд без перезагрузки ([D-26](../decisions.md#d-26)).
- [ ] Статус отображается в списке задач очереди и доступен там как фильтр.

### Не входит в объём
- Ограничения переходов (граф воркфлоу), обязательные поля и комментарий при переходе,
  ограничение перехода по роли — релиз 3.
- Автоматические переходы (например, «в работу» при назначении исполнителя).
- Резолюция при закрытии («Выполнено» / «Отменено») — отдельное поле, вне MVP.
- Массовая смена статуса у нескольких задач.
