# Уведомления (US-100 … US-103)

Блок 12 MVP. Принцип: **тишина по умолчанию лучше спама** — уведомляем только о том,
что касается пользователя лично. В MVP канал один — in-app ([D-18](../decisions.md#d-18),
подтверждено пользователем).

Подписка на задачу неявная ([D-17](../decisions.md#d-17)): подписчики задачи — её создатель,
текущий автор, текущий исполнитель, все, кто оставил хотя бы один комментарий, и все,
кого в ней упомянули.

---

## US-100. Уведомление о назначении на меня

**Как** участник команды
**я хочу** узнавать, что на меня назначили задачу,
**чтобы** не пропустить работу, о которой мне не сказали в чате.

*Если этого нет:* назначение задачи становится бессмысленным — человек о нём не узнает.

### Критерии приёмки
- [ ] При назначении пользователя исполнителем задачи он получает уведомление
      «<Имя> назначил вас исполнителем задачи <КЛЮЧ>: <название>».
- [ ] Назначение самого себя уведомления не создаёт.
- [ ] При смене автора задачи новый автор получает уведомление «<Имя> указал вас автором
      задачи <КЛЮЧ>»; назначение себя автором уведомления не создаёт.
- [ ] Снятие пользователя с задачи (замена исполнителя на другого или на «не назначен»)
      уведомления **не** создаёт.
- [ ] Нажатие на уведомление открывает соответствующую задачу.

### Не входит в объём
- Письмо и push-уведомление — канала email в MVP нет ([D-18](../decisions.md#d-18)).
- Напоминания о задачах, по которым долго нет движения.

## US-101. Уведомление об изменении моей задачи

**Как** автор, исполнитель или участник обсуждения задачи
**я хочу** узнавать о смене её статуса,
**чтобы** вовремя подхватить работу (например, забрать задачу на тестирование).

### Критерии приёмки
- [ ] При смене статуса задачи уведомление получают все подписчики задачи, кроме того,
      кто выполнил изменение.
- [ ] Текст уведомления содержит ключ задачи, название и переход статусов:
      «<Имя> перевёл <КЛЮЧ> из «В работе» в «Ревью»».
- [ ] Изменение приоритета, сложности, названия, описания, вложений и ссылок уведомлений
      **не** создаёт — эти изменения видны в истории.
- [ ] Пользователь не получает уведомлений о собственных действиях ни в каком случае.
- [ ] Один пользователь получает не более одного уведомления на одно событие, даже если
      он одновременно автор, исполнитель и комментатор задачи.

### Не входит в объём
- Уведомления обо всех изменениях подряд, дайджест изменений за день.
- Настройка уведомлений на уровне отдельной задачи (кнопка «не следить») — релиз 2.

## US-102. Уведомление о новом комментарии

**Как** участник обсуждения
**я хочу** узнавать о новых комментариях к задачам, которые меня касаются,
**чтобы** отвечать на вопросы, а не находить их через неделю.

### Критерии приёмки
- [ ] При добавлении комментария уведомление получают все подписчики задачи, кроме автора
      комментария.
- [ ] Уведомление содержит ключ задачи, имя автора комментария и начало текста
      (первые ~100 символов, разметка Markdown в превью не отображается как символы).
- [ ] Нажатие открывает задачу и прокручивает её к этому комментарию.
- [ ] Удаление или редактирование комментария уже отправленное уведомление не изменяет
      и новых не создаёт; при переходе к удалённому комментарию открывается задача,
      и показывается сообщение, что комментарий удалён.

### Не входит в объём
- Ничего: упоминания вынесены в отдельную историю US-104.
- Ответ на комментарий прямо из центра уведомлений.

## US-103. Центр уведомлений и настройки подписки

**Как** пользователь
**я хочу** видеть все свои уведомления в одном месте и отключать лишние,
**чтобы** трекер не превратился в источник шума.

### Критерии приёмки
- [ ] В шапке приложения есть значок уведомлений со счётчиком непрочитанных; счётчик
      обновляется без перезагрузки страницы не позднее чем через 5 секунд после события
      ([D-26](../decisions.md#d-26)).
- [ ] Счётчик показывает точное число до 99, далее «99+».
- [ ] В центре уведомлений показан список: тип события, задача, кто инициировал, время;
      непрочитанные визуально отличаются от прочитанных.
- [ ] Уведомление помечается прочитанным при переходе по нему; есть действие
      «Отметить все как прочитанные».
- [ ] Уведомления хранятся не менее 30 дней и подгружаются порциями.
- [ ] В настройках профиля можно включить и выключить каждый тип уведомлений отдельно:
      назначен исполнителем; назначен автором; **упомянули в тексте**; смена статуса задачи,
      на которую я подписан; новый комментарий к задаче, на которую я подписан;
      новый участник проекта (только для администраторов).
- [ ] По умолчанию включены все типы.
- [ ] Отключённый тип не создаёт ни записи в центре уведомлений, ни увеличения счётчика.
- [ ] Пользователь видит только свои уведомления; чужие недоступны ни в UI, ни через API.
- [ ] Уведомления по задачам проекта, из которого пользователя исключили, перестают
      приходить; уже полученные остаются в списке, но переход по ним показывает
      «Задача не найдена».
- [ ] Настройки уведомлений хранятся так, что добавление канала email не потребует
      перенастройки пользователем ([D-18](../decisions.md#d-18)).

### Не входит в объём
- Email-канал, push, интеграции с мессенджерами — решение пользователя: в MVP только in-app.
- Режим «не беспокоить», расписание и часы тишины, дайджесты.
- Настройка уведомлений отдельно по каждому проекту.

## US-104. Уведомление об упоминании

**Как** человек, которого позвали в обсуждение,
**я хочу** получить уведомление, когда меня упомянули,
**чтобы** ответить на вопрос, адресованный лично мне.

*Если этого нет:* упоминание превращается в декоративную подсветку — адресат о нём не узнает.

### Критерии приёмки
- [ ] Упоминание участника в комментарии или в описании задачи ([comments](./comments.md), US-74)
      создаёт уведомление упомянутому: «<Имя> упомянул вас в задаче <КЛЮЧ>».
- [ ] Уведомление содержит начало текста, в котором находится упоминание (первые ~100 символов).
- [ ] Нажатие открывает задачу и прокручивает к комментарию с упоминанием; для упоминания
      в описании — к описанию задачи.
- [ ] Упоминание самого себя уведомления не создаёт.
- [ ] Если человек упомянут в комментарии и одновременно является подписчиком задачи,
      он получает **одно** уведомление — об упоминании, а не два.
- [ ] Уведомление об упоминании приходит независимо от того, отключён ли у пользователя тип
      «новый комментарий»: это разные типы, каждый отключается отдельно.
- [ ] Отключённый тип «упомянули в тексте» не создаёт ни записи, ни увеличения счётчика.
- [ ] Уведомление не создаётся, если упомянутый на момент отправки уже не участник проекта.

### Не входит в объём
- Отдельная вкладка «Упоминания» в центре уведомлений.
- Уведомление об удалении упоминания или о правке текста, где было упоминание.
- Ответ на упоминание прямо из центра уведомлений.
