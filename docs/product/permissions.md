# Модель прав доступа

> Это нормативный документ для бэкенда. Если поведение не описано здесь — его нельзя
> «додумать», нужно спросить PM. Термины — из [glossary.md](./glossary.md).

## 1. Базовые правила

0. **Два уровня доступа.** Сначала решается, пускать ли человека в трекер вообще
   (**список доступа**, раздел 1.1), и только потом — что ему можно внутри проекта (роль).
   Прохождение аутентификации в Яндекс ID не означает доступа к трекеру.
1. **Единица доступа внутри трекера — проект.** Пользователь либо участник проекта (с ролью), либо не имеет
   к нему никакого отношения. Промежуточных состояний нет.
2. **Роль одна на проект.** У пользователя ровно одна роль в конкретном проекте:
   администратор, участник, читатель. Роли не суммируются.
3. **Права наследуются вниз по иерархии.** Роль в проекте определяет права во всех его
   очередях и задачах. Прав на уровне отдельной очереди или задачи в MVP нет.
4. **Глобальная роль ровно одна — владелец трекера.** Она даёт единственное право:
   управлять списком доступа ([D-39](./decisions.md#d-39)). Ни к одному проекту доступа
   она не даёт. Все остальные права — только проектные. Любой пользователь, прошедший список
   доступа, может создать проект и станет его администратором.
5. **Невидимость вместо запрета.** Не-участник проекта не должен узнать о существовании
   проекта, очереди или задачи. Ответ на любой запрос к чужому объекту — `404`, а не `403`.
   `403` возвращается только когда пользователь **видит** объект, но действие ему не разрешено
   (например, читатель меняет статус).
6. **Права проверяются на сервере.** Скрытие контрола в UI — удобство, а не защита. Для каждой
   строки матрицы должен существовать серверный отказ.
7. **В проекте всегда есть минимум один администратор.** Последнего администратора нельзя
   ни разжаловать, ни исключить, ни удалить его членство.

### 1.1. Доступ в трекер (уровень 0)

Пользователь допускается внутрь приложения, если выполняется хотя бы одно условие:

| Условие | Как появляется запись | Источник записи | Кто управляет |
|---|---|---|---|
| Email есть в списке доступа с начала жизни инстанса | Начальное наполнение из конфигурации инстанса | `config` | Владелец инстанса при развёртывании; такие записи автоматически получают признак владельца трекера |
| Владелец трекера добавил адрес на экране управления доступом | Ручное добавление | `manual` | Владелец трекера |
| Пользователь принял действующее приглашение | Создаётся автоматически при вступлении в проект | `invitation` | Администратор проекта — тем, что выдал приглашение |

Правила:

- Пользователь, прошедший Яндекс ID, но не удовлетворяющий ни одному условию, **не получает
  сессию** и видит экран «Доступ к трекеру закрыт». Учётная запись в трекере для него
  не создаётся.
- Ссылка-приглашение действует **в обход** списка доступа — иначе механизм приглашений
  бессмыслен: пригласить нового человека было бы невозможно.
- Попадание в список доступа само по себе не даёт доступа ни к одному проекту: человек
  видит пустой список проектов и свой профиль.
- Исключение из всех проектов **не** удаляет запись из списка доступа: человек по-прежнему
  может войти и увидеть пустой список проектов. Чтобы закрыть вход, владелец трекера отзывает
  доступ — удаляет запись из списка ([D-40](./decisions.md#d-40)).
- **Отзыв доступа немедленно завершает все активные сессии** этого пользователя. Данные
  (комментарии, история, авторство) и членство в проектах при этом сохраняются.

### 1.2. Управление списком доступа (глобальное право)

Обозначения те же, что в разделе 2.

| Действие | Владелец трекера | Пользователь с доступом | Нет доступа |
|---|:--:|:--:|:--:|
| Видеть экран «Доступ в трекер» и список записей | + | − (пункт меню отсутствует, API — 403) | − (401) |
| Добавить адрес в список доступа | + | − | − |
| Удалить запись (отозвать доступ) | + | − | − |
| Выдать или снять признак владельца трекера | + | − | − |
| Удалить собственную запись | − (нельзя удалить себя, [D-39](./decisions.md#d-39)) | − | − |
| Снять признак владельца с последнего владельца | − (в трекере всегда есть хотя бы один владелец) | − | − |

Владелец трекера **не получает** никаких прав внутри проектов: не видит чужие проекты,
не читает их задачи, не может добавить себя в проект. Чтобы работать с проектом, он должен
быть его участником на общих основаниях.

## 2. Матрица «роль × действие»

Обозначения: **+** разрешено, **−** запрещено, **С** разрешено только для собственного объекта
(создан этим пользователем).

Колонка «Не участник» — пользователь, прошедший список доступа (раздел 1.1), но не состоящий
в этом проекте.

### 2.1. Проект

| Действие | Админ | Участник | Читатель | Не участник |
|---|:--:|:--:|:--:|:--:|
| Создать проект | — (действие вне проекта: доступно любому пользователю, прошедшему список доступа; создатель становится администратором) ||||
| Видеть проект в списке «Мои проекты» | + | + | + | − |
| Открыть страницу проекта | + | + | + | − (404) |
| Скопировать адрес проекта | + | + | + | − |
| Изменить название и описание | + | − | − | − |
| Изменить короткое имя в адресе (slug) | + | − | − | − |
| Загрузить/заменить/удалить обложку | + | − | − | − |
| Удалить проект | + | − | − | − |

### 2.2. Участники и приглашения

| Действие | Админ | Участник | Читатель | Не участник |
|---|:--:|:--:|:--:|:--:|
| Видеть список участников и их роли | + | + | + | − |
| Создать ссылку-приглашение | + | − | − | − |
| Видеть активные приглашения и их использования | + | − | − | − |
| Отозвать приглашение | + | − | − | − |
| Принять приглашение по ссылке | — (действие вне проекта: доступно любому вошедшему через Яндекс ID с действующим токеном, **в том числе тому, кого нет в списке доступа**) ||||
| Изменить роль участника | + | − | − | − |
| Исключить участника из проекта | + | − | − | − |
| Выйти из проекта самостоятельно | + (если он не последний администратор) | + | + | − |

### 2.3. Очередь

| Действие | Админ | Участник | Читатель | Не участник |
|---|:--:|:--:|:--:|:--:|
| Видеть список очередей проекта | + | + | + | − |
| Открыть очередь и список её задач | + | + | + | − (404) |
| Создать очередь | + | − | − | − |
| Переименовать очередь (название, описание) | + | − | − | − |
| Изменить ключ очереди | — (запрещено всем: ключ неизменяем, [D-06](./decisions.md#d-06)) ||||
| Удалить очередь | + (только пустую) | − | − | − |

### 2.4. Задача

| Действие | Админ | Участник | Читатель | Не участник |
|---|:--:|:--:|:--:|:--:|
| Открыть задачу по ключу | + | + | + | − (404) |
| Создать задачу | + | + | − | − |
| Изменить название и описание (в т.ч. чужой задачи) | + | + | − | − |
| Изменить статус | + | + | − | − |
| Изменить приоритет и сложность | + | + | − | − |
| Назначить/сменить исполнителя (в т.ч. себя) | + | + | − | − |
| Изменить автора | + | + | − | − |
| Добавить вложение | + | + | − | − |
| Удалить вложение | + | С | − | − |
| Добавить внешнюю ссылку | + | + | − | − |
| Удалить внешнюю ссылку | + | + | − | − |
| Удалить задачу | + | − | − | − |
| Смотреть историю изменений | + | + | + | − |

Пояснение: участник может менять **любую** задачу проекта, а не только свою. Трекер малой
команды — среда высокого доверия; ограничение «только свои задачи» ломает базовый сценарий
«подхватил чужую работу» ([D-11](./decisions.md#d-11)).

### 2.5. Комментарии

| Действие | Админ | Участник | Читатель | Не участник |
|---|:--:|:--:|:--:|:--:|
| Читать комментарии | + | + | + | − |
| Написать комментарий | + | + | − | − |
| Упомянуть участника (`@`) в комментарии или описании | + | + | − (не создаёт текстов) | − |
| Быть упомянутым | + | + | + | − (нельзя упомянуть не-участника) |
| Редактировать свой комментарий | С | С | — | − |
| Редактировать чужой комментарий | − | − | − | − |
| Удалить свой комментарий | С | С | — | − |
| Удалить чужой комментарий | + | − | − | − |

Пояснение: чужой текст не редактирует никто, включая администратора — подмена чужих слов
разрушает доверие к истории обсуждения. Удалить чужой комментарий администратор может
(модерация), и это попадает в историю задачи.

### 2.6. Уведомления и профиль

| Действие | Владелец | Кто угодно другой |
|---|:--:|:--:|
| Видеть свои уведомления | + | − |
| Отметить уведомление прочитанным | + | − |
| Менять свои настройки подписки | + | − |
| Видеть/менять чужой профиль и настройки | — | − |

## 3. Роли простыми словами (для UI-подсказок)

- **Владелец трекера** — единственная глобальная роль: решает, кто вообще может войти
  в трекер. Внутри проектов особых прав у него нет.
- **Администратор** — управляет проектом: настройки, участники, приглашения, очереди.
  Всё, что может участник, может и он.
- **Участник** — работает: создаёт и меняет задачи, комментирует, назначает исполнителей.
  Настройки проекта ему недоступны.
- **Читатель** — только смотрит: задачи, комментарии, историю. Ничего не меняет.

## 4. Правила назначения ролей

- Признак владельца трекера выдаётся автоматически записям из начальной конфигурации
  (`config`) и далее передаётся только вручную другим владельцем ([D-39](./decisions.md#d-39)).
- Создатель проекта автоматически получает роль администратора.
- Роль при вступлении по приглашению = роль по умолчанию, указанная в приглашении.
  Через приглашение **нельзя** выдать роль администратора ([D-05](./decisions.md#d-05)):
  администратора назначает только действующий администратор вручную, из списка участников.
- Администратор может понизить себя до участника или читателя, если он не последний
  администратор проекта.
- Исключение участника: его комментарии и записи истории остаются (авторство сохраняется),
  поле «Исполнитель» в его задачах обнуляется, поле «Автор» остаётся. Ранее оставленные
  им упоминания сохраняются как текст, но перестают быть ссылкой на профиль в контексте
  этого проекта, и новых уведомлений он по задачам проекта не получает.

## 5. Что должен вернуть API (нормативно)

| Ситуация | Ответ |
|---|---|
| Нет сессии | `401` |
| Аутентификация в Яндекс ID прошла, но пользователя нет в списке доступа и приглашения нет | Сессия не создаётся; пользователь получает экран «Доступ к трекеру закрыт». Машиночитаемо — `403` с отдельным кодом причины |
| Запрос от пользователя, чей доступ отозван, по уже открытой вкладке | `401`: сессия завершена, клиент показывает экран «Доступ к трекеру закрыт» |
| Обращение к экрану или API списка доступа не-владельцем | `403` |
| Добавление адреса, который уже есть в списке доступа | `409` |
| Попытка владельца удалить собственную запись | `409` |
| Попытка снять признак владельца у последнего владельца или удалить его запись | `409` |
| Попытка упомянуть пользователя, не состоящего в проекте | Упоминание сохраняется как обычный текст, уведомление не создаётся; ошибки нет |
| Запрос к объекту проекта, где пользователь не состоит | `404` |
| Действие не разрешено ролью, но объект виден | `403` |
| Приглашение истекло, отозвано или токен неизвестен | `410` для истёкшего/отозванного, `404` для неизвестного |
| Пользователь уже участник и открывает ссылку-приглашение | `200` + переход в проект, роль не меняется |
| Попытка снять роль у последнего администратора | `409` |
| Попытка удалить непустую очередь | `409` |
| Ключ очереди занят (в том числе в другом проекте) | `409` |
