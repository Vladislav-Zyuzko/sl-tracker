# Глоссарий SL Tracker

Одно понятие — один термин. Колонка «В UI» — единственный допустимый текст на экранах и в
документации. Колонка «В коде / API» — единственное допустимое английское имя в БД, DTO,
маршрутах и именах событий. Синонимы из третьей колонки **запрещены** к использованию где бы
то ни было: они появляются здесь только чтобы их можно было опознать и заменить.

Если нужного понятия здесь нет — не изобретай термин молча, попроси PM добавить строку.

## 1. Люди и доступ

| В UI | В коде / API | Запрещённые синонимы | Определение |
|---|---|---|---|
| Пользователь | `user` | аккаунт, юзер | Человек, вошедший в трекер через Яндекс ID. Имеет имя, email и аватар, полученные от провайдера |
| Профиль | `profile` | личный кабинет | Экран с данными текущего пользователя, настройками уведомлений и выбором темы оформления |
| Отображаемое имя | `user.displayName` | ник, никнейм, ФИО | Имя человека в интерфейсе. Приходит из Яндекс ID и в трекере не редактируется; если провайдер не отдал имя, им становится email или логин ([D-43](./decisions.md#d-43)) |
| Тема оформления | `theme mode` | скин, стиль, ночной режим, цветовая тема | Выбор цветовой схемы на экране профиля: **как в системе** (по умолчанию), **светлая**, **тёмная**. Хранится на устройстве, между устройствами не переносится ([D-44](./decisions.md#d-44)) |
| Участник проекта | `member` (`project_member`) | сотрудник, юзер проекта, коллаборатор | Пользователь, явно добавленный в проект. Ровно у одного проекта одна запись на пользователя, с ролью |
| Роль | `role` | уровень доступа, permission | Роль участника **в конкретном проекте**: администратор, участник, читатель. Вне проектов есть ровно один глобальный признак — владелец трекера ([D-39](./decisions.md#d-39)); других глобальных ролей нет |
| Администратор проекта | `admin` | владелец, owner, суперюзер | Роль с полным управлением проектом: настройки, участники, приглашения, очереди, удаление |
| Участник (роль) | `member` | редактор, writer | Роль с правом работать с задачами и комментариями внутри проекта, но без управления проектом |
| Читатель | `reader` | наблюдатель, viewer, гость | Роль «только чтение»: видит проект, очереди, задачи, комментарии и историю, но ничего не создаёт и не меняет |
| Приглашение | `invitation` | инвайт, заявка | Ссылка с токеном, по которой пользователь после входа через Яндекс ID становится участником проекта. Имеет роль по умолчанию, срок жизни и состояние |
| Ссылка-приглашение | `invitation link` | инвайт-ссылка | URL вида `/invite/<token>` — единственный способ добавить человека в проект в MVP |
| Адрес проекта | `project link` | шара, публичная ссылка | Полный URL проекта (`https://<домен>/projects/<slug>`), копируется кнопкой «Скопировать адрес проекта». **Не даёт доступа**, служит для навигации участников. Латинская часть адреса — «короткое имя в адресе», см. раздел 2 |
| Сессия | `session` | логин | Активный вход пользователя. В вебе — httpOnly-cookie, в будущей мобилке — bearer-токен |
| Список доступа | `access list` | allowlist (в UI), whitelist, белый список, вайтлист | Перечень email, которым разрешён вход в трекер. Ведётся владельцем трекера на отдельном экране и пополняется автоматически при принятии приглашения. Не путать с ролями: список доступа решает «пускать ли в трекер вообще», роль — «что можно внутри проекта» |
| Запись доступа | `access entry` | разрешение, грант | Одна строка списка доступа: email, источник, дата добавления, кем добавлена, признак владельца трекера |
| Источник записи | `access entry source` | тип записи, происхождение | Откуда взялась запись: **из конфигурации** (`config`, начальное наполнение инстанса), **добавлена вручную** (`manual`, через экран), **по приглашению** (`invitation`, при вступлении в проект) |
| Владелец трекера | `instance owner` | администратор инстанса, суперадмин, суперюзер, владелец (без уточнения) | Единственная глобальная роль в продукте: право видеть и менять список доступа, выдавать и снимать этот же признак другим. Доступа к чужим проектам не даёт ([D-39](./decisions.md#d-39)) |
| Отзыв доступа | `access revocation` | блокировка, бан, удаление пользователя | Удаление записи из списка доступа: вход закрывается, активные сессии человека немедленно завершаются, его данные и членство в проектах остаются ([D-40](./decisions.md#d-40)) |

## 2. Структура

| В UI | В коде / API | Запрещённые синонимы | Определение |
|---|---|---|---|
| Проект | `project` | воркспейс, пространство, борд, команда | Верхний контейнер: обложка, описание, участники, очереди. Границы доступа проходят по проекту |
| Короткое имя в адресе | `project.slug` | slug (в UI), ЧПУ, алиас, идентификатор проекта | Латинская часть адреса `/projects/<slug>`: строчные латинские буквы, цифры и дефисы. Уникально глобально, при переименовании проекта не меняется; прежние значения продолжают вести на проект ([D-35](./decisions.md#d-35)). Слово «слаг» допустимо в коде и в разговоре инженеров, но не в интерфейсе |
| Обложка проекта | `project cover` | фото, аватар проекта, лого | Одно изображение проекта, показывается в карточке и шапке проекта |
| Очередь | `queue` | доска, список, категория, спринт, эпик | Пространство задач одного рода внутри проекта. Владеет ключом и набором статусов |
| Ключ очереди | `queue.key` | префикс, код, аббревиатура | Латинские заглавные буквы и цифры, 2–10 символов, начинается с буквы. **Глобально уникален на весь трекер**, задаётся при создании и не меняется. Пример: `DEV` |
| Задача | `issue` | тикет, таск, issue (в UI), карточка, заявка | Единица работы. В коде и URL — только `issue` |
| Ключ задачи | `issue.key` | номер, ID задачи | `<КЛЮЧ_ОЧЕРЕДИ>-<НОМЕР>`, например `DEV-42`. Публичный идентификатор, участвует в URL `/issues/DEV-42`, неизменяем |
| Номер задачи | `issue.number` | порядковый номер, seq | Целое число, выдаётся по возрастанию внутри очереди при создании задачи. Не переиспользуется, пропуски допустимы |

## 3. Поля задачи

| В UI | В коде / API | Запрещённые синонимы | Определение |
|---|---|---|---|
| Название | `issue.title` | заголовок, тема, summary | Однострочный текст, 1–255 символов, обязателен |
| Описание | `issue.description` | текст, body, контент | Многострочный текст в Markdown, до 100 000 символов, необязателен |
| Статус | `status` | состояние, стадия, колонка, этап | Текущее положение задачи в работе. Хранится данными: у каждой очереди свой набор статусов |
| Категория статуса | `status.category` | группа, тип статуса | Служебная классификация статуса: `open`, `in_progress`, `done`. Определяет, считается ли задача завершённой. В MVP не редактируется |
| Приоритет | `issue.priority` | важность, срочность, severity | Целое число 0–100 с шагом 10 (11 значений). Больше — важнее. По умолчанию 50, пустым не бывает |
| Диапазон приоритета | `priority band` | уровень важности, категория приоритета | Словесное пояснение к числу: **Низкий** (0–20), **Обычный** (30–60), **Высокий** (70–80), **Критический** (90–100). Вычисляется из числа, отдельным полем не хранится ([D-32](./decisions.md#d-32)) |
| Сложность | `issue.storyPoints` | оценка, эстимейт, сторипойнты, вес | Story points по шкале Фибоначчи: 1, 2, 3, 5, 8, 13 либо «не оценено» (пусто) |
| Автор | `issue.authorId` | заказчик, инициатор, постановщик | Пользователь, указанный как автор задачи. Назначается вручную и может быть изменён. По умолчанию — создатель |
| Создатель | `issue.createdById` | автор (нельзя!), reporter | Пользователь, фактически создавший задачу. Устанавливается системой, не меняется, показывается только в истории |
| Исполнитель | `issue.assigneeId` | ответственный, assignee (в UI), владелец задачи | Пользователь, который делает задачу. Ровно один или никто |
| Вложение | `attachment` | файл, аттач, приложение | Файл, приложенный к задаче. До 25 МБ. Изображения показываются превью, остальное — списком |
| Ссылка | `issue link` (внешняя) | линк, урл | Внешний URL, добавленный к задаче (подпись + адрес). **Не путать со связью между задачами** — связей в MVP нет |
| Комментарий | `comment` | сообщение, реплика, пост | Текстовая запись под задачей с указанием автора и времени |
| Упоминание | `mention` | тег, меншен, обращение | Ссылка на участника проекта внутри текста комментария или описания, вводится через `@`. Создаёт уведомление упомянутому и делает его подписчиком задачи |
| История изменений | `history` (`issue_history`) | лог, аудит, активность, changelog | Хронологический список изменений задачи: кто, когда, какое поле, с какого значения на какое |
| Запись истории | `history entry` | событие, ивент | Одна строка истории. Одно действие пользователя может породить несколько записей (изменил статус и исполнителя — две) |

## 4. Состояния и выборки

| В UI | В коде / API | Запрещённые синонимы | Определение |
|---|---|---|---|
| **Активная задача** | `active issue` | мои задачи, открытые, текущие, в работе | Задача, у которой **исполнитель — текущий пользователь** и статус **не относится к категории `done`**. Это единственное определение «активности» в продукте, используется в сайдбаре и в поиске по нему |
| Завершённая задача | `done issue` | закрытая, выполненная | Задача в статусе с категорией `done`. В MVP такой статус один — «Закрыт» |
| Сайдбар | `sidebar` | боковое меню, левая панель, навигация | Постоянная левая панель приложения: проекты, список активных задач текущего пользователя, поиск по ним |
| Панель задачи | `issue side panel` | правая колонка, инспектор, боковое меню задачи | Боковая область на экране задачи с полями: статус, приоритет, сложность, автор, исполнитель |
| Подписчик задачи | `subscriber` | наблюдатель, watcher, следящий | Пользователь, который получает уведомления по задаче. В MVP подписка **неявная**: создатель, автор, исполнитель, все, кто комментировал, и все, кого упомянули. Отдельного поля «Наблюдатели» нет |
| Уведомление | `notification` | оповещение, алерт, пуш | Запись о событии, адресованная пользователю. В MVP канал один — in-app |
| Центр уведомлений | `notification center` | колокольчик, инбокс | Экран/панель со списком уведомлений пользователя и счётчиком непрочитанных |

## 5. Статусы по умолчанию

Создаются данными при создании любой очереди. Пользователь их в MVP не редактирует, но
хранятся они как записи, а не как enum ([D-08](./decisions.md#d-08)).

| Порядок | В UI | Системное имя (`status.key`) | Категория | Смысл |
|---|---|---|---|---|
| 1 | Открыт | `open` | `open` | Задача заведена, работа не начата |
| 2 | В работе | `in_progress` | `in_progress` | Исполнитель работает над задачей |
| 3 | Ревью | `review` | `in_progress` | Результат проверяется коллегами |
| 4 | Тестирование | `testing` | `in_progress` | Результат проверяется тестированием |
| 5 | Закрыт | `closed` | `done` | Работа завершена, задача перестаёт быть активной |

## 6. Слова, которых у нас нет

Чтобы не появлялись «сами собой»: **доска, колонка, спринт, эпик, баг (как тип), подзадача,
метка, тег, дедлайн, воркфлоу-переход, наблюдатель (как поле), организация, отдел, гость,
публичный проект, бан, блокировка пользователя, суперадмин, связь между задачами
(блокирует / дублирует / относится к)**. Большинство относится к отложенному объёму — см. [roadmap.md](./roadmap.md); связи между
задачами отклонены пользователем и не запланированы вовсе ([D-45](./decisions.md#d-45)).
Использовать эти слова в UI и в коде MVP нельзя: они создают ожидание функциональности,
которой нет.
