## Релиз 1 — MVP «Команда работает в трекере» — **поставлен**

**Цель.** Команда из 3–15 человек полностью переносит рабочие задачи в SL Tracker и больше
не ведёт их в мессенджере и таблицах.

**Состояние.** Сквозной сценарий из [vision.md](./vision.md#критерий-готовности-mvp-проверяемый-end-to-end-сценарий)
проходит. Поставлено: серверная часть (37 путей REST и WebSocket-канал живых обновлений),
клиент со всеми экранами MVP, сквозной набор проверок QA, боевой стенд и инструкция
развёртывания. Пользователь прошёл приложение руками; три найденных дефекта исправлены.
Дефекты автоматического прогона ведутся в [defects.md](../qa/defects.md) — это зона QA
и инженеров, объём релиза они не меняют.

### Чем поставленное отличается от первоначального плана

Три расхождения, зафиксированные решениями, — чтобы никто не сверялся с устаревшим текстом:

| Что | Было в плане | Стало | Решение |
|---|---|---|---|
| Тёмная тема | «сознательно не делаем», релиз 3+ | входит в MVP, переключатель в профиле (система / светлая / тёмная) | [D-44](./decisions.md#d-44) |
| Конфликт одновременного редактирования описания | предупреждение при сохранении с выбором «перезаписать / отменить» | предупреждения нет, побеждает последняя запись, молча, для всех полей | [D-27](./decisions.md#d-27) |
| Связи между задачами | «имеют смысл только с эпиками», релиз 3 | **запрошены пользователем и отклонены им же**; не планируются ни в одном релизе | [D-45](./decisions.md#d-45) |

Плюс один задел, который **не считается функцией продукта**: список задач очереди в API
поддерживает фильтры по исполнителю, автору и границам приоритета, но экран MVP показывает
только фильтр по статусу ([D-28](./decisions.md#d-28)). Обещать пользователю то, чего нет
на экране, нельзя — это материал релиза 2.

## Релиз 2 — «Видно всю картину»

**Цель.** Трекер перестаёт быть только личным списком дел: команда видит состояние работы
целиком и находит нужное. Плюс закрываем мелочи, которые видно каждый день.

Порядок ниже — предлагаемый приоритет PM. Он не согласован с пользователем и меняется
свободно, пока работа не начата.

### 2.1. Первые кандидаты: дёшево, а раздражает ежедневно

| # | Что | Зачем именно это | Цена | Решение |
|---|---|---|---|---|
| 1 | **Отображаемое имя редактируется в профиле** | Яндекс ID не всегда отдаёт имя: у части людей в списке участников и в выборе исполнителя стоит email или логин. Это видно всем и всегда | Признак «имя задано вручную», иначе следующий вход затрёт правку; метод сохранения в API; правка US-04 | [D-43](./decisions.md#d-43), вопрос Q18 |
| 2 | **Пометка «доступ отозван»** в списке участников и в выборе исполнителя | Сейчас на человека без входа можно назначить задачу, и она повиснет | Признак в ответах API по участникам; состояние в двух местах интерфейса | [D-40](./decisions.md#d-40), вопрос Q17 |
| 3 | **Ограничение приёма приглашений считать по приглашению, а не по адресу** | За общим NAT онбординг команды больше 20 человек упирается в ложный отказ на единственной двери в трекер | Смена единицы счёта, порог по адресу поднимается | [D-42](./decisions.md#d-42), вопрос Q19 |
| 4 | **Автоссылки на ключи задач** в описании и комментариях (без поповера) | Ключ в тексте сейчас копируется руками | Разбор текста уже есть под упоминания; проверка прав — только при добавлении поповера | [D-38](./decisions.md#d-38) |

### 2.2. Крупные блоки

1. **Канбан-доска очереди.** Колонки = статусы очереди, перетаскивание карточки меняет
   статус, ручной порядок внутри колонки сохраняется. Фильтр по исполнителю.
2. **Глобальный поиск.** По ключу, названию, тексту описания и комментариев, только
   в пределах доступных пользователю проектов. Отдельный экран результатов.
3. **Фильтры и сохранённые представления.** Набор условий (проект, очередь, статус,
   исполнитель, автор, приоритет, сложность), сохранение под именем, личные представления.
   Часть условий уже поддержана контрактом списка задач — начинать можно с экрана.
4. **Перенос задачи между очередями.** Со сменой ключа; ссылка со старым ключом продолжает
   открывать задачу ([D-14](./decisions.md#d-14)).
5. **Наблюдатели.** Явное поле и кнопка «Следить» / «Не следить», отписка от конкретной
   задачи ([D-17](./decisions.md#d-17)).
6. **Email-уведомления:** дайджест и/или мгновенные письма, отписка одним кликом.
   Модель настроек подписки к этому готова с MVP ([D-18](./decisions.md#d-18)).
7. **История изменений списка доступа:** кто кого и когда впустил или отозвал.
8. **Приглашение конкретного человека по email** — осмысленно вместе с почтовым каналом.
9. **Архивирование очереди** — альтернатива удалению непустой очереди
   ([D-24](./decisions.md#d-24)).

### 2.3. Обсуждаемо, но не обещано

- **Поповер превью задачи** при наведении на автоссылку — только после пункта 2.1.4
  и с проверкой прав на каждую упомянутую задачу ([D-38](./decisions.md#d-38)).
- **Сообщение о конфликте редактирования** — тост после сохранения «Описание правил также
  <Имя>. Сохранена ваша версия». Берём **только вместе с показом предыдущей версии
  описания**: иначе сообщаем о потере, которую нельзя отменить ([D-27](./decisions.md#d-27)).
  Модальное окно не возвращается ни при каких условиях — это решение пользователя.
- **Перенос выбора темы между устройствами** (сейчас выбор хранится локально в браузере).
  Изменение контракта ради удобства, которого никто пока не просил ([D-44](./decisions.md#d-44)).

**Не входит в релиз 2:** редактор статусов, воркфлоу, типы задач, спринты, связи между
задачами.

## Релиз 3 — «Команда настраивает трекер под себя»

**Цель.** Процессы разных команд перестают ломаться о наши пять статусов.

1. **Редактор статусов очереди:** добавление, переименование, порядок, категория; правила
   переноса задач при удалении статуса.
2. **Воркфлоу:** разрешённые переходы, обязательные поля при переходе, ограничение перехода
   по роли.
3. **Типы задач**, а вместе с ними эпики и подзадачи ([D-37](./decisions.md#d-37)).
   Связи между задачами сюда **не входят по умолчанию**: они отклонены пользователем
   ([D-45](./decisions.md#d-45)) и возвращаются только по его отдельному запросу.
4. **Шаблоны задач** (описание по умолчанию для очереди).

## Что решаем после обратной связи, а не сейчас

Спринты и планирование итераций, отчёты и графики (burndown, распределение по исполнителям),
интеграции (Git, мессенджеры, календарь), импорт из Яндекс Трекера/Jira, публичные проекты
и гостевой доступ, мобильное приложение, второй язык интерфейса (строки уже лежат
в ресурсах, см. [D-36](./decisions.md#d-36), поэтому это перевод, а не переделка).

Ни одна из этих тем не считается обещанной. Прежде чем брать любую из них, PM обязан
показать сценарий пользователя, который без неё ломается.

## Что не появится без отдельного решения пользователя

- **Связи между задачами** — запрошены и отклонены ([D-45](./decisions.md#d-45)).
- **Сроки (дедлайны), теги, учёт времени** — решение пользователя: не входят.
- **Локальный вход по email и паролю** — только Яндекс ID.
- **Модальное предупреждение о конфликте редактирования** — отменено пользователем
  ([D-27](./decisions.md#d-27)).
