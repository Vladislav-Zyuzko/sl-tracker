# Дорожная карта SL Tracker

Границы жёсткие: если фича не названа в разделе MVP — её в MVP нет, даже если она «на пять
минут». Перенос фичи между релизами оформляется записью в [decisions.md](./decisions.md).

---

## Релиз 1 — MVP «Команда работает в трекере»

**Цель.** Команда из 3–15 человек полностью переносит рабочие задачи в SL Tracker и больше
не ведёт их в мессенджере и таблицах.

**Готово, когда** проходит сквозной сценарий из [vision.md](./vision.md#критерий-готовности-mvp-проверяемый-end-to-end-сценарий).

### Явно вне MVP (и в каком релизе появится)

| Фича | Релиз | Почему не сейчас |
|---|---|---|
| Канбан-доска | 2 | Drag&drop и хранение позиции карточек — отдельный крупный кусок |
| Глобальный поиск по задачам | 2 | Полнотекстовый индекс, ранжирование, экран результатов |
| Фильтры и сохранённые представления | 2 | Нужен язык условий; в MVP один фильтр — по статусу |
| Перенос задачи между очередями | 2 | Смена ключа + редиректы со старого ключа ([D-14](./decisions.md#d-14)) |
| Наблюдатели и кнопка «Следить» | 2 | Неявной подписки хватает ([D-17](./decisions.md#d-17)) |
| Email-уведомления | 2 | SMTP/почтовый сервис, домен, шаблоны, отписка. Решение пользователя: в MVP только in-app ([D-18](./decisions.md#d-18)) |
| Автоссылки на ключи задач в тексте и поповер превью | 2 | Проверка прав на каждую упомянутую задачу; ценность ниже упоминаний ([D-38](./decisions.md#d-38)) |
| Сроки (дедлайны) | не запланировано | Решение пользователя: не входят |
| Редактор статусов очереди | 3 | Модель данных готова, нужен экран и правила миграции задач при удалении статуса |
| Воркфлоу: разрешённые переходы и условия | 3 | Требует конструктора правил |
| Типы задач, эпики, подзадачи, связи | 3 | Меняют модель задачи целиком; иерархия не закладывается даже в модель данных ([D-37](./decisions.md#d-37)) |
| Спринты и планирование | 3+ | Мы не Scrum-инструмент; решать после обратной связи |
| Тёмная тема | 3+ | Решение пользователя |
| Мобильное приложение | 3+ | API уже проектируется под это |

## Релиз 2 — «Видно всю картину»

**Цель.** Трекер перестаёт быть только личным списком дел: команда видит состояние работы
целиком и находит нужное.

**Содержание (порядок — предварительный, уточняется после MVP):**

1. **Канбан-доска очереди.** Колонки = статусы очереди, перетаскивание карточки меняет статус,
   ручной порядок внутри колонки сохраняется. Фильтр по исполнителю.
2. **Глобальный поиск.** По ключу, названию, тексту описания и комментариев, только в пределах
   доступных пользователю проектов. Отдельный экран результатов.
3. **Фильтры и сохранённые представления.** Набор условий (проект, очередь, статус, исполнитель,
   автор, приоритет, сложность), сохранение под именем, личные представления.
4. **Перенос задачи между очередями.** Со сменой ключа; ссылка со старым ключом продолжает
   открывать задачу.
5. **Наблюдатели.** Явное поле и кнопка «Следить»/«Не следить», отписка от конкретной задачи.
6. **Автоссылки на ключи задач** в описании и комментариях, затем поповер с превью задачи
   ([D-38](./decisions.md#d-38)).
7. **Email-уведомления:** дайджест и/или мгновенные письма, отписка одним кликом.
   Модель настроек подписки к этому готова с MVP.
8. **История изменений списка доступа:** кто кого и когда впустил или отозвал. Сам экран
   управления доступом входит в MVP, журнала изменений в нём нет.
9. **Приглашение конкретного человека по email** — становится осмысленным вместе с почтовым
   каналом.
10. **Пометка «доступ отозван»** в списке участников проекта и в выборе исполнителя —
    вопрос Q17.
11. **Архивирование очереди** — альтернатива удалению непустой очереди ([D-24](./decisions.md#d-24)).

**Не входит в релиз 2:** редактор статусов, воркфлоу, типы задач, спринты.

## Релиз 3 — «Команда настраивает трекер под себя»

**Цель.** Процессы разных команд перестают ломаться о наши пять статусов.

1. **Редактор статусов очереди:** добавление, переименование, порядок, категория; правила
   переноса задач при удалении статуса.
2. **Воркфлоу:** разрешённые переходы, обязательные поля при переходе, ограничение перехода
   по роли.
3. **Типы задач** и вместе с ними эпики, подзадачи и связи между задачами (блокирует /
   заблокирована, дублирует, относится к).
4. **Шаблоны задач** (описание по умолчанию для очереди).

## Что решаем после обратной связи, а не сейчас

Спринты и планирование итераций, отчёты и графики (burndown, распределение по исполнителям),
интеграции (Git, мессенджеры, календарь), импорт из Яндекс Трекера/Jira, публичные проекты
и гостевой доступ, тёмная тема, мобильное приложение, второй язык интерфейса (строки уже
лежат в ресурсах, см. [D-36](./decisions.md#d-36), поэтому это перевод, а не переделка).

Ни одна из этих тем не считается обещанной. Прежде чем брать любую из них, PM обязан
показать сценарий пользователя, который без неё ломается.
